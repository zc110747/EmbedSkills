# 静态提取：容器解析、指纹、资源与字符串

> 只读文件本身得出结论。**所有地址类结论都需后续真机复核**（见 `evidence-grading.md`）。

## 1. 先做身份指纹（30 秒内能定性）

| 看什么 | 结论 |
|---|---|
| 节名（`.text/.rdata/.data`） | 常规编译产物，未加壳 |
| 节名异常（`.UPX*`、乱码名、`.vmp*`） | **已加壳/虚拟化** → 先脱壳 |
| 节熵值 | > 7.2 且导入表极简 ⇒ 压缩或加密 |
| 导入表 | `mscoree` → .NET；`Qt5*/Qt6*` → Qt；`comctl32`+自绘类名 → Win32 自绘；`MFC*` → MFC |
| 资源类型 | 自定义类型名（非 RT_*）多为内嵌数据；加密封面/皮肤常在此 |
| 时间戳/版本资源 | 与 UI 上显示的版本号是否一致（不一致说明有二次打包） |

**判据**：任何一步结论只依赖单一特征时，标"孤证"。

## 2. 容器解析（PE 为例，其它格式类推）

按顺序取：**段表 → 导入/导出表 → 资源目录 → 重定位表**。

- **段表**：得到每个段的 RVA/大小/权限；`.rdata` 常有只读数据与字符串，`.data` 常是可写全局。
- **资源目录**：递归遍历类型→名称→语言三级；把每个资源 dump 出来按 `类型_名称_语言.bin` 命名，便于后续检索。
- **资源实体**：区分"直读可得"与"加密/压缩"。判据：头部是否为已知格式魔数（PNG/JPG/ZIP/GZ/XOR 后仍可辨的低熵）。
- **关键产物**：把解析结果落成 **JSON**（段、导入、资源索引、字符串位置），后续所有查询都基于它，
  避免反复重解析二进制。

## 3. 字符串挖掘（两种编码都要扫）

```text
ASCII   : 连续可打印字节 (0x20..0x7E)，长度 ≥ 4
UTF-16LE: 可打印字节 + 0x00 交替，长度 ≥ 4 字符
```

**必做**：
- 两种编码分别导出，**统计数量对比**——如果一种远少于另一种，说明数据主要存在另一种里。
- 从字符串**反推结构**：相邻字符串的地址差 ≈ 固定步长 ⇒ 这些是**表项**，可反推条目数/顺序。
- 多语言词条：找到语言分块边界，用"同类词条的跨块对齐"推条目映射。

**典型价值**：内嵌脚本、功能名、快捷键名、错误文案、URL、注册表键、dll 名（后者提示依赖）。

## 4. 内嵌脚本/配置：优先找它

脚本（Lua/JS/Python/自定义 DSL）或结构化配置（XML/INI/JSON）是**最高价值的发现**：
- 它直接给出"改什么、怎么改"，比猜行为可靠。
- 常常以明文存在（或明文字符串表 + 轻量编码）。
- 一旦拿到，**它就是实现规格**；后续只需把它的语义翻译成目标语言。

**做法**：按上一步的"表项反推"找到脚本区的起止，整体 dump，再逐个解析语法。

## 5. 反汇编辅助（只读，不改）

用于回答两类问题：
- **符号/基址如何解析**：看它如何从一条指令取出 rip 相对操作数（见 `replica-memory-engine` 的符号解析）。
- **覆盖点在哪**：看某功能在其判定指令附近的 patch 模式。

**纪律**：反汇编用于**取证与边界确认**，不用于"照抄字节数"——
覆盖长度必须由指令长度解码器独立算出（见 `replica-memory-engine`）。

## 6. 落盘清单

```
docs/recon/
  ~/FINDINGS.md          ← 主结论（带证据等级）
  ~/pe_parse.json         ← 段/导入/资源索引
  ~/strings_ascii.txt     ← ASCII 串（带偏移）
  ~/strings_utf16.txt     ← UTF-16 串（带偏移）
  ~/resources/            ← dump 出的资源实体
  ~/scripts/              ← 提取出的内嵌脚本/配置
```

**可复现要求**：每个 dump 脚本都要能重跑并给出稳定结果；不稳定的（依赖时间戳等）要写明。
