# 喂给 TTS 之前的文本准备（Markdown / 编码 / 语言闸门）

把"文档 → 语音"接起来时，**真正出问题的往往不是 TTS 本身，而是喂进去的文本**：
读错编码得到乱码、把词表和习题也念了、把中文丢给英文模型得到噪音。
这一篇只讲"喂之前"的三道关，判据全部来自实测。

## 1. 只读指定章节：别整篇念

常见素材是**教程式 Markdown**（一个文件里塞了正文 + 词表 + 习题 + 答案 + 导航链接）。
需求几乎总是"只念正文"，所以解析必须是**章节抽取**而不是"读整个文件"。

规则（CommonMark 语义）：

- 用 ATX 标题定位目标章节（`^ {0,3}(#{1,6})\s+(.*?)\s*#*\s*$`，标题前最多 3 个空格）。
- 章节正文 = 标题之后，直到**下一个同级或更高级标题**为止。
  ⇒ `## Article` 到下一个 `##`/`#` 结束；`###` 是它的子节，要保留。
- **代码块（``` / ~~~）要单独跟踪**：块里的 `# 注释` 不是标题。
- 章节名匹配要**宽容**：大小写不敏感，并容忍 `**Article**:`、`Article:` 这类写法
  （归一化时剥掉首尾 `*`/`` ` ``/`#`/空白/冒号）。
- 找不到章节时，**把文件里实际有哪些标题列出来**再报错 —— 这比"未找到 Article"有用得多。

## 2. 剥离语法，但**不要丢文字**

Markdown → 纯文本时最危险的动作是"顺手删掉看不懂的东西"。判据：**只删语法，不删内容**。

| 元素 | 处理 |
|---|---|
| `**粗体**` `*斜体*` `~~删除线~~` | 去掉标记，**保留文字** |
| `[可见文字](url)` / `![alt](url)` | 保留**可见文字/alt**，丢掉 URL（URL 念出来是噪音） |
| `<https://…>` 自动链接 | 整段丢掉（纯 URL 无可念内容） |
| 行内代码 `` `x` `` | 去掉反引号保留内容 |
| 引用 `>`、列表 `-` `1.` | 去掉标记保留条目文字 |
| 表格 | 分隔行（`\|---\|`）丢掉；**数据行按行独立成段**，单元格用 `,` 连接 |
| 围栏代码块 | 整块丢掉（不是自然语言）；**同时要 `FlushParagraph()`** |
| 水平线、HTML 注释 | 丢掉 |
| `&amp; &lt; &#39; &nbsp;` 等实体 | 还原成字符（否则会被念成"amp"） |

段落语义：**段内软换行合并成一个空格，空行作为段落分隔**。
输出用 `\n\n` 连接段落，交给 TTS 自己按句切分即可（Piper 实测无长度上限）。

## 3. 编码：只接受 UTF-8，其余**报错而不是尽力解码**

用错代码页静默解出的乱码，到了 TTS 那边会表现成"模型读不对我的文本"——归因完全跑偏。
所以要在读文件这一步就把编码问题变成**可执行的错误**。

四重判据（按顺序，实测有效）：

1. **BOM 优先**：UTF-8 BOM 接受并剥掉；UTF-16 LE/BE、UTF-32 LE/BE 直接拒绝，
   并在消息里**写出检测到的是哪种编码**。
   ⚠️ 判 UTF-32 必须在 UTF-16 之前（UTF-32 LE 的 BOM `FF FE 00 00` 以 UTF-16 LE 的 `FF FE` 开头）。
2. **无 BOM 时看 NUL 字节分布**：16 位编码的 ASCII 文本每个码元贡献一个 `0x00`。
   判据用"**占比**"而不是"出现过"：`nulBytes * 4 >= length` 才算 16 位；
   再看 NUL 落在奇数位（LE）还是偶数位（BE）。
   （只按"有没有 NUL"判，6 字节的小二进制文件就会被误判成 UTF-16。）
3. **严格 UTF-8 解码**：`new UTF8Encoding(false, throwOnInvalidBytes: true)`，
   捕获 `DecoderFallbackException` 并用 `ex.Index` 报出**首个非法字节的偏移**。
4. **兜底查控制字符**：解出来若含 `\u0000-\u001F`（除 TAB/CR/LF）、`\u007F`、`\u0080-\u009F`、
   `\uFFFD`，说明实际编码不是 UTF-8 —— 真实 Markdown 不会有这些字符。

已知盲区（要如实标注）：**无 BOM 且每个 16 位码元都不含 `0x00`** 的 UTF-16 无法与 UTF-8 区分
（全文都是非拉丁字符时可能发生）。含 ASCII 的 UTF-16 必然被第 2 条拦下，
而英文素材必然大量含 ASCII，所以这个盲区不影响正常用法。

## 4. 语言闸门：非目标语言**在合成前**中止

英文模型喂中文/西里尔/假名不会报错，会**产出噪音或静音**——最坏的一种失败（有产物、能用播放器打开、内容是垃圾）。
所以要在调用引擎**之前**判定语言，并且：

- **复用同一个"可发音字符"定义**：让语言闸门和文本校验器共用同一个 `IsSupported(char)`，
  两处判据不同就会出现"校验过了但模型读不出来"。
- 报错要给出**脚本名 + 数量 + 示例字符的码位**：
  `检测到 8 个非英文字符（中日韩文字或全角符号 8 个）… 示例字符：'我'(U+6211)`。
  只说"包含非法字符"用户没法改。
- 分脚本归类至少要覆盖：CJK/全角、假名、韩文、西里尔、希腊、希伯来、阿拉伯、泰文、天城文、
  代理对（表情符号/增补平面）。
- **中止 = 不产出任何文件**（不是产出空文件，也不是产出后再删）。测试要断言"没有新文件"。

## 5. 默认"当前目录"这类规则要能被单测

"不指定输出目录就生成在当前目录"这种规则，别写死在流程中间：

```csharp
public static string ResolveOutputPath(string inputFile, string? outputDir) =>
    Path.Combine(outputDir is null ? Environment.CurrentDirectory : Path.GetFullPath(outputDir),
                 Path.GetFileNameWithoutExtension(inputFile) + ".wav");
```

抽成纯函数后：目录规则的用例不需要真去合成、也不需要改进程的 CWD（改 CWD 会影响整个测试进程，
是并行测试的经典污染源）。
