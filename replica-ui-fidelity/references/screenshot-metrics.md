# 截图度量：标尺、像素统计、取色

> 无第三方图像库时也能做：PNG 解码（含 5 种行滤波）纯手写即可，或用系统自带工具。

## 1. 先定标尺

```text
物理像素 (截图上量的)  ÷  显示缩放  =  逻辑像素 (代码里写的)
```

**缩放从哪来**：宿主显示设置（如 150% / 200%）；或用 DPI 探针脚本读 `GetDpiForWindow`。

**纪律**：整个工程**只在一个空间里写坐标**（推荐逻辑像素），运行期统一乘 `DeviceDpi/96`。
混用两个空间是错位问题的最大来源。

## 2. 截图获取（Windows）

```text
① 枚举顶层窗口：EnumWindows → 按「可见 + 类名前缀 + 标题关键词」筛选
   ⚠️ 标题用的是窗口 Text（常是副标题文案），不是界面上那个大标题控件
② 取尺寸：GetClientRect / GetWindowRect
   ⚠️ 进程必须先声明 DPI 感知，否则拿到虚拟化坐标
      (SetProcessDpiAwarenessContext(-4) / SetProcessDPIAware)
③ 抓像素：
   - 被遮挡也能抓：PrintWindow(hwnd, hdc, 0x2 /* PW_RENDERFULLCONTENT */)
   - 仅前台可见：BitBlt
```

## 3. 像素统计（核心复验手段）

```text
逐行统计某目标色的像素：
  for y in 0..h:
      run = 最长连续满足 |px - target| < tol 的区间
      if run >= 阈值: 记录 (y, run, x0)

用途：
  - 找横线：返回若干条 (y, 长度, 起始x)
  - 找竖线/分隔：逐列做同样统计
  - 找文字块：统计"非背景"像素的行区间，得到每行墨迹的上下界与左右界
```

**"非背景行区间"是量布局的主力**：把每行文字的行区间列出来，
相邻区间中心差 = 行距；行区间的左右界 = 文本宽度与起点。

## 4. 取色

- 在**平坦区域**取（避开抗锯齿边缘、渐变、阴影）。
- 同一色多个位置取样，取**众数**而非第一个。
- 记录时写清位置，便于回查。

```text
背景: 在无内容的角落取
文字: 取笔画主体（不是边缘），或直接取"最亮的众数"
强调色: 在选中态/下划线处取，单独命名
分隔线: 在线的正中取（线本身可能有 1~2 物理像素宽）
```

## 5. 文字墨迹框测量

```text
对某一行文字：
  y0..y1 = 该行"非背景"像素的上下界     → 墨迹高度
  x0..x1 = 左右界                      → 墨迹宽度
用于：
  - 标定字号（拿候选字号渲染同串文字，比墨迹宽/高）
  - 反推行中心（(y0+y1)/2）与行距
  - 反推文字起点（x0，用于补偿自绘控件内缩）
```

## 6. 复验判据模板

| 断言 | 判据 |
|---|---|
| 条装饰线存在 | 目标色出现 N 条 `run ≈ 期望长度` 的横线 |
| 位置正确 | 每条 `x0` 落在预期列区间 |
| 行距正确 | 相邻横线 `y` 差 ≈ 行距常量 |
| 文字未裁切 | 某行墨迹宽度 ≈ 参考宽度（不显著小于） |
| 元素未重叠 | 相邻元素的墨迹行区间不交叠 |

**注意**：复验必须在**最终交付的二进制**上做（Debug/Release 都跑），
不是只在某次中间版本上做过就算。

## 7. 反模式

- ❌ 用 `GetWindowRect` 而不声明 DPI 感知。
- ❌ 按界面"大标题"去筛窗口（那是控件文本，不是窗口标题）。
- ❌ 取色取到抗锯齿边缘。
- ❌ 只截一次图就下结论；UI 有首帧/布局延迟，要等稳定再截。
- ❌ 复验用"看起来对了"代替像素统计。
