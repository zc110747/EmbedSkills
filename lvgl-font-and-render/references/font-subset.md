# 子集字库：字符集提取、覆盖校验与字形探针

面向「用 `lv_font_conv` 之类工具生成子集字库」的场景。核心事实：**缺字不会报错，
LVGL 会画一个空心方框并打一条 warn**，而所有尺寸 API 都正常 —— 所以必须用探针与覆盖校验兜住。

## 一、探针该断言什么

1. **每一个依赖的字体都必须画出非零像素**。取字符串渲染后统计非背景像素，为 0 即失败
   —— 这一条就能抓住「压缩标志不匹配」和「字体整个没编进去」。
2. **逐个码点检查「运行期才会出现的字」**。源码里写死的字符串可以从源码收集字符集来生成精选字体；
   但模型输出、用户输入、配置文件里的字**不可能**被静态收集。做法：把码点列表写进测试，
   断言 `lv_font_get_glyph_dsc()` 命中 **且** `lv_font_get_bitmap_fmt_txt()` 非 NULL
   **且** 位图字节里至少有一个非零。
   （命中 cmap 但位图全零 = 画出来是空白，同样算 bug。）
3. **字符集生成器必须跳过字体产物目录**。生成产物永远不是输入；把它算进去会形成正反馈，
   一轮轮把无关字符收进来。
4. 生成期加**覆盖自校验**：脚本自己回读生成的 `.c`，确认目标字符全部在位。
5. ⚠️ **子集字库的字符集只能从源码自动提取，绝不能手写。**
   手写列表的失败方式是「导出被判定文案时漏了一个字，几个单元格全部变成同一个字 + 豆腐块」——
   编译零警告、单元测试全绿、`lv_obj_get_width()` 全对。
6. **字体文件名/取值范围变了要回看资源占用**：删掉 40 个用不到的字形，24px 4bpp 的字库
   体积降约 40%，整包固件体积随之下降。字库是「按需子集」时，这种回收是常态收益。
7. **交付前的界面文案变更 = 必须重跑一次覆盖校验**。把覆盖校验脚本挂进构建流程
   （或至少写进「改文案必做」清单）。

### 扫描前必须剥注释（实测会虚涨）

字符集扫描要**先剥掉 C 注释**再取字符串字面量。注释里引用的规格文案
（例如 `/* "默认都为空…" */` 这类说明）不是界面文案，算进去只会把看不见的字形塞进字库 ——
实测字库体积虚涨约 40%。

### 生成与校验必须共用同一份扫描

⚠️ **两条腿必须共用一个字符集定义。** 字库生成脚本与覆盖校验脚本一旦对
「界面会用哪些字」的理解出现分歧，校验就会**静默失效** —— 它还在打印 PASS，
但守的已经不是同一件事。把扫描逻辑抽成一个模块，两边 import。

## 二、压缩标志不匹配：整屏有框无字

- 生成器不加 `--no-compress` 时输出**压缩位图**；若 `LV_USE_FONT_COMPRESSED` 为 0，
  `lv_font_get_bitmap_fmt_txt()` 返回 **NULL**，LVGL 对 NULL 位图**直接不画**。
- 症状：容器、边框、颜色、布局全对，**一个字都没有**。
- 定位：逐码点断言位图回调非空；或统计渲染后非背景像素数为 0。

## 三、豆腐块（空心方框）

- 根因：该码点不在字体的 cmap 里。
- 表现：LVGL v8.3+ 在 `LV_USE_FONT_PLACEHOLDER=y`（默认开）时画一个
  `border_width = 1`、`box_w = line_height/2`、`box_h = line_height` 的空心矩形，
  颜色取文字色。它**看起来像一个 UI 元素**（带色方框很容易被当成图标），
  同时打 `LV_LOG_WARN`。
- 定位优先级（从便宜到贵）：
  1. `grep "glyph dsc. not found" <console log>` —— LVGL 自己会 Warn，**先跑这个**；
  2. 逐码点 `lv_font_get_glyph_dsc()`；
  3. 字形探针 GLYPH（见下）。

## 四、字形探针（GLYPH）：ink 覆盖率 + ASCII 点阵图

对每个用到的码点：

- `lv_font_get_glyph_dsc()` 拿 `box / adv / bpp`；
- `lv_font_get_bitmap()` 拿位图，统计**非零像素占比（ink）**；
- 把位图打成 **ASCII 点阵图**（`#` / `+` / 空格）。

一次能抓：

| 现象 | GLYPH 输出 |
|---|---|
| 缺字形 | ink = 0 / MISSING |
| 字库压缩标志不匹配 | 整屏 0 ink |
| 字形本身画错 | ASCII 点阵图可以人眼确认「这个字到底是不是那个字」 |

一个 24×24 的汉字用 24 行 × 24 列打出来，部首结构一眼可辨，既不用看图也不用猜。

**ink 覆盖率还能反过来当合理性检查**：正常汉字大致落在 30%~70%；
整片 0% 或接近 100% 都说明生成参数不对（缺图 / 位深或阈值错）。

## 五、字体相关的排查顺序

按代价从低到高，**先跑便宜的**：

| 顺序 | 探针 | 做法 | 一次能抓什么 |
|---|---|---|---|
| 1 | **控制台 grep** | `grep "glyph dsc. not found" log` | 子集字库缺字（LVGL 自己会 Warn）。**先跑这个** |
| 2 | **TEXTFIT** | 遍历 label：`lv_txt_get_size()` 算自然尺寸，与 `lv_obj_get_width/height()` 比，打印 `dx/dy`（**空文本的 label 直接跳过**，否则一堆 `0x0` 噪声） | 溢出 / 裁切。**这是唯一能给出「差几个像素」的探针**，文案长度一改就有用 |
| 3 | **GLYPH** | 见第四节 | 缺字形、压缩标志不匹配、字形画错 |
| 4 | 整帧抓取 | 见 `onscreen-forensics.md` | 布局、配色、对齐的最终事实 |

## 六、验收清单（字体部分）

- [ ] 控制台里 `grep "glyph dsc. not found"` 必须为 0 行（子集字库缺字的第一道网）
- [ ] 每一个字体都渲染出非零像素
- [ ] 运行期才出现的字符逐个码点校验 cmap + 位图非零
- [ ] 字符集扫描剥掉注释；跳过字体产物目录
- [ ] 生成字库与校验字库共用同一份字符集扫描（否则校验会静默失效）
- [ ] 改过任何界面文案后跑一次离线覆盖校验（源码字符集 ⊆ 字库 cmap）
