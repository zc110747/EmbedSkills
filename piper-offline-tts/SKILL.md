# Piper 本地离线 TTS 集成

把 Piper（`rhasspy/piper`）当作**完全离线**的"文本 → WAV"引擎接进应用时需要的 CLI 契约、
长文本实测方法与模型/许可口径。**所有数字都是实测值，不是文档推测。**

## 何时用

- 要给应用加"本地 / 离线 / 不出网"的语音合成（英语或 piper 支持的其他语言）。
- 已经装了 piper 但**跑不出 WAV**：不报错、0 字节、或内容截断。
- 需要判断"长文本要不要自己切段"，以及切段后怎么拼回一个 WAV。
- 需要说清运行时与声学模型的**来源、版本、哈希与许可**（交付/合规要求）。

## 核心知识点（实测）

| 知识点 | 结论 |
|---|---|
| 正文怎么传 | 走 **stdin**（不是位置参数、也不是 `-t`） |
| 输出怎么指定 | `-f` / `--output_file <path>`；`-m` / `--model <*.onnx>` 与 `-c` / `--config <*.onnx.json>` **两个都要给** |
| espeak-ng-data | piper 找**自己 exe 旁边**的 `espeak-ng-data` ⇒ **从任意工作目录调用都能跑**，不必 `cd` 到安装目录 |
| 有没有长文本上限 | **没有实际上限**。实测 7,499 字符（60 句）一次 stdin 输入即正确合成：输出 **500.6 s**、22,074,508 B **单文件**、耗时 37.8 s；piper 自身按句切分，不截断、不乱序 |
| 实时率 | 68 字符单句 ⇒ **4.46 s** 音频，22,050 Hz / 单声道 / 16 bit / 196,768 B，RTF ≈ **0.07** |
| 何时才需要自己切段 | 只在你要**控制内存或让进度条动起来**时才切。"模型一般都有长度限制"是**假设**，不是事实 |
| 其他调参 | `--noise_scale` / `--length_scale`（语速）/ `--noise_w` / `--sentence_silence` |
| 返回码语义 | 退出码 0 **不代表**产物正确（见下）；失败时把 stderr 原文留住 |
| 真正的坑常在"喂之前" | 素材常是教程式 Markdown（正文 + 词表 + 习题 + 答案 + 链接混在一个文件里）⇒ 要**按标题抽取章节**；编码与语言要在调用引擎**之前**判 |

## 判据与反模式

- **"没有上限"必须实测证明，不能靠推断**：写一个探针扫字符数（如 68 / 500 / 2000 / 7499），
  每条断言"产物存在 + 可解码 + 时长 > 0 + 字节数量级合理"，结论才敢写进设计。
  反过来，**不要**因为"TTS 通常有限制"就先写一套切段 + PCM 拼接 —— 那是没被验证过的假设，
  多出来的合并逻辑本身就会成为缺陷来源（拼接顺序、格式不一致、异常截断）。
- **成功判据是"能解码且时长 > 0"，不是"退出码 0"**：退出码 0 而产物缺失/半截是常见形态。
  时长用解码器读（`WaveFileReader.TotalTime`），**不要按文件大小估算**。
- **产物原子落地**：先写 `.<名字>.<guid>.tmp.wav`，校验通过再 `File.Move(..., overwrite: true)`。
  失败路径必须删掉临时文件，**绝不让半截 WAV 占用用户选定的路径**。
- **别把模型放进版本库**：`.onnx` 是几十 MB 级二进制。用 `.gitignore` 排除 +
  一个**带哈希校验**的下载脚本；运行时按"向上查找"定位，程序集输出目录里**不要**拷贝模型。
- **失败信息要能定位**：把 stdout/stderr 原文留在结果对象的 `Diagnostics` 里。
  只报"piper 退出码 1"等于没报。
- **未验证的部分如实标注**：没有真机听感验证、没做高 DPI 时，写"未验证"，
  不要用"应当可以"糊过去。
- **许可要落到具体文件**：运行时（可执行文件）与声学模型是**两套不同的许可**，
  各自的来源、版本、哈希都要写进交付说明（见 references）。
