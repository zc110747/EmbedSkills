# 零依赖配置子集读取器：判据与守卫

配套 `app-select-relay-server/SKILL.md` §9。适用于"不想引第三方库，但需要一份可读、可校验的
配置文件"的服务（YAML / INI / TOML 子集皆同）。

---

## 一、核心判据：**拒绝，而不是半应用**

自研解析器最容易犯的错不是"支持太少"，而是**支持之外的输入被静默接受**。
最坏的失败形态按严重度排：

| 失败形态 | 后果 | 严重度 |
|---|---|---|
| 拼错的键名被忽略 | 用默认值跑起来，行为与配置不符，且**没有任何提示** | ★★★ 最坏 |
| 重复键后者覆盖前者 | 改一处配置不生效 | ★★★ |
| 越界/类型错误被截断 | 端口变成 0 / 容量变成 1 | ★★ |
| 制表符被当成缩进 | 缩进层级错乱，键挂错父节点 | ★★ |
| **带行号报错** | 用户 5 秒修好 | ✅ 正解 |

⇒ 一条规则概括：**凡是不在写明子集内的输入，一律带行号报错，绝不猜。**

---

## 二、明确的子集范围（写进文档，也写进代码注释）

支持：

- `#` 注释、空行；
- `---` / `...` 文档标记；
- 缩进嵌套的 `key: value` 块（**只允许空格，2 空格一级**）；
- 单/双引号标量，含 `\n` `\t` `\\` `\"` 转义；
- 裸标量；
- 布尔：`true/false/yes/no/on/off/1/0`；
- `key.sub: value` 的点分扁平键（与缩进嵌套等价，便于 CLI 覆盖）。

**不支持（必须报错）**：

- 序列 / 列表（`- item`）
- 锚点 / 别名（`&a` / `*a`）
- 多行标量（`|` / `>`）
- 制表符缩进
- 第二个文档

---

## 三、报错信息模板（直接抄）

```
unknown configuration key(s): 'server.prot'          # 拼错键名 -> 列出所有未知键
duplicate key 'server.port' (first defined on line 3) # 重复键 -> 给出首次定义行
tabs are not allowed for indentation (use 2 spaces)   # 制表符
line 12: sequences are not supported in this subset   # 子集之外 -> 行号
server.port: expected an integer in [0, 65535], got 'abc'
```

要点：

- **"未知键"要一次列全**（用户常常改了不止一个）。做法：解析出一个键集合，
  再与**已知键白名单**求差集。
- **行号要尽量给**。为此解析时就要保留每个键的行号 —— 这也顺带让"重复键"能报首次定义行。
- 错误走 stderr，**退出码非 0**（例如统一的 `2` = 配置错误），且**不打印成功横幅**。

---

## 四、`port: 0` 必须合法（范围是 `[0, 65535]`）

很容易把范围写成 `[1, 65535]`，于是：

- 多实例部署无法共存；
- 自动化测试无法"让 OS 分配临时端口"，只能靠随机端口 + 重试，一定会 flaky。

⇒ 显式允许 `0 = 让 OS 选一个空闲端口`，并在启动横幅里**把真实端口打出来**
（否则调用方无从知道连哪里）。**顺带要有测试用例覆盖 `0`。**

---

## 五、守卫：样例文件 ↔ 内置默认模板必须逐字同步

服务通常有两份"默认配置"：

1. **内置默认模板**（`--print-default-config` 打印的那份）；
2. **随源码发布的样例配置文件**。

它们会漂移。修法是**让测试比对两者**（键集合 + 值 + 注释里的默认值）：

```
[app_test_config] default template  ==  shipped sample file   ... PASS (47 checks)
```

**一份真实的翻车记录（值得记住）**：改了默认模板后我按 target 增量构建，但只重建了
**测试目标**、没重编服务 ⇒ `--print-default-config` 打出**旧**模板，看起来像"改动没生效"。
⇒ **按 target 增量构建时，改了共享源文件必须全量重建再验收。**

## 六、启动期一致性告警清单

配置合法 ≠ 组合合理。下面每条都值得一条 `[warn]`（在启动横幅里，按 `#4` 的 ASCII 契约输出）：

| 条件 | 告警 | 为什么 |
|---|---|---|
| `max_clients > 等待集合容量 − 1` | `max_clients=N exceeds what one wait set can watch; the room will stop accepting at M` | 否则表现为静默丢数据（见 `fdset-and-select-limits.md`） |
| `backlog < max_clients` | `backlog=N is below max_clients=M; a connect burst larger than the kernel pending queue will be refused before the server can accept it` | 内核会在服务之前拒连接 |
| `poll_interval_ms` 很大 | 提醒"这也是最坏消息延迟" | 单线程轮询里 tick == 延迟 |
| 公告 / 预处理类开关开启 | 提醒"会往字节流里插入自己的字节" | 透传服务里这是**破坏透明性**的开关 |

**启动横幅要打印真实有效的数值**（`watch ceiling`、有效 `max_clients`、实际绑定的端口），
而不是用户写进去的原始值。**"读回真实值"是配置类问题的通用解。**

---

## 七、CLI 覆盖的优先级（写清顺序）

```
--config <path>  >  ./<name>.yaml  >  随源码发布的那份  >  内置默认
```

外加逐项 CLI 覆盖（`--host` / `--port` / `--max-clients` / …）。
**文档里写成一张有序表**，不要含糊 —— "为什么我的配置没生效"绝大多数时候是优先级歧义。

---

## 八、检查清单

- [ ] 未知键 → 报错并**列全**（禁止静默用默认值）。
- [ ] 重复键 → 报错 + 首次定义行号。
- [ ] 制表符缩进 → 明确报错并指出正确做法。
- [ ] 子集外语法 → 带行号报错，**绝不半应用**。
- [ ] `port: 0` 合法；启动横幅打印**真实**绑定端口。
- [ ] 内置默认模板 ↔ 样例文件**用测试比对**。
- [ ] 启动期组合告警：容量 / backlog / 延迟 / 透明性。
- [ ] 解析错误退出码 ≠ 0，且**不打成功横幅**（否则脚本会误判为启动成功）。
