# 实拍照片 → 3D 模型纹理

把实物照片贴到模型对应面上，用**最小的工程量**取得最大的真实感提升。
适用于"已有正确几何 + 想要真实外观"的任何装配体（机械臂、设备面板、机构件）。

**先划清边界**：这是 **Level 3→4 的视觉增强**，不是几何重建。
几何尺寸仍来自配置（YAML），与运动学/物理严格一致；纹理只挂在外观层。
若项目已有"外观几何 vs 运动学"的解耦（如 `links[].geometry` 与 `links[].length` 分开），
贴图就完全不动运动学 —— 这一点要先确认，否则改外观会连带改物理。

## 0. 先决定路线（别一上来就 SfM）

| 路线 | 照片需求 | 工程量 | 何时选 |
|---|---|---|---|
| **照片纹理贴图** | 每块板 1 张正视图 | 小 | **首选**：板件是平面/规则体 |
| 照片参考层 / 实拍叠加 | 1–3 张 | 极小 | 只要"看得见真值"，不要真 3D |
| SfM 稠密重建 → 换网格 | 每零件 20–40 张 | 大 | 曲面复杂、形态不规则 |
| 3D 高斯泼溅 | 100+ 张 | 很大 | 静态物体；**动态关节装配基本不现实** |

⚠️ **薄板 + 细杆 + 纯白背景的装配体是 SfM 的困难场景**（弱纹理、重复结构、特征匹配失败）。
这种物体做重建的产出/投入比很差，贴图路线反而更好看。

## 1. ★ 该拍哪一面：大面法向 = `size` 里最小那一维

零件 `size = [X, Y, Z]`（宽/厚/长）。**大面 = 去掉最小那一维后剩下两维张成的面**，
其**法向沿最小那一维**。

```
[22, 5, 74]  → 最小 Y=5 → 大面 22×74、局部薄轴 Y
[94, 82, 7]  → 最小 Z=7 → 大面 94×82、局部薄轴 Z
[30, 6, 22]  → 最小 Y=6 → 大面 30×22、局部薄轴 Y
```

**这条是整条路线最容易错的地方**：机械臂的大臂/小臂长板，大面朝向**左右**而不是正前方。
相机摆在机械臂正前方只会拍到 **5mm 厚的窄边** —— 那张照片**不能用来贴图**。

**解决：把相机摆到"侧面"（垂直于摆动平面）** —— 即 §1 末尾推出的 **±Y** 方向。
**不需要动任何关节**：长板的大面本来就朝左右，站到侧面就正对着它了。

> ⚠️ **2026-09-13 实测定论 —— 不要"转 base 关节把它转过来"**（旧建议已推翻，两处错）：
> 1. **`base` 限位只有 ±60°**（`robot.yaml` 实测读出），不是 ±90° —— 超了后端**直接拒发**。
> 2. **转向对分辨率是零和的**：远端确实放大 ×1.08，但板法向同时偏 20°、
>    投影缩短 `cos20° = 0.94` ⇒ **净 1.015**，还白搭一层透视。**转 base 是纯亏。**
>
> ⇒ **机位（相机在哪）才是变量，关节不是。** 详见 §2.5「动关节改变不了 px/mm」。

> 一旦换了机位，**同一批内不要再换回来** —— 混机位会让光照/白平衡不一致，
> 各零件贴到同一个模型上会像拼凑的。

### ★★ 但上面算出来的只是**局部**薄轴 —— 局部轴 ≠ 世界轴

「从侧面拍 / 俯拍」说的是**世界方向**，而 `size` 的最小维是**零件局部坐标系**里的。
**位姿一折叠，局部轴映射到哪个世界轴就变了。** 把两者当同一件事，会把一批零件标错方向。

实测（MuJoCo，同一机械臂、本位姿）：

| 零件 | 局部薄轴 | 本位姿**实测**世界方向 | 只看局部轴会得出 |
|---|---|---|---|
| `upper_arm_link` 大臂板 | Y | 世界 Y，\|1.00\| | 侧面 ✅ |
| `base_link` 底板 | Z | 世界 Z，\|1.00\| | 俯拍 ✅ |
| **腕部横撑** | Z | **世界 X（沿臂伸出方向）**，\|0.92\| | 俯拍 ❌ |
| **腕部本体** | Z | **世界 X（沿臂伸出方向）**，\|0.92\| | 俯拍 ❌ |

**别背轴向。** 两条更可靠的做法：

1. **代码里从模型读**：算出每个 geom 的 `world_R @ local_thin_axis`，看它落在哪个世界轴上
   （MuJoCo：`d.xmat[body_id] @ mju_quat2Mat(geom_quat)`；three.js：`mesh.matrixWorld`）。
2. **拿实物转一圈**，找面积最大的那个面，正对它。这是最终的、不依赖任何坐标约定的判据。

**顺带的坐标系基准**（读出来才知道"侧面"指哪边）：取关节轴的世界方向 ——
本例 `base` 轴 = 世界 Z（竖直）、`shoulder`/`elbow` 轴 = 世界 Y
⇒ 机械臂在 **X–Z 竖直平面**内摆动、本位姿朝 +X 伸出。
**相机必须摆在垂直于该平面的方向（±Y）**，也就是"侧面"。

## 2. 拍摄协议（四项硬性要求）

1. **正对（无透视）** —— 判据：板的两条平行边在画面上**平行且等长**（无梯形）。
   等价判据：板面亮度**无左右渐变**（光照梯度是透视的侧写）。
   做法：对准板面中心前后微调；有条件就**离远 + 拉长焦/裁切**（透视随距离衰减）。
2. **填满画面** —— 长边 ≥60% 画面高度。
3. **背景干净 + 光照均匀** —— 垫白纸/白板（便于白底暗件分割）；
   避免直射高光斑（**高光会被当成纹理永久贴上去**）与单侧明暗梯度。
4. **四角完整入画** —— 不要裁掉边角，板周围留约 5% 白边。

**不需要标尺。** 零件真实尺寸已在配置里（YAML），校正时直接以真实尺寸作为目标矩形
就能完成归一化。放把尺子也无害，可交叉验证比例。

**原图不要手动裁切/旋转/调色** —— 校正靠照片里四角的**几何位置**，裁切反而丢边界信息。

## 3. 四角估计：PCA + 对角极值（无 cv2 时等价 `minAreaRect`）

```python
ys, xs = np.nonzero(mask)
pts = np.column_stack([xs, ys]).astype(float)
mean = pts.mean(axis=0); q = pts - mean
_, vecs = np.linalg.eigh(np.cov(q.T))
axes = vecs[:, ::-1]                       # 主方向在前
rot = q @ axes                             # 旋到主轴坐标
s = rot[:, 0] + rot[:, 1]
d = rot[:, 0] - rot[:, 1]
corners_rot = rot[[np.argmax(s), np.argmax(d), np.argmin(s), np.argmin(d)]]
corners = corners_rot @ axes.T + mean      # 旋回
```

- 排序成 `[TL, TR, BR, BL]`：按 y 分上下两半，各按 x 排。
- **分割**：白底暗件，灰度阈值（本项目沿用手工标定的 90）。
- **去噪**：先腐蚀再膨胀（开运算）去掉孤立噪点，但**不改变整体外轮廓**。
  没有 cv2/scipy 时用 `PIL.ImageFilter.MinFilter/MaxFilter`。
- ⚠️ **必须目视复核**：PCA 在背景不干净（阴影 / 线缆 / 别的零件）时会给出
  **看似合理但错**的四角。每次落一张"原图 + 红框四角 + 校正结果"的复核图，
  **先看图再信结果**；不贴合就手动指定四角，**不要硬调阈值凑**。

## 4. ★★ 透视校正：自己写 homography，**不要用 PIL 的 `Image.transform(QUAD)`**

**实测结论（这条最值钱）**：PIL 的 `QUAD` 与本模块的 homography 约定**不一致**，
会引入 **+12~17px 的系统性平移**：

```
刻度线真值         [185, 370, 554]
PIL Image.QUAD     [197, 387, 567]   ← 差 12~17px
自实现 homography  [185, 370, 554]   ← 精确命中
（同一组四角、同一次 round-trip；四角估计误差本身只有 1.00px）
```

**它不抛异常、不崩、输出尺寸正确、内容也大致对** —— 表现只是"纹理好像被挪了一点点"，
在 3D 场景里看起来像"细节没对齐"或"贴图有点怪"，**归因方向全错**。

**用 DLT 解单应 + 自己双线性重采样**：

```python
def homography(src, dst):
    """4 点 DLT。src/dst 为 [TL,TR,BR,BL]。"""
    A = []
    for (x, y), (u, v) in zip(src, dst):
        A.append([x, y, 1, 0, 0, 0, -u*x, -u*y])
        A.append([0, 0, 0, x, y, 1, -v*x, -v*y])
    h, *_ = np.linalg.lstsq(np.asarray(A), dst.reshape(-1), rcond=None)
    return np.append(h, 1.0).reshape(3, 3)
```

**坐标约定必须写死在注释里**（不写清，下一个人会重踩）：
输出像素**索引** `(i,j)` 对应源坐标 `H·(i,j,1)`；两图四角按 左上/右上/右下/左下 一一对应。

**★ 半像素容差**（否则纹理边缘一圈白边）：区域判据别用严格的 `u ∈ [0, w-1]` ——
homography 有浮点误差（反投影出 `99.9999998`）会把边界行判成"区域外"填成背景色。
用 `u ∈ [-0.5, w-0.5]`（双线性在边缘本就该 clamp 到边界像素）。
真实照片的四角估计**永远**差半像素，所以这在生产中必然发生。

**归一化**：目标矩形尺寸 = 零件大面真实尺寸 × 统一 px/mm（如 10）。
长边统一放竖直方向（先按照片朝向校正，再依据长宽比决定是否旋转 90°），
这样不同零件纹理密度一致。

## 6. 用"合成模拟照片"自证几何正确

没有真实照片也能验证管线 —— 而且**必须**验证，否则你只证明了"它能跑"。

1. 生成**理想纹理**：整块铺满（**不要留白边**），在长边的 25%/50%/75% 处画横线
2. 用**同一个 homography** 把它投影成一个**梯形**（模拟拍照透视）→ "模拟照片"
3. 跑校正管线（分割 → 估四角 → 校正 → 归一化）
4. **断言**：三条刻度线回到预期像素位置（±几 px）、中心区灰度仍是零件色

> 踩过的坑：理想纹理四边留了 6px 白边"模拟板外背景"，导致分割只拿到**内缩一圈**的
> 深色区，校正后内容被放大 ⇒ 刻度线**系统性偏大** 13~16px。
> **真实场景里"零件区域"就是纹理本身**，所以合成时必须铺满。

## 7. 接口一致性：文件名清单必须**双向**比对

采集指南（给人看）和脚本（给机器看）各有一份文件名清单，**漂移的后果是
"用户照做了、脚本却找不到"，而且不报错**（只是安静地跳过）。

- 让**脚本**从配置（YAML）推导文件名清单，提供 `--list` 作为**权威清单**
- 加测试**双向**比对：指南里出现的每个 `<name>.jpg` 都必须是脚本认识的名字；
  脚本能处理的每个名字，指南里也要交代过（哪怕是"不建议拍"那一栏）
- 正则要容忍序号后缀（`` `foo_02.jpg` `` → 基础名 `foo`）
- 别名表（`DETAIL_ALIASES`）把不可读的 `link_detail3` 映射成 `link_brace`；
  **同名条目必须尺寸一致**（同尺寸的不同实例共用一张纹理），不一致要**报错**而非静默覆盖

### ★★ 别名的键是 `enumerate(details)` 的**下标** —— 给 details 加件会静默挤错它

实测（本项目：给 `forearm_link` 加一段"腕端补料"）：清单推导遍历的是
`geometry`(plate) **加上 details 里的所有 plate**，而别名键用的是 **details 数组下标**
（`forearm_brace` 就是该 link 的 index 3）。于是"给 details 加个件"**不是无副作用的操作**：

| 做法 | 后果 |
|---|---|
| 加一个 `plate` 插在**中间** | 清单多出 `link_detail1/2`，原别名错位成 `link_detail5` ⇒ 双向断言报「指南提到脚本不认识的文件名」 |
| 加一个 `plate` 追加到**末尾** | `detail1/2` 仍进清单 ⇒ 反向断言报「脚本能处理但指南里没提到」 |
| 加一个 **`box`** 追加到末尾 | 清单**逐字不变** ✓ |

⇒ 两条硬规则：

1. **补料 / 内部件用 `box` 而不是 `plate`** —— 管线只枚举 plate；且这类件本来就没有照片
   数据，没有纹理长宽比契约要守。
2. **必须追加到 `details` 末尾** —— 插在中间会让后续下标整体错位。这个耦合**只在跨语言的
   断言里才暴露**（YAML ↔ Python ↔ 文档），单看渲染完全看不出来。

### ★ 想"把板子改长"来补缺口？先看纹理长宽比契约

若把主板的 `size` 改长以填掉相邻缺口，会触发
「纹理长宽比必须与板大面一致」的契约（例：tile 3.778 vs 新板 4.444）。
**这条契约是对的**（它是"把图配错板"的防线），不要为了让它过而放宽容差 ——
而且**缺料段本来就没有照片数据，硬套贴图本身就是错的**。
正解是另加一段**不带 texture** 的补料（见上两条硬规则）。

## 8. 防倒退

对这类"静默几何错误"，加**源码扫描测试**挡住"顺手改回去"：

```python
def test_rectify_rejects_pil_quad_based_mapping():
    src = inspect.getsource(mt.rectify)
    assert "Transform.QUAD" not in src and "Image.QUAD" not in src, (
        "rectify 又用回了 PIL 的 QUAD —— 它会引入系统性几何平移（见 ADR）。")
```

同理可挡：`np.allclose` 用于纯运动学比较、`data.qpos[...] = target` 之类。

### 判定的三条防倒退（各钉住一个真实踩过的错）

```python
def test_undecidable_when_blob_touches_border_and_never_blames_tilt():
    """断言**不得**出现"离镜头更远" —— 禁止再把"框错对象"说成"板倾斜"。"""
    assert "离镜头更远" not in "\n".join(blockers)

def test_dark_scene_is_not_mistaken_for_blur():
    """喂**真机实测值**（ΔI=119、斜率 53）必须通过 —— 禁止退回绝对值判据。"""
    assert _ev(_metrics(plate_mean=24, bg_mean=143, sharpness=53))[0] == "ok"

def test_truss_openings_are_a_note_not_a_blocker():
    """填充率 0.40 时仍须 ok —— 禁止把镂空升级成阻塞。"""
    assert _ev(_metrics(rect_fill=0.40))[0] == "ok"
```

> 写断言时，**优先钉住"不许说什么"而不是"说了什么"**：
> `assert "离镜头更远" not in msg` 比 `assert "不可判定" in msg` 更能挡住归因退化 ——
> 后者在"既说不可判定、又顺带给个倾斜数字"时照样通过。

```
    纹理线  selftest 固化 + 往返恒等 + 源码扫描防倒退 + 文档一致性双向比对
```

> **测试为什么要分两条线**：倾斜方向、分辨率建议、归一化判据都是对指标的**算术**，
> 用构造字典测才精确。合成多边形会引入最小外接四边形的拟合误差 —— 那样测的是拟合，
> 不是判定逻辑。（实测教训：想合成一个"只有左右倾斜、没有上下倾斜"的多边形是
> **做不到的** —— 等腰梯形左右边必然等长，左右不等则上下必不等。硬凑只会得到
> 脆弱且失真的样本。）
