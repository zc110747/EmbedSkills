# 无浏览器环境下的前端取证与验证

## 何时用

沙箱封掉 Chromium/Playwright、真浏览器起不来，却要证明前端**对着活后端真的能跑**；
或故障形态是"编译通过、单测全绿、屏幕上就是 `undefined`"；或"首帧重影/幽灵副本、一交互就消失、截图永远抓不到"。

## 核心知识点

| 知识点 | 要点 | 判据 |
|---|---|---|
| 分层判定 | 客户端模块（L1）与组件渲染（L2）可在 Node 里全额覆盖；effects/轮询/接线（L3）与 socket/CORS/打包产物（L4）必须真浏览器或语言无关客户端 | 交付说明写明哪层没覆盖，别用一个绿勾假装全测过 |
| 真浏览器先试 | 本机已装的 Edge/Chrome 比下载 Chromium 快得多，先花几秒试一次 | 退出码非 0 + 输出 0 字节 + stderr 空 ⇒ 环境层拦截，别再调参数，转 Node 侧 |
| Check A | 用 esbuild 打包**客户端自己的模块**（不重写调用逻辑）去打活服务 | 逐个 URL 实打；每个面板字段的存在性单独断言，`=== undefined` 才算失败 |
| Check B | `react-dom/server` 的 `renderToStaticMarkup` 只要 DOM 树、不要 DOM | 产物不得含 `undefined`/`NaN`/`[object Object]`，且必须有正样本断言 |
| 首帧分流 | "首帧多出一份、一动就正常"是三码事：画两次且变换不同 / 画两次且变换相同 / 单帧陈旧变换 | 先定类再取证，三类证据与修法完全不同 |
| 逐帧记录器 | 在渲染回调里读**渲染真用的矩阵**，不调 `updateMatrixWorld()` | 帧 0 读到单位阵常是仪器伪影，不是 bug |
| 造前提 | 瞬态复现不了，多半是触发前提没被摆出来 | 去**数据源**造前提，别在渲染器里戳 |
| 源头对齐 | 修"同一份几何被喂了两组输入"，应让两个输入在源头一致 | 把第二个物体藏起来只掩盖假状态与跳变 |

## 判据与反模式

- 编译通过 ≠ 运行时正确；"不抛异常"不是判据，**字段存在性**才是。
- payload 必须从活服务现取；手写 fixture 测的是"我以为的形状"。
- 空态（未连接 session）必须单独渲染一遍，白屏的唯一解读是"前端坏了"。
- CORS **不能靠读配置**：写死的白名单读起来永远正常，而每个请求被 400 拒且浏览器报成"网络错误"。Node 侧请求结构上看不见它——全绿与浏览器全挂可以同时为真。改用**活服务两侧预检**：配置过的 origin → 200，没配过的 → 400。
- 回归断言要**两侧**；只断言"新 origin 被放行"会被"全放行"骗过。
- 抓不到瞬态不要靠多截图，要在**每一帧**留证；两张截图先平移对齐再取残差，看残差的**空间分布**。
- 比对前先打印图像尺寸：截图尺寸 ≠ 缩略图尺寸，按缩略图裁会裁到空白、残差假性为 0。
- 端口/主机由**同一个变量**派生，白名单、探测地址、绑定地址读同一个值。
- 改测试前先分辨哪条不变量是**刻意的契约**：应把它拆成两段（一次性 + 稳态）而更紧，不是删掉或放宽。
