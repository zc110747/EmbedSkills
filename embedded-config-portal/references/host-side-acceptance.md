# 主机侧真机验收：会骗人的地方与脚本约定

## 1. 四个会骗人的地方

1. **中文不能做 grep pattern（GBK 控制台）。**
   `netsh` / `ipconfig` 等系统工具输出是 GBK，在 bash 里用中文当 pattern 会
   **静默匹配失败 → 假阴性**（表现为"没连上""没拿到 IP"，其实已经连上了）。
   → 断言只用 ASCII：`TTL=` / `100%` / 目标网段 / HTTP 状态码 / 端口连通性。
   → 或按固定行号取（`sed -n '8p'`），但取到的可能仍是乱码，**别据此下结论**。
2. **扫描结果是缓存，不能证明设备活着。**
   系统的 SSID 列表可能是几分钟前的缓存；设备已经挂死，列表里仍然有它。
   → 判"设备是否活着"**以设备侧串口日志为准**，扫描只用于"发现"。
3. **关联失败的真实原因在系统的无线自动配置事件日志里**，不在命令行返回里。
   "网络不可用 / RSSI=255" = 根本没扫到该 BSS；"密码错误" = 完全另一回事。
   凭猜会浪费大量时间。
4. **连一个没有外网的热点会动默认路由。**
   先看路由表与接口跃点，确认默认路由归属；必要时给被测网卡钉一个很大的跃点（**需要管理员**）。
   没有管理员权限就不要硬改 —— 改为接受"验证期间本机公网可能瞬断"，把验证安排在不需要联网时。

## 2. 两条同源症状

- **设备"消失"先分清是拔线还是真崩了** —— 连续轮询串口端口列表：
  稳定消失 = 物理断开；反复出现 = 掉进 panic 重启（引导循环）。
- 某些 shell 工具会**吞掉子进程输出**；长命令或需要 stdout 的场景一律**落盘再读文件**，不要相信空输出。

## 3. 验收脚本怎么写

- **stdlib only**（如只依赖 `urllib`），不引第三方包，任何机器都能跑。
- **PASS/FAIL 计数 + 非 0 退出码**，可接进批处理或 CI。
- **读检查与写检查分离**；写检查必须**能恢复原值**并断言恢复成功，否则下次运行的前提就变了。
- 越界输入检查要断言**"设备未被改动"**，而不只是"返回了 400" ——
  否则"返回 400 却已生效"这类 bug 会漏过。
- 为**设备行为**断言，不为**接口形状**断言：
  带超时的读取要断言耗时落在预期区间，不能只看状态码。
- 至少留一条**否定路径**：非法通道号、缺参数、超范围值。

## 4. 交付口径

- 交付物（README / 汇报）里每个数字都要有出处：分区占用与百分比、内嵌页字节数、监听端口、路由条数。
  没核对过的写"未核对"，不要估算后当实测值。
- 说"验证通过"时要讲清**验证到了哪一层**：
  设备起来了 / 端口通了 / HTTP 通了 / 参数真的写进硬件并读回一致 —— 这四层经常被混为一谈。
