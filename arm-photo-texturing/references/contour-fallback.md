# 2.10 ★★★ 当照片只能给出**轮廓**：反解**参数化平面轮廓**（黑件 / 薄片件）

§5.5 的结论是"暗端件贴上去看不见内容"；但有更省的一条路线 ——
**黑件不需要纹理，它需要形状**。激光切割 / 机加工的亮切口恰好把剪影勾出来，
剪影里的形体特征（齿数、锯齿、收窄点、斜切角）是**可读且可数**的。

实测（机械臂夹爪，5 张近景）：黑件在照片里 `≤3` 码值占 **72%~77%**（无任何可提取纹理），
但读出了全部关键特征并参数化成 `type: jaw`：

| 读出的特征 | 实拍依据（可量化） |
|---|---|
| 根部**整圈方齿齿轮盘**（中心有装饰镂空 + 铰轴螺栓） | 齿轮直径 / 爪长 = 246/359 = **0.69** |
| 两片爪的齿轮**互相啮合**（不是各自独立转） | 齿廓在两者之间连续咬合 |
| 内侧缘**一排浅锯齿**（约 9 个） | 逐齿可数 |
| 外侧缘出盘后**先收窄一次**（"脖子"） | 收窄点约在 1/3 长度处 |
| 末端**斜切收尖** | 尖角内低外高 |

> ⚠️ 顺带作废"提亮救黑件"：且**别踩这个 Python 坑** —— 把数组归一化到 0–1 之后写
> `np.clip(a, 0, 255)` 会把整幅图压成**纯黑**（正确写法是 `np.clip(np.power(a,gamma)*bright*255.0, 0, 255)`）。
> 我因此连续生成 4 张全黑"放大图"，还一度误判成"裁切位置错"。

## 三条实践规则

1. **先做尺寸链自洽检查，再谈形状细节**。把照片上的**比值**（如齿轮直径 / 爪长）与模型比值对齐
   （实测 0.69 vs 0.71）—— 比值对不上时，后面所有细节都是在拟合噪声。
2. **派生量必须由几何推，不写进配置**。本例三条关系全在渲染层推：
   ① 两齿轮中心距 = `2 × 分度圆半径`（标准啮合）；② 爪指中线相对齿轮中心内偏
   `δ = 分度圆半径 − 宽/2`（让齿轮中心落在爪指**内侧缘**上）；③ 由 ①② 得
   **`θ=0` 时两爪内侧缘正好贴合**。
   把"配平"写进配置文件 = 把一致性检查从代码里删掉。**同时在解析层加前置校验**
   （`分度圆半径 < 宽/2` 直接抛错，并说明"爪中线会落到齿轮外侧且闭合时两爪贴不上"）。
3. **形状参数与观感参数分开记账**。哪些是"从剪影读出来的"（有证据）、哪些是"目视调出来的"
   （无证据，如锯齿数 / 颜色），必须在文档与 ADR 里**显式区分**，否则下一轮会把目视调参当测量结果。

## 渲染实现：为什么必须是**一条连续闭合折线**

要让"齿轮盘 + 爪指"成为**一个**件，`ExtrudeGeometry` **不做布尔并集** ⇒
画成两个 Shape 会 z-fighting、分离处露接缝。必须**首尾相接成一条闭合折线**
（有中心镂空时，`shape.holes` 的绕向要与外轮廓**相反**）。

- 坐标映射只认一个：`Shape(x, y)` → 机构 `(Y, Z)`、挤出轴 → `X`，即循环置换 `(x→y, y→z, z→x)`，
  行列式 **+1** ⇒ **不翻手性、法线无需修正**。
- ⚠️ **镜像必须反转点序**：轮廓 x 取反后绕向变顺 ⇒ 挤出体法线朝里（发黑 / 漏光）。
- ⚠️ **倒角会把顶点挪走**：0.3mm 倒角让"爪尖"理想点偏 **0.176mm** ⇒
  "θ=0 内侧缘贴合"这类判据要给容差，并**另加一条精确不变量**（如镜像对称 `left.y ≈ −right.y`）来钉死逻辑。
- ⚠️ **单测不要自己重算坐标**：直接读 `geometry.getAttribute('position')`，
  在极值处取均值。手算很容易漏掉"平面 → 机构"的坐标置换（实测漏掉后取到了 Y 方向的齿轮中心偏移 **21**）。
- ⚠️ 齿轮只做**一段弧**（爪指开口处无齿）时，齿数要按
  `round(gearTeeth × 弧角 / 2π)` 折算，不能直接用整圈齿数。
