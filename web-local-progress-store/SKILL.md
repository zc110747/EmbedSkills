# 纯前端本地进度：存储、导出导入、跨端镜像

没有账号也没有后端时，"学习到哪了 / 收藏了什么 / 看到第几页"只能存在本机。
难点不在读写 `localStorage`，而在**身份稳定、载荷兼容、迁移不丢数据、多端对得上**。

## 何时用

- 静态站/本地应用要记住「哪些条目已完成」，且**明确不上传**。
- 要提供「导出 / 导入」让用户换设备，或让桌面端、手机端、网页端三方共享同一份进度。
- 收到「**导入后记录变少了**」「**手机上勾了电脑上看不到**」「**文件明明是对的却说格式错误**」。

## 核心知识点

| 知识点 | 结论 |
|---|---|
| 身份 | 存**永久 ID**（如四位补零字符串 `"0001"`），永不拿标题/文件名/序号当身份 —— 标题会改，编号不会 |
| 版本化 | 载荷带 `schemaVersion`；不认识的版本**拒绝并说明**，不要"尽力解析"（会把数据解释错） |
| 键名 | 存储键自带语义与版本（`<app>_<feature>_v1`），改结构就换键，不原地改语义 |
| 导出即契约 | 导出的 JSON 是**对外接口**：键序、缩进、行尾都算格式。跨语言/跨端必须逐字节同构，否则「可以互相导入」只是宣传语 |
| 载荷最小化 | 只放版本号 + 条目 + 时间戳；不放正文、不放机器信息、不放任何个人信息 |
| 导入两段式 | 先**预览**（文件有效条数 / 当前条数 / 两种模式各得多少）再执行，别一点就写 |
| 合并 vs 覆盖 | 合并 = 并集，绝不删除；覆盖 = 以文件为准，**会清掉已有记录** ⇒ 必须二次确认 |
| 无效项 | 格式非法条目跳过**并计数**，未知 ID 忽略**并报数量**，重复去重；一个不剩就拒绝导入 |
| 坏存档 | 解析失败/结构不对时：**现有进度一律不动**；不可解析的旧存档先备份成 `…__corrupt` 再重置 |
| 存储不可用 | 隐私模式/禁用存储时退化为**内存态**并提示，功能不崩 |
| 纯逻辑抽离 | 解析、合并、统计做成不碰 DOM 的函数并挂到 `globalThis`，才能在 Node 里真跑测试；模块顶层不要一上来就 `document.xxx` |

## 跨端镜像（桌面/手机外壳）

外壳把网页的 `localStorage` 镜像成**同目录一个 JSON 文件**，格式与网页「导出」完全一致：

```
写：页面每次 setItem → 桥接脚本转成字符串 → 原生按键名落盘（先写 .tmp 再替换）
读：启动时把文件内容当"种子"塞回 localStorage（只在网页为空/不同时覆盖）
兜底：再加一次定时轮询（1.5–2 s），因为网页可能有绕过 setItem 的写入路径
```

- **行尾是隐藏的坑**：.NET 的 `Environment.NewLine` 在 Windows 上写 CRLF，而网页导出是 LF。
  "同构"要按字节核对，否则 diff 一开就是满屏差异（JSON 语义等价，但比对会失败）。
- 落盘用「临时文件 + 替换」，避免进程被杀时留下半截 JSON。
- 导入到网页的路径要和导出的路径共用同一个解析器，别写两套。

## 判据与反模式

- 判据不是"能存能读"，而是：**换端之后条目数、时间戳、键序全部一致**，且两端文件可互相导入。
- 反模式：拿标题当键；把 `schemaVersion` 当装饰；导入直接覆盖；用 `JSON.parse` 的异常当唯一校验；
  在桥接脚本里自己发明一套格式（应当直接复用网页的导出载荷）。
- 删除类操作（覆盖导入、清空）一律二次确认，并把"会少几条"提前算出来告诉用户。
