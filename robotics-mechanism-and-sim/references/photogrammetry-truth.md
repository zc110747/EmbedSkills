# 机构几何真值的取证与校核

## 0. 边界：管什么、不管什么

| 管 | 不管 |
|---|---|
| 真值从哪来、能不能信、怎么证可复现 | 链路怎么把真值送下去（串口/固件/协议） |
| CAD / 照片 / 相机取证的手法与陷阱 | 仿真里怎么用这份真值 |
| 改真值的连锁影响与校验顺序 | 外观/纹理细节（另一条轨，只给边界） |

## 1. ★★ 铁律：先证"测量可复现"，才有资格改真值

- **单批"最优" = 过拟合。** 定 ROI / 阈值 / 骨架模型**必须跨 ≥2 批验证**。
- **"改模型让它对上"与"调参数让它对上"是同一类错误。** 必须先证**测量本身可复现**
  （如：某增益跨批极差在几个百分点的量级以内），再改真值文件；**一次只改一条**，改完**重跑判据**。
- 真值文件是**唯一**的（尺寸/限位/标定/耦合只此一份）；**禁止**在测试、固件、前端里
  各留一份"方便用"的常数 —— 那会让"改了一处没改另一处"静默通过。
- ★ **带区间的搜索必须显式检测"最优解是否贴边"**：最优落在区间端点 **2% 以内**
  ⇒ **那个值不是测量结果，是区间的人为截断**。
  ⇒ **两个读数互相矛盾时，先查区间是不是设窄了，别急着改模型。**
- **纯几何推理走不通时，改用「致动并观察」（motion-diff）**：动一个关节 → 拍前后两帧 → 差分
  ⇒ **差分区域 = 该关节及其下游零件**。不依赖任何相机位姿假设。
  ⚠️ 但它**给不出干净的单块板四角** ⇒ 只能做**归属判定 + 粗定位**，别拿它当尺寸来源。
- 量包围盒**必须目视复核**（线缆、桌沿会污染 bbox）；**手入镜 / 相机位移是头号污染源**。
- ★ **固定 ROI 只在同一机位下可比**：换机位必须重定 ROI **并目视确认 ROI 落在物体上**；
  量一个小面时**不要**用"掩膜 bbox 画矩形"（会把**确实该变**的邻件圈进来）
  ⇒ 在**基线图算出的固定像素集合**上量。

## 2. ★★ 能力边界：常见的三件"量不出来"

1. **无位置回读的开环舵机**：`OK SET` / `STATUS` / 后端 `joint_state` **全都在说"我打算去哪"**，
   **没有一条**能证明"它实际上在哪"；**唯一外部地面真值是相机**。
   ⚠️ **「无位置回读」≠「没动作」** —— 只说明**不能证明"到位"**，**不等于"没动"**。
   链路侧的误差面板反映的是**时延与限位截断**，不是"物理臂到位没有"。
2. **包围盒不能当连杆长**：mesh bbox 含端盖 / 横撑 / 倒角 ⇒ **系统性偏大**。
3. **CAD 姿态 ≠ 零点位** ⇒ 见 §4。

★ **三态 `ok` / `reject` / `undecidable`；「判不了」≠「不合格」** ——
判不了时**禁止**输出"像结论"的数字（采集类产物是**给操作者的行动指令**，
指令错了**不会报错**，人会照着错的指令调很久）。

## 3. ★★ 读复杂标准格式一律用参考实现（自研解析器会骗你）

实录：自研正则解析 STEP 误判「只有层级没有几何、0/241 可达」并写成 `BLOCKED`；
换 **OCCT**（`cadquery-ocp`，`STEPCAFControl_Reader` + `XCAFPrs_DocumentExplorer`）
读同一文件 ⇒ **111/111 全有几何**。

- ★ **铁律**：自研工具给出**否定性结论**（"文件坏了"/"数据缺"/"0 可达"）时，
  **必须先用参考实现复核** —— 否则把**工具的能力边界**误报成**数据的缺陷**。
- 自研解析器会**静默丢弃**的三处（修完一处还会被下一处继续骗，**别逐个打补丁**）：
  ① **复杂实例**（多子类型并列、无单一类型名）；② **嵌套括号引用**（漏 list 就断链）；③ **编码混杂**。
- ⚠️ **"计数对齐" ≠ "解析正确"**：修好 ① 后实体计数已对齐（0 缺失）但几何仍为 0
  ⇒ 不能拿计数当验收判据。

**OCP / pybind 绑定常见坑**（写脚本必踩）：

| 症状 | 正解 |
|---|---|
| `Bnd_Box.Get()` 报 `Unable to convert … Limits` | 取 6 个 `CornerMin()/CornerMax()` 分轴访问 |
| `XCAFPrs_DocumentExplorer.Flags_s()` 不存在 | 用**模块级** `XCAFPrs_DocumentExplorerFlags_None` |
| `exp.IsCurrentLeafNode()` 不存在 | 用 `not node.IsAssembly` |
| 叶片标签是无名 `NAUO*` | 真名在 **`node.RefLabel`**（`IsNull()` 才回落 `node.Label`） |
| 序列类型不在预期子模块 | 如 `TDF_LabelSequence` 在 `OCP.collections.Sequence_TDF_Label` |
| 目标几何与同轴杂面混在一起 | **按半径阈值分离**（目标轴的半径显著大于同心杂面维度 ⇒ 取半径 ≥ 某阈值过滤） |

## 4. 从 CAD 读关节轴：可行；反推连杆长：不可行

**可行** —— **舵机输出轴 = 关节旋转轴**。在舵机实体上枚举圆柱面
（`BRepAdaptor_Surface` + `GeomAbs_Cylinder`），每个舵机都会命中**多个共轴圆柱面**（同半径），
一致性高即非偶然面 ⇒ 得到轴方向 `d` 与轴上一点 `p`。

- ★★ **两轴严格平行（夹角 ≈ 0）⇒ 平行四连杆的结构性签名**：间距固定
  ⇒ 此前只靠**照片反解**的经验拟合耦合（拟合残差可观）**升级为结构事实**。
  这类"从拟合升格为几何事实"的结论要写进决策记录与真值文件注释
  （**注释不触发**冻结基线）。
- 轴方向与真值文件逐条比对 ⇒ 得到 `KINEMATIC_STRUCTURE_CONFLICT = YES/NO`，
  比"看起来对"强。

**不可行** —— ⚠️ **`length` 不可由 STEP 反推**（别浪费时间再试）：
已证 **STEP 姿态 ≠ 零点位**。真值零点位下两轴应差一个已知角度，而 CAD 实测 **≈ 0（共线）**
⇒ STEP 给的是「**该姿态下**的瞬时轴间距」，而需要的是「**零点位**沿各杆 +Z 的伸展」。
拿它写进 `length` 会**立刻破坏 FK/IK + 冻结基线**。
同理「底板→某轴」的距离含舵机体 + 转盘板 + 立柱板，而 `length` 是"纯伸展" ⇒ **语义不同**。
⇒ **唯一正当路径 = 标尺实拍**（正交侧视 + 画面内标尺）。

## 5. 关节与机构判定速查

- **关节轴**：常见布局 = 底座绕**竖直轴**偏航；肩/肘/腕在**同一竖直平面**内俯仰；爪沿**水平横轴**分开。
  ⚠️ 若手上的 spec 示例给出的轴向与"哪个轴管上下"**自相矛盾**，按"能得到竖直平面 2R 机构"的那组取值
  —— 照另一组会变成**水平 SCARA**，与整机完全不符。
- **被动关节**（如"爪的绝对倾角被连杆锁住"）不进状态量、不进 UI、不进协议 ⇒
  加它可以**不改协议一个字**。判定它该不该进协议，看它**有没有独立执行器**。
- ★★ **绝对角 vs 局部角**（最容易搞错的一条）：
  - 某关节可能存的是**绝对倾角**，而真机由**独立执行器 + 平行四连杆**驱动
    ⇒ 与上游关节**解耦**，用 `coupling: {joint: <upstream>, gain: -1}` 表达；串联网里的**局部旋转**
    = 常数 + (−1)×上游角。
  - ⚠️ **这种关节的合法域是"斜的"**（与上游耦合），而 MuJoCo hinge 的 `range` **只能表达轴对齐的盒**
    ⇒ **没有任何单一 range 能表达它**。若只靠 range，仿真会照常执行"局部角在盒内、但绝对角结构上转不到"的位形。
  - **架构结论**：**真值文件 = 唯一限位真值**；仿真的 `range_padding_deg` 只承担
    **数值保护**（防积分器发散），**不承担语义**。
- **`link.length` = 机构尺寸的唯一真值**：一根连杆沿**其近端关节坐标系**的 +Z 伸展 `length`，
  末端即下一关节坐标系原点 ⇒ **改 `length` 即改机构尺寸**，无需同步改任何关节字段。

## 6. ★ 改真值的连锁清单（照抄这个顺序）

改运动学（`length` / 轴限位 / 耦合 / `actuators`）或物理量时**必须按序**做完，漏一步会被守卫抓到，
或更糟：**静默不一致**。

| # | 动作 | 判据 / 坑 |
|---|---|---|
| ① | 重生成产物（MJCF / URDF） | 产物过期 ⇒ "配置与产物同步"守卫报红（**守卫正常工作**） |
| ② | 重冻结基线 | ★ **冻结基线的键 = 真值文件的仓库相对路径** ⇒ 更新后**哈希必须逐位不变**；变了说明路径动了 |
| ③ | 重采集黄金数据 + Sim2Sim 冻结 | 不重跑 ⇒ Sim2Sim 回归必红 |
| ④ | 修**写死旧值的断言**（前后端都有） | ★ **能引用 `limits.min/max` 就别写死端点**，否则每次修订都制造假红 |
| ⑤ | 同步全部文档 | **文档↔配置一致性要在测试里盯**，不靠自觉 |

★★ **最容易踩：方向类标定会翻转"钳位端"。** 改 `reverse`（或等价方向翻转）后，
**逐处检查"越界钳位"断言钳的是哪一端** —— 实测把 `θ+K` 改成 `−θ+K'` 后，
原用例用大正角触发"钳上限"，新映射下它钳到**下限** ⇒ 必须改用大负角才保持原意。
⇒ **通则：改方向后把"所有越界用例"逐个重算期望值**，不要只看"还报不报错"
（方向反了**照样是绿的**）。

★ **标定三端点自洽**：改方向时 `homePose` 必须能反算回固件开机位，
而**旧关节限位本身可能是照旧（错）方向定的** ⇒ **限位必须一并由执行器硬限位反算**，
不能只翻 `reverse`、也不能只改 offset（两种都会撞车）。
⚠️ 仅由**口述**得到的方向**没有相机判据**时，要显式标注"待独立复核"。

## 7. 冻结基线的"语义核心"边界

判据是**语义核心哈希**，不是整文件：

- **放行**：改**外观**（`links[].geometry` / `details` / 外观段）—— 换网格、改尺寸**不报错**
- **报错**：改**运动学**（`length` / 轴限位耦合 / `actuators`）或**物理量** ⇒ 逐字段列差异

⚠️ **外观阶段边界**（动之前先确认）：

| 允许改 | 禁止改（**动了就要停下问用户**） |
|---|---|
| 几何形状 / 细节件 / 外观参数 | `length` / `joints.*` / `actuators.*` / `homePose` / **`tcp`** |

- ★ **`tcp` 在语义核心白名单里** ⇒ 外观阶段**绝不要**顺手改它。
- ⚠️ **不得**按视觉外观重新划分连杆（显示分组必须沿用既有边界，只换**内部**几何）。
- ★ **`content_hash` 的语义陷阱**：`generated_by` 描述的是"生成产物的生成器"，
  **不是**真值文件本身；**只有产物**（URDF / MJCF 之类）才标 `is_generated=True`，
  真值文件 / 物理量 / 各条目 / 用例一律 `False`。

## 8. ★ 已放弃的路线（别再试，省得重复劳动）

| 路线 | 放弃理由 |
|---|---|
| CAD → URDF 直接接入 | 官方导出的 URDF 可能只有极少 link / 0 joint、件未指派、且 **mm 尺寸配 m 原点的 1000× 单位错** ⇒ joint origin/rpy/axis/limit **无输入可取** |
| 从 STEP 反推 `length` | 已证 **STEP 姿态 ≠ 零点位**（见 §4）⇒ 唯一路径是**标尺实拍** |
| 自研 STEP/URDF 解析器 | 会给出"文件坏了"的假结论（见 §3）⇒ 一律用参考实现 |
| 用 mesh 包围盒当连杆长 | 系统性偏大，禁止 |
