# 邮件周期汇总（Weekly Mail Digest）

## 何时用

- "邮件汇总""上周邮件""邮箱周报""邮件周报""看看这周有什么邮件"
- 把某时间区间（默认「上周」= 上一个自然周，周一 00:00 ~ 下周一 00:00）的收发邮件归纳成报告
- 同一套流程可缩短为日报、拉长为月报

产出：`outputs/email-weekly-<起始日期>_<结束日期>.html`，深色极简风格，用 `present_files` 打开预览；聊天里给「统计概览 + 明细 + 要点提炼」三段式。

## 核心知识点

### 1. 调用序列

邮件 MCP 工具默认不在激活列表，先用 `ToolSearch`（精确工具名）加载 schema，再用 `DeferExecuteTool` 调用。需要的是「取账户信息 / 列消息 / 取单封消息（可选搜索）」四个。

1. **取主邮箱账户**：调用取账户信息的接口，在返回的 `aliases[]` 里取 `is_primary: true` 的 `alias_id`；每次会话先调一次。
2. **列消息**：对 inbox 与 sent 各拉一次，用 `after` / `before`（ISO8601 带时区偏移）过滤区间；单个请求 `limit` 上限 50，翻页看 `pagination.next_cursor` / `has_more`。
3. **按需取正文**：只对确实需要正文的 1~2 封调用取单封接口。

### 2. 正文陷阱与统计口径

- **不要对每封都取正文**：营销类 HTML 邮件正文可达十万字符量级，会被截断落盘，白烧一轮上下文。列表接口返回的 `snippet` 已足够写摘要。
- `created_at` 是 **UTC**，展示一律换算到本地时区（+8）再写。跨日要仔细核对，别把日期写错一天。
- 统计口径：收件数 / 已发送数 / 未读数（`is_read: false`）/ 带附件数（`has_attachments: true`）。
- 按发件人域名归类：厂商资讯、活动邀约、账号安全、推广广告。
- 若除主邮箱外的第二账户未开通（接口返回 `not_bound`）：不要重试、不要向用户重复报错，只在结尾说明本次覆盖范围。

## 判据与反模式

- 摘要写成中文陈述句，不要照抄英文 snippet。
- 明细按**重要性**排序（待决策 / 与技术栈相关 > 资讯 > 推广 > 广告），不是纯时间序。
- 要点段给 2~3 条**结论**，并标出「待你决策」的项（授权请求、报名截止之类）。
- 版式一旦确认满意就固定，不擅自改风格、不加彩色状态色。
- 结尾必须复述统计表与要点，并说明数据源与覆盖范围。
