# 端到端验收与规模压测

代码「生成」只是第一步，**跑通验证闭环**才是迭代基础。两类战场共用同一套纪律：

- **固件侧**：构建 → 烧录 → 串口/SWD/像素观测
- **上位机侧**：N 客户端压测 → stats 采样 → 无损/背压/泄漏断言

差别只在观测手段，翻车方式高度重合（采样太早、读旧行、判据恒绿）。

## 何时用

- 交付/验收任何一个子模块：固件、上位机服务、视频链路。
- 写自测 / 回归脚本，定义「通过」的标准；或已有测试「总是通过」，要判断它是否**恒绿**。
- 一键脚本跑不起来、真机现象与代码对不上时做故障定位。
- 多客户端规模压测、压测偶发失败（flaky）、读到的计数像「服务什么都没干」。

## 五条通用纪律（先立规矩，再写场景）

| 纪律 | 内容 | 违反后的典型症状 |
|---|---|---|
| **A 断言前先等前置** | 任何「断言某状态」的前一行必须是「等它该成立」 | 1000 客户端在冲连接，内核握手完成 ≠ 服务 `accept()` 完 → `online=973` 假失败 |
| **B 读计数先记基线** | 等待条件必须基于**基线**（`before + 1`），不是「存在某行」 | 缓冲里早有 `[stats]` 行 → 立刻成立 → 读到上一轮的 0 |
| **C 负向对照** | 用同一份源码编一份**重新打开缺陷**的「旧行为」二进制，跑同一套断言，必须 FAIL | 脚本没有牙齿：坏二进制也全绿 |
| **D 判据抽纯函数** | 真机路径与 `--selftest` 离线路径**调用同一个函数** | 自检另抄一份判据 → 改真判据时自检照样绿 |
| **E 先查工具再查产品** | 「我没观测到」≠「它没发生」；否定性结论一律先查观测能力 | 格式不匹配被误诊成探针故障 / 固件缺陷 |

> 超时要**如实报失败**，而不是放宽断言 —— 放宽会同时放走真失败。

## 固件侧硬判据

- **构建**：Debug + Release **双构零警告**；显式给出 FLASH / RAM 字节数与占比。
- **烧录**：烧 **`.elf`**（`.bin` 会报 `no flash bank found` + `wrote 0 bytes`），见 `Verified OK`；
  改完代码**必须先重烧**再抓串口 —— 只 `reset` 会看到旧固件行为。
- **「没报错 ≠ 有数据」**：调用返回 0、日志被限流都不算证据。取符号地址后直读内存比对预期值。
- **`mdw` 只能 4 字节对齐整字读**：非对齐报 `Failed to read memory`，且 sysprogs 版 OpenOCD
  会打印 `0x…: ERROR 0` **且不报错退出**（症状是「读回少几个字段」）。读窄变量先按
  `off & ~3` 对齐到整字并去重，再按 lane 切字节。
  ⚠️ `mdw` 打印的地址是**小写** hex —— 用 `%08X` 去匹配会静默匹配不到（返回一堆 `None`、
  不抛异常），正则必须 `IGNORECASE`，且「解析失败」与「会话失败」要分开报。
- **多区域读取必须在同一次 halt 内完成**：两次 `dump()` 是两次独立会话，之间固件自由运行
  ⇒ 拿到的是不同时刻快照（实测同一变量差 2379 counts）。
- **短于一次会话的瞬态窗口（百 ms 级）：单点采样＝抽签**。一次会话本身 0.3~0.6 s，
  对策是**一个会话内采一排点**（注入命令 → 短睡 → `halt` → 读数 → `resume` 重复 N 次），
  判据降级为**形状判据**（存在某点满足 A / 峰值满足 B / 末点满足 C），每条对应可证伪机制。
- **物理输入仿真「长期生效」是有条件的**：引脚电平真变过一次（手碰按键 / 抖动 / 排线松动），
  注入的按下态会被**静默抹掉**，固件无痕迹，真人按键不受影响 —— 这不是固件缺陷。
  对策：同会话内、松开前读「已按住时长」计数器做**目标侧见证**；开跑前加静止门
  （原始电平/稳定态/时长任一非零即拒绝开跑）。⚠️「去抖计数已饱和」**不能**证明此刻没人按键。
- **验收脚本自己的退出码语义必须自测**：Python `sys.exit(True)` 退出码是 **1**、
  `sys.exit(False)` 是 **0** ⇒ 直接传 `main()` 的布尔返回值会得到**PASS 报 1、FAIL 报 0**。
  统一 `return 0 if ok else 1`，并穷举「比对成败 × 收尾成败」四种组合钉死映射。
- **`argparse` 的 `help=` 里不能出现字面 `%`**：会对 help 再做一次 `%` 插值 →
  `ValueError: unsupported format character`，`--help` 与 usage 提示**同时崩**（正常路径不受影响，
  能长期潜伏）。`%%` 转义也不行（会被外层 `%` 格式化先吃掉）。措辞改「百分比」，
  并把「每个脚本 `--help` 退出码 0」纳入回归。
- **坑/地址是两端的**：绑定地址、白名单、就绪探测必须读同一个变量；改端口后真把端口移开跑一遍。

## 上位机侧硬判据

- 「5 个客户端全绿」**不能**推任何关于 1000 个客户端的结论。规模压测要回答：
  **无损吗？有背压吗？有泄漏吗？退出干净吗？这个脚本会不会恒绿？**
- 无损的「唯一证明」是**聚合恒等式**（发包总数 = 收包总数 + 各端丢弃数），不是逐包日志对齐。
- 断言分层：**包边界**（切包正确）与**字节相等**（内容正确）分开断言 —— 混在一起时，
  内容错了和边界错了给出同一个红，定位要重做。
- 失败信息必须**精简**：每条断言只给「期望 / 实际 / 第一个不符的下标」，不要 dump 整个包。
- 接进 CTest 只跑**快速子集**，长时间压测单独入口。

## 判据与反模式

- 脚本报 FAIL，**先怀疑前提没成立**，再怀疑产品代码（四类自造 FAIL 见 references）。
- **一条断言只证一件事**；别把「后来的合理变化」断言成「没收敛」。
- **警惕「退化相等」型假判据**：`平滑极差 <= 原始极差` 在平滑完全没生效（两个量同一个数）时
  照样成立 ⇒ 永远绿。比较两个统计量前先自问「功能彻底失效的话，这条还成立吗？」
  对策：留**相对余量**（`<= 0.75 ×`）；基准量太小时报「判据不适用」而**不给 PASS**。
- **用例的边界值必须从真值源推导，禁止写死**：写死的 `speed 4.1`（本意「超上限」）在量程
  4.0→4.5 后**反而合法** ⇒ 静默变成另一件事、照样 PASS。同理，脚本默认参数也要锚到真值源，
  解析不到就**报错退出**，不回落成硬编码。
- **状态机类改动必须逐个「沿」验收**：只测上升沿、漏掉下降沿，而停机路径往往不改任何其他
  变量 ⇒ 「只在 A 变化时清理」的写法一路不触发，残留上次的值，而屏幕可能仍然正确。
- **阈值类判据取「连续段下界」**：物理阈值附近常是**随机**的（最低档偶尔成、中间档全败、
  高档全成）。取 `min(通过的档)` 会锚到「偶尔成了」的点，给出假安全感。
- **比「一次会话」还短的瞬态、『相位翻转』拍、写基准合成传感器输入**等长案例，
  配方见 `references/verify-script-patterns.md` 与 `references/embedded-acceptance-playbook.md`。
- 一键脚本自身 `exit 0` **不能**推断服务还活着（常驻进程可能已被回收）；验证必须在同一次调用内做完。
