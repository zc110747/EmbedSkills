# 设备运行期配置门户与状态推送

## 何时用

- 给既有固件加"手机连热点改参数"的运行期配置能力。
- 网页或本地 UI 显示的值与硬件实际值不符，或界面只是命令回显。
- 需要定义运行期可改参数的取值域、校验、持久化与生效口径。
- 连不上板子，仍要对内嵌网页做行为断言。

## 核心知识点

| 主题 | 结论 |
|---|---|
| 病根 | 同一份配置被驱动层、网页层、本地 UI、持久化层并发读写。先定唯一真值源 + 串行化 + 白名单，再写业务。 |
| 唯一真值源 | 配置结构体、取值域白名单、标签↔取值互转函数只定义一次，四层全部引用。 |
| 取值域 | 对齐被配置硬件的真实约束，给显式白名单，不收"任意正整数"。 |
| 串行化 | 读自带秒级超时、改参数写同一外设 → 必须互斥；锁落在驱动层，顺序为取锁→等 flush→重配置→放锁。 |
| 网络输入 | 一律白名单；非法值 4xx 且不写盘、不下硬件；失败要结构化可观测，不得 200 + 静默忽略。 |
| 持久化 | 无记录用默认值并打日志；读回再校验一次；区分"已保存"与"已生效"。 |
| 内嵌网页 | 走构建系统的资源嵌入能力，不内联 C 字符串；响应显式带 charset。 |
| 状态推送 | 界面读"设备真实值"而非"输入值"；快照周期推送，事件队列只承载变化，无客户端零开销。 |
| 无硬件验证 | Node vm 沙箱 + 最小 DOM 桩注入真实 state JSON，对渲染结果做行为断言。 |
| 主机侧验收 | 中文不能做 grep pattern；扫描结果是缓存；关联失败看系统事件日志；连无外网热点会动默认路由。 |

## 判据与反模式

- 反模式：网页拼字符串、驱动写宏、UI 再写一份显示文本 → 加一个取值要改三处。
- 反模式：给每个控件单独打补丁（加回读、加定时器）→ 应建统一状态通道一次解决。
- 反模式：把周期性大帧塞进事件队列 → 队列元素膨胀、白吃 RAM。
- 反模式：前端留 setInterval 轮询、断线 reload()、回填输入框不跳过 activeElement。
- 判据：越界输入要断言"设备未被改动"，不能只看"返回了 400"。
- 判据：说"验证通过"必须讲清到了哪一层：设备起来 / 端口通 / HTTP 通 / 参数写进硬件并读回一致。
