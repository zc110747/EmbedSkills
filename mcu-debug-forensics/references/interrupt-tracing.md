# 中断链路与总线故障的取证

## 1. EXTI 软件中断注入——免手指验证链路

向 `EXTI->SWIER` 对应线写 1，会产生**与引脚边沿完全等价**的中断请求，用于验证
`EXTI -> NVIC -> HAL_EXTI_IRQHandler -> 回调 -> xSemaphoreGiveFromISR -> 任务被唤醒`
整条链路，无需人手去点触摸屏 / 按按键。

```bash
openocd -f <ocd.cfg> -c "reset run" -c "sleep <ms>" -c "halt" \
  -c "mww <EXTI_IMR> <line_bit>"     # 先强制使能该线（ISR 自屏蔽时必须） \
  -c "mww <EXTI_SWIER> <line_bit>"   # 注入该线 \
  -c "resume" -c "sleep <ms>" -c "shutdown"
```

> 注意：若该中断的 ISR 在入口**自屏蔽**自己的线（防噪声），注入前必须先用
> `mww EXTI_IMR <line_bit>` 把 mask 位打开，否则软件中断会被直接丢掉。

回读 `SYSCFG->EXTICR[n]`（`n = line / 4`）可确认该线复用到哪个 GPIO 端口，例如
`0x00007000` 表示 line 7 的 `EXTI7` 字段为 `0x7` → 已复用到 `GPIOH`。

**边界**：这条验证的是**链路通断**，不验证引脚电平——仍需真实触发一次看是否产生业务日志。

## 2. 中断风暴定位与防护

**现象指纹**：中断计数在几秒内爬到几万；ISR 抢占低优先级的轮询式 I2C 传输 → HAL 超时 →
从机拉住 SDA → I2C 总线 BUSY 锁死，之后每次读都失败。

**典型根因**：中断引脚配成浮空（`GPIO_NOPULL`），且紧邻一条高速翻转的信号线
（如软件位绑定 I2C 的 SCL），串扰耦合出边沿。

**定位手段**：给该中断加 **1 秒窗口速率计数**，把"风暴"变成 `N/s` 的数字再判断——
这是这类问题最划算的诊断投入。

**防护方向**（三层，按代价从小到大）：

1. 触发引脚改上拉/下拉（消除浮空，最直接的根因修复）。
2. 在 ISR 内加最小间隔去抖（丢弃过密边沿），并保证 ISR 内不再重新武装到同一条件。
3. 给该中断加速率看门狗：超阈值时屏蔽（`IMR` 清位）并上报，避免拖死整条总线。

## 3. I2C 总线锁死恢复

要点：HAL 超时后从机仍拉住 SDA、外设锁在 BUSY；**不恢复则一次失败变永久失败**。

判据（`SDA 低` / 外设 `BUSY` / `AF-ARLO-BERR` 错误标志，**任一**成立才动手）：

1. 关外设，引脚切为 GPIO 推挽；
2. 时钟脚手动翻转 **≥9 次**，把被从机拉住的 SDA 释放出来；
3. 产生一个 STOP 条件（SDA 在 SCL 高时上升）；
4. `HAL_I2C_DeInit()` + `HAL_I2C_Init()` 清除锁存标志；
5. 引脚还原为 AF 开漏；
6. 调用方：恢复失败要能上抛并限频重试，避免在每帧都恢复导致阻塞。

## 4. 无相机 / 无示波器的量化验证（bit-bang 外设）

GPIO 软件 SPI / 自研 bit-bang 外设"看不到波形"时，用**计数器 + 增量**替代示波器：

```c
/* 非 static，否则 nm 看不到符号；volatile 防被优化掉 */
volatile uint32_t g_xfer_bytes, g_cmd_bytes, g_data_bytes;
```

判据：

- `xfer == cmd + data` **严格相等**（允许 ≤1 的差，因为 halt 可能停在两个自增之间）。
- **必须采两次看增量**：`Δdata % 1024 == 0` → 每帧 8 页 × 128 字节整帧发完。
  只看绝对值会被"halt 停在半帧中间"误判成"刷新被截断"。
- `Δcmd == 24 × Δ帧数`（每页 3 条寻址命令：页地址 + 列低 + 列高）。
- `初始化开销 = cmd − 24×帧数` 应为常量，且**要与 `Init()` 里逐条数出来的命令数相等**
  （实测数出 28、实测 28 → 逐条命令都真的发出去了）。
- **交叉验证（很划算）**：末次写数据结束时数据脚停在最后一位，所以输出寄存器
  `GPIOx->ODR` 的该位应 == `Buffer[last] & 1`；又若初始化时把时钟脚置低、事后读回高，
  则**反向证明 bit-bang 确实执行过**。

同类可复用套路：把"物理量是否合理"作为判据而不是"有没有报错"——
读目标 RAM 里的采样结构，检查 `ok` 标志、`samples>0`、`errors==0`、量纲合理
（如静止时加速度模长应落在 0.5–1.5 g）；若某器件 ID 寄存器读回全 0，
说明该模块**未装配**（硬件事实，非故障），**绝不允许把 0 值当成功上报**。
