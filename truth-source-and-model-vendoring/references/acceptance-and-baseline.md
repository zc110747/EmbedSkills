# 冻结基线、互证与验收

## 一、真值必须**冻结**，判据是**语义核心哈希**

用整文件哈希会把"改外观"也拦下（改个注释、调个几何描述就红），于是人会习惯性
`--update` 把红抹掉 —— 冻结就此失效。

**做法**：把真值文件拆成「**语义核心字段**（进哈希）」与「**外观字段**（不进哈希）」两类。

```json
// core/baseline/baseline-kinematics-physics.json
{
  "files": {
    "packages/<pkg>/model/robot.yaml": {
      "sha256": "...",                  // 整文件：仅作记录
      "core_sha256": "...",             // ★ 判据（只含 lengths/limits/coupling/actuators 标定）
      "frozen_fields": { "links": ["id","parent","length"], "joints": ["...","limit","coupling"] }
    }
  }
}
```

语义分工（按此划分，字段名按真值源登记）：

| 改动类型 | 结果 |
|---|---|
| 外观几何 / details / 注释 | ✅ 放行 |
| `length` / 轴限位 / 耦合关系 / `actuators` 标定 | ❌ 报错并**逐字段列差异** |
| `gravity` / `contact` / `timestep` / `servo` / `inertia` | ❌ 报错 |

三条配套纪律：

1. **有意改后**：`freeze_baseline.py --update` **且**重跑生成器（URDF/MJCF 是产物，
   另有 `test_generated_*_is_in_sync_with_config` 盯同步）。
2. ★ **基线里的键 = 真值文件的仓库相对路径** ⇒ **目录搬迁时键必然变**，但
   `--update` 后**语义核心哈希必须逐位不变**。这是判断"只挪了位置、一个字节没动"的唯一硬证据。
3. `--check` 类工具**只读**。它红了**只说明"今天的实现与冻结时不一致"**，唯一正确处置是
   **查清差异**，不是 `--update` 抹掉。把这句话写进文档。

## 二、"黄金数据"与真值**分别**冻结

真值冻结管"输入"，黄金数据管"**输出**"。两者都要，因为**实现可能改坏而真值没动**。

**做法**：把实现的实际输出（FK 位姿、IK 解、工作空间采样）序列化，
生成器带 `--check` **逐位复现**。

```
packages/<pkg>/tests/cases/{joint,fk,ik,workspace}_cases.json
packages/<pkg>/tools/gen_<pkg>_baseline.py            # 生成
packages/<pkg>/tools/gen_<pkg>_baseline.py --check    # 逐位比对（CI 跑这个）
```

★ **改运动学 / 物理后必须重跑生成器**，否则回归必红 —— 但红了要**先看是真改坏了还是改对了**。

## 三、三条实现**互证**，不是自证

单一实现"自己算出来自己验"没有意义（尤其 IK：残差是它自己的 FK 算的，必然很小）。
**至少两条独立实现互相对账**，并把残差**冻结**成预期值。

```
前端渲染层（TS）  ↔  参考实现（Python）  ↔  物理引擎（MuJoCo）
```

- 黄金值必须取自**独立来源**：例如 `mj_forward()` 读目标 site，而不是复用参考实现的输出。
- ★ **容差按机构登记，且必须写明理由；未登记一律报错，不给缺省值。**

| 机构 | 容差量级 | 理由（示例形态） |
|---|---|---|
| `<pkg-id>` | `1e-6 mm` | 两侧是同一份浮点推导，实测残差留足量级余量 |
| `<pkg-id-2>` | `5e-2 mm` | 官方 URDF 把 `<origin rpy>` 截断到 6 位有效数字，两份官方文件自身就有 µm 级系统差 |

理由：悄悄给个"够大"的缺省，等于把"新增机构时没人想过它的精度来源"藏起来 ——
而那正是**为了让它通过而放宽阈值**的开端。

★ **能力缺失要"声明为不存在"，不是"跑不出来"**：若某台机构没有 IK，
就让它的能力声明指出无解析解并返回 `success:false` —— **绝不**套用别的机构的解算器。
最危险的一类失败正是：把**平面 2R 的解析解**套到**6 铰链**机构上跑，
**它成功返回了**（`success:true`、残差很小、界面一切正常），因为残差是它自己的 FK 自证的。
⇒ 能力门必须落在**调用点**上，能力声明不满足时**一次都不调用求解器**。

## 四、多机构下的**统一验收框架**（别写两套判据）

第二台机构接完后最容易犯的错：**照抄一份验收**。两套标准各自都能自己绿，
"用同一套判据"就只是说法。

### 入口只有一个

```python
run_sim2sim(robot_id)          # 判据（用例枚举 / 三侧面比对 / 能力门）只有一份
sim2sim_matrix()               # 回归矩阵 = 选择器声明的**全部**机构
```

`--freeze` 把结果落盘成 `tests/baseline/<robot>/sim2sim.json`；
前端与参考实现**读同一批文件**（否则"一致"会被拆成两套互不相干的标准）。

### ★ 能力门必须落在**真正下发命令的那一层**

引擎接口返回 `NOT_IMPLEMENTED` **不够** —— 只要有一条代码路径绕过引擎去调**底层求解器**，
它就会**成功返回**一组无意义的关节角（残差还会因为用自己的 FK 自证而看起来很小）。

```ts
// 在 store / controller 这一层就要挡
const solverKind = loadRobot(activeId).kinematics.capability.solverKind;
if (solverKind !== 'analytic') return { success: false, reason: 'NO_SOLVER', … };
```

并且 **`NO_SOLVER` 必须与"不可达"分开表达**（`OUT_OF_WORKSPACE` / `JOINT_LIMIT`）：
后两者是"试过、不行"，前者是"**没算**"。合并会让用户以为要调目标点。
拒绝时仍要写下目标点 + 状态，让界面能说清"我想去哪"和"为什么没动"。

**判据取自能力声明（数据），不是 `if robotId === …`（逻辑）** —— 将来加了数值 IK，
只需要改它自己的 capability 声明。

### ★ 交叉一致性：两批**独立采集**的产物必须互相对照

抽出统一框架时唯一的风险点，是"顺手改掉基准模型的期望值"（新框架自己算一遍当然自洽）。
解法：让**新框架的快照**与**旧的黄金基线**在**同名用例**上互相比对：

```python
for case in report.fk_cases:
    ref = golden_by_id.get(case.id)     # 由另一个工具采集
    if ref: assert_allclose(case.tcp_frontend, ref["tcpFrontend"], atol=1e-9)
```

### 报告里不允许出现"没测过的东西"

没有 IK 的机构 ⇒ 报告里**没有**对应的用例字段，快照里也没有，
并用一条测试盯着（`test_no_robot_fabricates_ik`）。**空白 ≠ 零**：
用 `null` 表达"没有误差可言"，绝不用 `0`。

### 日志告警要**分对象**

"参数化物理仿真的质量 / 惯量为估算值"这句话对**自有模型**成立，
对**官方模型**（真值在官方 MJCF）就是**错的**。把错的告警留在日志里比没有告警更糟 ——
读日志的人会以为官方模型也被"估"过。⇒ 按 `physics_kind` 分支打印。

## 五、验收清单（照抄改路径即可）

```bash
# ── 静态 + 单元 ──
tsc -b --force                    # 0 error
vitest run                        # 全绿（★ 含包内测试）
vite build                        # 产物 .js 中禁止出现的字符串命中 0（.js.map 必含，不算）
# ── 参考实现（★ 必须在**仓库根**执行）──
python -m pytest -q               # 走 testpaths：core/tests + tests + packages
# ── 一致性 / 互证 ──
python core/tools/run_sim2sim.py --all                # 统一矩阵（全部机构）
python core/tools/freeze_baseline.py                  # 真值 ↔ 冻结基线
python packages/<id>/tools/gen_*_baseline.py --check  # 黄金数据逐位复现
python core/python/<pkg>/cli.py validate --all        # 选择器 / manifest / 真值 / 包目录 四方对账
# ── 端到端 ──
node tests/e2e/ui-smoke.mjs       # ★ 必须隔离端口
```

**四条执行纪律**：

1. ★ **`pytest` 只在仓库根成立**：从子目录跑会输出 **`no tests collected` 且 exit 0**，
   只看退出码的脚本会读成"通过"。跑之前先确认 cwd。
   另外 `testpaths` 相对 **rootdir** 解析 ⇒ **不要给 pytest 传目录参数**（传了就绕过 testpaths）。
2. ★ **e2e 必须隔离端口**：默认端口可能是用户正在驱动真机的实例，**不能杀**。
3. ★ **后台进程与验收必须在同一次调用内**：`(cmd &)` 起的进程只活到本次调用结束。
4. ★ **禁止把 `--update` 当成"让测试变绿"的手段**。

## 六、真机验收：两条独立证据链，不能混着读

| 证据 | 证明什么 | 不证明什么 |
|---|---|---|
| 链路层：握手标识 / 命令回执 / 状态回推 | 指令**送到固件并被接受** | ❌ **物理到位** |
| 相机：实测位姿 | 物理**真的动了 / 到位了** | — |

★ 真机**无位置反馈**时状态回推是**开环目标值** —— 链路全绿 ≠ 到了位。
要物理证据只能靠相机，且要先做台面标定（分割板 + 锁曝光）。
**这一条最容易自欺，务必在文档里显式声明。**

## 七、常见认知误区

| 误区 | 实情 |
|---|---|
| "改的是外观，冻结不会拦" | 若外观字段被误放进语义核心，**会拦** ⇒ 冻结的**字段划分**要评审 |
| "测试全绿 = 覆盖到了" | 路径 / 测试配置写错会让包内测试**一条不跑**而全绿 ⇒ 数**收集数** |
| "IK 残差很小 = 解对了" | 残差若是自己的 FK 算的，就是**自证** ⇒ 必须独立实现互证 |
| "同一个模型的两份官方描述等价" | URDF 与 MJCF **经常不一致** ⇒ 逐位对 |
| "文档里说清楚就行" | 只有**会失败的检查**才算约束 ⇒ 每条纪律配一条**能红**的守卫，并**反向验证它会红** |
| "记在脑子里 / 注释里" | 用全仓 **grep 建立"漏改的读者"清单**，不能靠记忆 |
