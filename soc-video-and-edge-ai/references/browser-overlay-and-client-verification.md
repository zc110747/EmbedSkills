# 浏览器叠加层（overlay / HUD）与前端验收

端侧 AI 的结果最终要在浏览器里"看得见"。这一份记录叠加层最容易出的几类**静默**故障，
以及在没有浏览器的环境里能把验收做到哪一层。

## 1. 骨架 / 边界点要按"点数"选拓扑

- 硬编码 `keypoints.length === N` 是这类 bug 的固定形态：新模型的点数不同 → 条件恒假 →
  **有框、没有骨架**，而且不报任何错。排查时先怀疑这个条件，而不是模型。
- 把拓扑做成**数据** + `skeletonFor(count)`；**未知点数返回 `null`、什么都不画**。
  不要"尽力而为"地把连接表套到更短的数组上 —— 那会画出几条孤立连线，看起来像跟踪错误，
  把排查引到错误的层。
- 点数相同但**语义不同**时（例如 3 元组一个是 `[x,y,conf]`、一个是 `[x,y,z]`）也要区分来源。
- 连线表必须与生产端**同一份索引约定**，并在两边都写明"改一处必须改另一处"。
- 常见拓扑坑：拇指链从**腕**起，不是从食指 MCP 起。从后者起会有可见折角，像跟踪误差。

## 2. 同一份数据只能画一次

- 生产端常把同一结果放进两个字段（专用块 + 通用对象数组）。
- 两处都画 → 叠成双层：**像素级重合时完全看不出来**，一旦哪天只改了一处才爆，
  症状像"检测到两个目标"。
- 修法：指定一个权威来源，另一处跳过；**并写一条断言把两者的同源关系钉住**（逐点比对，给容差）。

## 3. 协议里"消费者不得使用"的标志位，UI 也必须门控

- 典型：参考点未锁定时 `delta` 是相对**零原点**的差值，**数值上等于绝对位置**。
  直接显示 = 操作者看到"目标一进画面就飞了一大段"，然后归因到跟踪算法。
- 正确做法：显示为不可用（`—`）**并给出状态文案**（`REF LATCHING` → `REF LOCKED`），
  让操作者知道这是等待而不是故障。
- 空态要显式：未检出时显示 `NO HAND`（或等价文案）。否则"目标不在画面里"与"前端坏了"长得一样。
- 增量字段（如逐轴运动的枚举）遇到未知取值要降级成 `?`，**绝不能把 `undefined` 拼进字符串**。

## 4. 坐标越界不要 clamp

- 生产端常常只 clamp bbox、**不 clamp 关键点**。贴边目标的关键点合法地落在画面外。
- 前端照实画、让画布裁掉，是**真实信息**；拉回画面内会画出与目标不符的骨架，
  然后被算到算法头上。
- 但要能分辨是哪种：判据是"多个轴**一起**越界吗"。只有一个轴越界且紧贴某条边 ⇒
  目标本来就在框外，不是映射错误。

## 5. 把绘制逻辑搬出组件，它才可能被验证

- 绘制函数（纯 2D context 调用，不含组件框架、不查 DOM）单独成模块。
  这样可以在 Node 里用**记录型 context** 断言"画了几条线、坐标是多少、有没有被 clamp"，
  而且测的是发布的那份代码，不是复刻品。
- HUD 用 **HTML 层**而不是画布文字：省掉 devicePixelRatio / `measureText` 那套，
  缩放时清晰，并且能在 Node 里 SSR 渲染做断言。

## 6. 无浏览器验收的三层与边界

| 层 | 能测 | 手段 |
|---|---|---|
| 逻辑 | 拓扑、派生字符串、契约 | 打包器打包**工程自己的模块** + 活 payload |
| 几何 | 画布调用参数与条数 | 记录型 context |
| 组件 markup | 字段是否真的渲染出来、空态 | SSR（React: `react-dom/server`；Vue: Vite `ssrLoadModule` + `@vue/server-renderer`） |
| 实际像素 / 长连接 / 轮询 / 模式切换 | ❌ | 必须真浏览器 |

- 判据**不是**"没抛异常"：扫产物里有没有 `undefined` / `NaN` / `[object Object]`，
  **并且必须有正样本** —— 从活 payload 现取的字符串必须出现在产物里。
  否则"什么都没渲染"也能全绿。
- **正样本要挑有区分度的值**：验证标签是否真的绑定时别选 `UNKNOWN` ——
  字段没绑定也正好显示 `UNKNOWN`，会蒙混过关。
- 空态单独渲一遍：每个视图常有一个 `if (!data) return` 的提前返回，
  那里漏个判空就是白屏，而使用者对白屏的唯一解读是"前端坏了"。
- payload 从活服务现取，**不要手写 fixture**：手写的是"我以为的形状"。
- 交付时**列出未覆盖的层**，不要让一个绿勾假装全都测过了。

## 7. 前端脚本的类型检查盲区

- `tsc` 不读 `.vue` / `.svelte`，打包器只**转译**、不做未定义标识符检查 ⇒
  **删了 import 却留下引用，构建全绿、运行时白屏**（真实发生过，且只在浏览器里可见）。
- 可自建检查：抽出每个 SFC 的 `<script setup>` 正文，前面补上编译器宏声明
  （`defineProps` / `defineEmits` / `withDefaults` / `defineExpose` / `defineModel` …），
  交给 `tsc`，再把报错行号**减去前缀行数**映射回原文件。
- 临时产物目录**必须放在前端工程内**：模块解析是从引用文件向上找 `node_modules`；
  放到系统临时目录会让每个 import 塌成 `any`，真正的错误被级联噪音淹没。
- 组件间的 `.vue` import 需要工程里的 `declare module '*.vue'` 一起纳入 include。

## 8. 编译期嵌入的前端：只构建前端不够

- 前端产物被编译期打进二进制（`go:embed`、静态嵌入、单文件打包）时，
  **只跑前端构建不会改变运行中的服务**。
- 启动/构建脚本的"是否需要重建"判断若只看"源码 vs 前端产物"，会漏掉
  "**前端产物比二进制新**"这一种 ⇒ 静默起旧 UI，改动看起来"什么都没发生"。
- 判据：用产物里**唯一的名字**（带哈希的资源名）去二进制里搜，确认嵌的是当前这份。

## 9. 验证用的"真机数据"优先从录制库取

- 结果录制器是 append-only、且原字节保真时，库里**已经有真机数据**。
- **先查录制库，再决定要不要人配合。** 人配合只留给"只有人能做到"的事
  （例如画面里真的出现一只手）。这条能把"必须有人在场"的验收变成无人值守。

## 10. 真实浏览器里的像素才是最终判据（overlay 验收的第四层）

前三层（录制库数据 / 记录型 2D context / SSR 组件）都答不了"骨架有没有画在那只手上"。
第四层必须真浏览器，而且**只断言"画了像素"不够** —— 画在角落也会通过。

- **比对对象**：`getImageData` 读回 overlay 画布 → 把 painted bbox 按
  `video_width / canvas_width` 映射回**原始视频坐标** → 与同一帧的 landmark
  比**质心距离**与**包围盒重叠**。
- **钉帧**：断言要读"绘制那一刻的帧"，不是"断言那一刻的手"。操作者一觉得跑完
  就会放下手臂，读实时会把结论变成 SKIP 并掩盖结果。
- **union 陷阱**：画布上的像素是 **bbox 矩形 + 类别标签 + 骨架**的并集。本项目中
  agent 给的**手部 bbox 是满画面高**（实测 `[350,0,749,720]`，而 landmark 只占
  y 186..697），矩形自己就画出两条贯穿全高的竖线。所以质心/重叠检查是 union 检查，
  **"骨架只画一次 / 画在手上"必须另找证据**（记录型 context + 截图），并在脚本里
  写明，否则下一个人会把 union 结论当成骨架结论。
- **越界的量级要实测再下结论**：本项目 landmark 刻意不 clamp，但归档 1521 帧 /
  31941 坐标实测最远只越出底边 72px —— "不 clamp" ≠ "点会飞到天外"，用数据说话。
- **驱动方式的选择**：浏览器 CLI 若是 `.cmd` 垫片，从 Python 子进程里引导守护进程
  在某些宿主上会被整条杀掉且无输出。稳妥分工是 **shell 驱动浏览器、脚本只做断言**，
  用环境变量把 DOM 快照与帧交给断言步骤。
- **浏览器会话要快进快出**：守护进程在长时间空转后会被回收，之后的 CLI 调用全部
  失败（典型报 "Chrome not found"）。顺序应是"先等目标出现，再开浏览器"。
