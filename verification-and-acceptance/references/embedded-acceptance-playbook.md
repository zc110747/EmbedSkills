# 嵌入式端到端验收（完整判据原文 · 由 embedded-verification-acceptance 并入）

代码"生成"只是第一步，**跑通验证闭环**才是迭代基础。

## 何时用

- 交付/验收任何一个嵌入式子模块：固件、上位机服务、视频链路。
- 写自测 / 回归脚本，定义"通过"的标准。
- 一键脚本跑不起来、真机现象与代码对不上时做故障定位。

## 核心知识点

| 环节 | 判据 |
|---|---|
| 构建 | Debug + Release **双构零警告**；显式给出 FLASH / RAM 的字节数与占比 |
| 烧录 | OpenOCD 烧 **`.elf`**（`.bin` 会报 `no flash bank found` + `wrote 0 bytes`），看到 `Verified OK`；改完代码必须先重烧再抓串口，只 `reset` 会看到旧固件行为 |
| 真机 | 串口启动日志 + 心跳；网络用 `ping` 全尺寸扫、`curl` 特征串、`arp -a` 核对 MAC 防假通 |
| 脚本 | 输出 **pass/fail 计数**与退出码，而非人肉看日志；不依赖硬件也能跑的纯逻辑单测优先 |
| 交付 | 每模块完成即增量汇报，✅ 清单收尾 |

- **「没报错 ≠ 有数据」**：调用返回 0、日志被限流都不算证据。取符号地址后直读内存比对预期值才是正向验证。
- **`mdw` 只能 4 字节对齐整字读**，非对齐地址报 `Failed to read memory`（sysprogs 版 OpenOCD 会打印 `0x…: ERROR 0` **且不报错退出**，症状是"读回少几个字段"，与"探针连不上"完全不同）⇒ 读窄变量先按 `off & ~3` **对齐到整字并去重**，再按 lane 切字节。另注意 `mdw` 打印的地址是**小写**十六进制 —— 用大写格式（`%08X`）去匹配它的多行输出会**静默匹配不到**（返回一堆 `None`、不抛异常），所以解析正则要 `IGNORECASE`，且"解析失败"必须与"会话失败"分开报，否则格式不匹配会被误诊成探针故障。
- 任何"性能异常"先做**双路径对照**（绕过外设 vs 经过外设）：两者共有的开销一定在主机侧。
- 长运行 / 网络项目：压测前后 CFSR / HFSR = 0，连续请求无失败，周期量 `*_valid` 恒定不冻结。
- 双固件（Bootloader + App）分三层验收：跳转 Golden path、升级路径、引擎级函数直调；重点确认**坏包在擦写前 abort、不破坏在跑的 App**。

## 判据与反模式

- 脚本报 FAIL，**先怀疑前提没成立**，再怀疑产品代码（四类自造 FAIL 见 references）。
- **否定性结论一律先查工具的观测能力**："我没观测到" ≠ "它没发生"。
- 一条断言只证一件事；别把"后来的合理变化"断言成"没收敛"。
- **多区域读取必须同一次 halt 内完成**：连续两次 `dump()` 是两次独立调试会话，之间固件**自由运行** ⇒ 拿到的是不同时刻的快照（本项目实测同一变量在两份快照里差 2379 counts）。一次 `init/halt` 内连续 `dump_image`。
- **运行态比对 = 结构严格 + 数值宽容 + 形状校验**：周期性变化的字段（占空比 / 累计计数 / 实时示数）要从逐字节比对里排除，但**不能整段忽略** —— 按期望值的正确格式生成正则做形状校验（值可抖、格式必须成立）。停机态仍走严格逐像素。
- **异步命令的收尾动作必须读回确认**：串口 / shell 命令由主循环异步解析，一轮里可能含阻塞式刷屏（本项目 OLED 约 250 ms/帧）。注入 `stop` 后要等足**并读回状态变量**确认生效（带重试），否则设备会带着执行器转到下一次验收 —— 这比误报更严重。
- **断言"唯一真值源"时注意派生显示量**：派生量是截断 / 取整来的，`pct == permille // 10` 成立，反向 `permille == pct * 10` 只在开环或整值时成立。
- **常量求值器要兼容派生宏与 C 强制转换**：需剥 `(int32_t)` 与 `100L` 后缀；**函数式宏不展开** ⇒ 供脚本读取的表达式要**把乘法展开写**，并加 `#if` 断言两条式子同值。
- **用例的边界值必须从真值源推导，禁止写死**：写死的 `speed 4.1`（本意"超上限"）在量程由 4.0 改到 4.5 后**反而合法** ⇒ 用例静默变成另一件事、照样 PASS。命令文本与期望值都现算；要"特殊点"（如真值为半整数）用**代码搜索**，找不到就报错退出 —— 宁可红，也不要退化成恒真断言。**同样适用于脚本自己的默认参数**：某门槛扫描脚本把区间写死成 `17..25`，而被测真值涨到 `27` 后区间内一档都命中不了 ⇒ 判据报"没找着门槛"，看着像被拉黑了。对策：默认区间/默认档位**锚到真值源**（如 `HI = STARTUP_PWM_PCT`、`LO = HI - 10`），且**解析不到真值源时明确报错退出、不回落成硬编码**（回落等于把坑埋回去）。
- **FAIL 提示要按被测状态分化**：停机态判据遇到"板子正在运行"，应提示换运行态脚本或先停机，而不是指去查固件 / ELF 一致性 —— 指错方向会让人往错处查很久（本项目真误判过一次）。
- **时域行为（抖不抖 / 稳不稳）要采时间序列，且采样必须在同一次调试会话内多轮 `halt→dump→resume`**：静态逐像素比对永远看不出抖动。每轮起一个新会话（~0.5 s 开销）会把采样间隔抬到秒级，让"窗口锁存"判据退化成恒绿；间隔远小于窗口时，"相邻两点取值一字不变"才是锁存的直接证据。固件里只在窗口方案下存在的累加器（如 `s_disp_cnt`）其推进过程本身就是结构证据（细则见 references §7.6）。
- **比"一次调试会话"还短的瞬态窗口（百 ms 级）：单点采样＝抽签，要采一排点 + 形状判据**。上一条讲的是"同一次会话内多轮 `halt→dump→resume`"；当窗口只有 ~200 ms 而**起一次会话本身就要 0.3~0.6 s** 时，单点采样落不落在窗口里纯看运气 —— 采样时刻稍晚就直接读到稳态、判据退化成恒绿。对策：① **一个会话内采一排点** —— 会话打开后先注入被测命令，再用"短睡 → `halt` → 读数 → `resume`"连续采 N 次，把序列连同 `t_ms` 一起带回；② 判据从"逐点等值"降级为**形状判据**，只断言"序列里**存在**某点满足 A""**峰值**满足 B""**末点**满足 C"，且每一条都对应一个可证伪的机制（存在相位=补偿态的点 ⇒ 补偿真发生过；峰值 > 设定值 ⇒ 确认阶段的目标确实是补偿值；末点 == 设定值 ⇒ 真切回来了，不是停在补偿值）。⚠️ 序列里"相位已翻转、目标尚未更新"的那一点**不是噪声**，是沿判据坑的直接证据，别当抖动滤掉。
- **警惕"退化相等"型假判据**：`平滑极差 <= 原始极差` 在平滑**完全没生效**（两个量就是同一个数）时极差相等、照样成立 ⇒ 永远绿。比较两个统计量前先自问"功能彻底失效的话，这条还成立吗？"——成立就不是判据。对策：留**相对余量**（如 `<= 0.75 ×`）；基准量本身太小时报「判据不适用」而**不要给 PASS**。
- **判据的"前提"必须由脚本自己钉死，别信设备残留状态**：只在参数显式给出时才下发配置的写法，会让脚本跑在**上一次异常退出残留的工况**上 —— 脚本头按默认值打印档位/窗口/预热时长，判据却按另一档的实际数据在算（本项目：板上残留设定速度 20.0，脚本按默认 10.0 打印，于是"窗口平均"看起来像失效了，报出 `disp 极差 178 / act 极差 30` 的假 FAIL）。对策：**无条件显式下发**本次用例所需的全部前提（配置值、工作模式），把"我以为的初始状态"变成"我刚设过的状态"；脚本异常退出要在 `finally` 里恢复现场。
- **阈值类判据要取「连续段下界」，并把「随机带」与「配置值失守」分开判**：物理阈值（起动力矩门槛 / 摩擦门槛 / 触发点）在阈值附近常常是**随机**的（取决于停位、温度、供压），实测会出现"最低档偶尔成、中间档全败、高档全成"。此时取 `min(通过的档)` 会锚到一个"偶尔成了"的点，与配置值一比给出**假安全感**（报裕量 10%，真实只有 6%）。对策：① 门槛取**自最高端向下连续通过**那段区间的下界（纯函数，便于离线自检）；② 判红条件写成"**配置值是否落在连续通过区间内**"而不是"结果是否单调"—— 随机带完全位于配置值**之下**时只报 INFO（那是机械属性，不是产品缺陷；把它算成缺陷会推着人去改根本没坏的代码，比漏报更伤人）；③ **阈值不是常量**：裕量只测一次就会过期（实测同一个量一天之内 `27%→28%`），"门槛 +N"这类经验裕量必须连同**重测命令与触发条件**写进被测源码注释，否则下一个人会照着过期数字继续贴着门槛配置。
- **比较统计量前先验证"适用区间"，不适用就报「前置不成立」而不是 PASS/FAIL**：均值/方差/极差这类判据只在信号**处于稳态**时才有意义 —— 信号还在单调爬升时，平滑量是**滞后**的，它的极差可以**反超**瞬时量的极差（本项目：`act` 仍在缓升时 `disp 极差 178 > act 极差 30`）。对策：三件套 —— ① 丢掉含爬升/预置过渡的**前段**（首个窗口）；② 量化"是否已稳态"（如**趋势占比** = `|后半均值 − 前半均值| / 全段极差`，纯爬升 ≈ 0.5、围绕均值抖动 ≈ 0，阈值取 0.40）；③ 前置不成立时**明确输出"不适用"并给出补救动作**（提示加大预热参数），既不冒充 PASS 也不误导去查固件。
- **判据要抽成「纯函数」给离线自检共用，否则自检验证的是抄本**：离线自检（不连板的 `--selftest`）是反向验证判据的主力，但如果它**另抄一份**"我以为的判据"，那改真判据时自检照样绿 —— 与上面"编译期断言脱钩"**同源**。对策：把判据逻辑提成不碰硬件的纯函数（输入 = 序列/状态，输出 = `(verdict, 标题, 详情)`，`verdict` 区分 `pass/fail/skip_*`），真机路径与自检路径**调用同一个函数**；自检用例成对构造：**该拦的拦得住**（功能完全失效必须 FAIL）+ **门槛不许放行**（同样量级但处于稳态的输入不得被判成 `skip`）、+ **该放行的放行**。
- 回归守卫必须**在旧代码上真的失败过**；只用新符号的测试在旧代码上只会收集期 `ImportError`。
- 写进文档的每个数字都要重复测到稳定；参数差一个就是另一个数。
- **验收脚本自己的退出码语义必须自测**：Python 里 `sys.exit(True)` 的退出码是 **1**、`sys.exit(False)` 是 **0** —— 把"被复用脚本 `main()` 的布尔返回值"直接交给 `sys.exit`，就得到 **PASS 报 1、FAIL 报 0** 的倒置（本项目 `verify_ui_running.py` 真踩过：真机内容全 PASS、退出码却是 1）。统一显式映射 `return 0 if ok else 1`，并把 `inject` / 被复用脚本的 `main()` / 收尾函数**全部打桩**，穷举"比对成败 × 收尾成败"四种组合钉死映射（配方见 references）。
- **物理输入可以完全无硬件仿真**：按键/拨码/组合键只要最终落到某个 RAM 状态变量，就能用 SWD 直接写它 —— 但**必须先读扫描器实现**确认"写进去会不会被刷回去"（去抖计数饱和后往往就长期生效，写一次即可），且**注入前读回确认前提成立**，否则判据在错误前提下"通过"或把"被刷回去"误读成"固件没响应"。组合键还要**在边界测它与单键功能的冲突**（非边界处增量相互抵消，会把冲突掩盖）。索引从 ELF 枚举取、步长用 `sizeof`。详见 references §7.7。
- **物理输入仿真"长期生效"是有条件的**：只要引脚电平真的变过一次，注入的按下态会被**静默抹掉**。上一条说的"去抖计数饱和后写一次即可"成立，是因为扫描器**只有**在 `计数 < 去抖阈值` 时才走进"改写稳定态"的分支；一旦有人**手指碰到按键 / 接触抖动 / 排线松动**，`原始电平 != 上次原始电平` ⇒ 计数器清零 ⇒ 重新饱和时 `稳定态 != 原始电平` ⇒ **稳定态被改写回引脚真实电平**，注入当场作废（固件侧完全无痕迹，而且**真人按键不受影响** —— 他按下去电平就稳定了，所以这不是固件缺陷、别去改固件）。症状是**整条用例零变化**，而报告会写成"分流/分支没生效"之类指向固件的结论 —— 这类假 FAIL 最贵（本项目为此误诊过一轮）。**对策（目标侧见证）**：若固件已有"已按住时长"这类每拍累加、松手清零的计数器，就**在同一个会话内、松开之前**读它 —— 被抹掉时它从 0 重新累加，与期望时长**差一个数量级**；正常时 ≈ 期望值（实测误差 ≤ 1 拍，容差取 100 ms 即可）。不达标 ⇒ `[WARN]` + **重测一次**；连续两次不达标 ⇒ 以"**测试前提不成立、本条不是固件缺陷**"退出（不要产出判据）。**开跑前再加一道静止门**：读「原始电平 / 稳定态 / 已按住时长」三者，任一非零即拒绝开跑并提示"请松手"—— ⚠️ "去抖计数已饱和"**不能**用来判"此刻没人按键"（一次触碰后 20 ms 内它又饱和了，对"手指正按着"完全免疫）。跨会话拼出来的按住（`按下 → host sleep → 读状态 → 松开`）无法在会话内取见证，只能在**松开之前**单独量一次。
- **「按住 N 毫秒」只能单会话目标侧计时**：`按下 → host sleep → 松开` 拼不出时长 —— 每次注入是一次独立调试会话（0.3~0.6 s），期间目标自由运行 ⇒ 误差与连发延迟（600 ms 级）同量级。计时必须搬进**目标时基**：一次会话内 `mww(按下) → resume → 目标跑 N ms → halt → mww(松开)`。长按增量按**绝对时间轴**派生（`1+(held−delay)/period` 步），别数拍子（主循环被阻塞式采样拉长会丢拍）；两种步长并存时判据直接建模**总增量**，别建第二本步数账。详见 references §7.8。
- **可写的"基准/零点"能反向合成传感器输入**（无压力源验阈值逻辑）：被测值多为 `(raw − baseline) × per`，`raw` 读不出但 `baseline` 写得进 ⇒ 写基准就能把被测值合成到任意值。三条纪律：① **必须闭环逼近**（"写→读"间隔 0.6~0.9 s，实测漂移 ≈620 码/s ≈ 8.4 单位/s，开环一次写会带着 5~7 个单位的误差落错侧）；② **修正量含自学习偏置**，否则"滞后 × 漂移"这个不动点会让迭代永远差一个常数；③ **"输入确实落在预期侧"须是独立前置判据**，验回差带的用例容忍必须收紧到小于半个回差带、且**两侧都测**（两侧结论相反才是真判据）。窄变量未对齐要先对齐整字读再取 lane。详见 references §7.9。
- **编译期断言同样会「判据脱钩」，而且更难发现**（它平时总是"通过"的）：用 `typedef char x[cond ? 1 : -1]` 做等宽 / 尺寸断言时，若 `cond` 里写的是**另抄一份字面量**（`sizeof("SPDR:~20.0")`）而不是**被测宏本身**，那么**改宏时断言照样成立**、等于不存在。实测（4 个构造缺陷 + 1 个正向对照）：只有"改栏位宽常量"被硬编码断言拦住，而"去掉预置前缀 `~`"、"去掉补位空格"这两个**真会画错**的改动**照常编过**。对策：让断言**从宏推导** —— 把格式符的占位长度折算成实际显示宽度（`显示宽度 = 串长 − len("%2u") − len("%u") + 整数列 + 小数列`），任何对宏的改动都立刻反映到断言上。**验证方式与运行期判据同款**：构造 3~4 个"应编不过"的缺陷 + 1 个"不该编不过"的正向对照，逐个跑构建看是不是真的红。
- **状态机类改动必须逐个「沿」验收，成对写用例**：新增"启动 / 停机时做某事"的分支时，最容易只测**启动（上升沿）**、漏掉**停机（下降沿）** —— 而停机路径往往**不改任何其他变量**（不改设定值、不换档），于是"只在 A 变化时清理"的写法**一路都不触发**，状态里残留上一次的值。危险点在于**屏幕可能仍然正确**（显示层往往还有一道 `running == 0` 判断兜着）⇒ 静态读代码完全自洽、肉眼也正常，只有读**状态字段**的验收脚本抓得住。对策：设计阶段把每个沿问一遍"这一步谁负责清理"；验收**成对**写（启动→预置 / 停机→回占位），并把"停机后状态应为……"立成独立判据。相关纪律：给函数**加参数**后立刻用 AST 核对"定义参数列表 == 各调用点实参个数"，别等到真机跑几十秒才 `TypeError`。
- **「相位翻转」那一拍返回的「本拍目标」仍是旧相位的值 ⇒ 沿判据的比较对象必须是「设定值」，不能是「本拍输出目标」**。典型形态：一个"补偿阶段 → 正常阶段"的两段式输出（先给补偿值带起来，确认转动后切回设定值），把"补偿结束"的判据写成 `输出 >= 本拍目标` —— 而相位翻转发生在**同一拍内**（状态机先按当时相位选目标、之后再翻转相位），于是这一拍拿到的目标还是**补偿值**，`补偿值 >= 补偿值` 恒真 ⇒ 窗口在转换拍就被关掉、输出**永久钉在补偿值**上。真机症状极具欺骗性：设定 25% 却一直输出 35%；把设定调到量程下限时输出比下限还高一档且**电机仍在转**（连"没转起来"的保护都测不出来，因为它被钉在一个能转的值上）。对策：关窗 / 退出条件**与设定值比**（`输出 == 设定值`），把"设定值"当独立变量贯穿判据；验收侧用**单会话时间序列**把这个边界打出来 —— 本项目实测点列里确实存在「相位已翻转、目标仍是补偿值」这一点，是这条坑的直接证据。
- 一键脚本自身 `exit 0` **不能**推断服务还活着（常驻进程可能已被回收）；验证必须在同一次调用内做完。
- **`argparse` 的 `help=` 文本里不能出现字面 `%`**：argparse 会对 help 再做一次 `%` 插值（`_expand_help` → `help_string % params`），裸 `%` 紧跟非格式字符直接抛 `ValueError: unsupported format character` ⇒ **`--help` 与"参数写错时的 usage 提示"两条路同时崩**（正常路径不受影响，所以能长期潜伏）。⚠️ 想靠 `%%` 转义也不行：若这行同时还有 `.py` 级的 `% DEFAULT_x` 格式化，`%%` 会**先被那层吃掉**、最终仍留一个裸 `%`（本项目 `verify_startup*.py` 就是这么埋了半年）。**对策**：措辞里别用 `%`（写"百分比"），并把"每个脚本跑一遍 `--help` 必须退出码 0"纳入回归。
- 「端口 / 地址」是**两端的**：绑定地址、白名单、就绪探测必须读同一个变量；改动后把端口真的移开跑一遍。
- 构建目录该清就清：`cmake --fresh` 或改用新目录名；动过 `GLOB` 源清单必须重跑 cmake 重新 GLOB。
