# 服务端入口分层纪律

适用面：给运动控制后端**新增入口/链路**（新协议、新传输、新网关、新外部客户端）。
客户端一侧（怎么让上游服务去连这个入口）见 `tcp-and-ws-link.md` 第一节。

## 0. 分层不变量：新入口只当 adapter

新增任何入口时，**它只能做"翻译"**：

| 可以做 | ❌ 不可以做 |
|---|---|
| 解析报文 → 调**同一个**控制器路径 | 绕过控制器直连设备 |
| 声明自己的**来源身份**（`origin`） | 自造第二份限位 / 尺寸 / 标定常数 |
| 把"读当前 → 算目标 → 下发"做成**原子操作** | 在这里实现 **IK / FK / 坐标变换 / 软限位** |
| 每连接独立 goroutine + `recover()`（崩溃隔离） | 非法输入返回 error 或 panic（应**返回结果**） |

★ 理由：命令必须与既有链路走**同一条**路，才能继承 **ACK 门控 / latest-wins / 限位校验** 的语义。
自造一份 = 造出"第二处真值"，它**不会报错**，只会在某天数值不一致。

★ **多客户端并发**：把"读当前 → 算目标 → 下发"（读改写）做成**原子操作**，
否则两条相对位移会互相踩踏。

★ **入口必须在协议里标注自己的身份**（第三来源 `external` 之类）——
否则对端 UI 会把它当"本页命令"，表现为**幽灵动、主臂不动**，更危险的是对端"指令侧"停在旧值，
下次操作把**整组旧指令**下发（真机跳回旧位姿）。详见 `origin-and-follow.md`。

## 1. 加新入口前先问三个问题

1. **目标端已有真值吗？** —— 外部客户端要建立"当前角"基准时，
   **正道是加一条只读查询**，而不是让它"先发一条无害命令去探"。
   ★ 只读查询**不碰**控制器状态机 / 设备 / 几何，是最小侵入的补基准方式。
2. **跨链路的参数语义等价吗？** —— 见 §2。**不等价就直接复用 = 两种模式行为相反且都"看起来正常"。**
3. **被拒时可观察吗？** —— 越界 / 超时 / 被门控挡下时，外部客户端必须能**看见原因**
   （错误码 + 当前值），否则它只能重试，把问题放大成"服务不稳定"。

## 2. ★★ 跨链路复用方向配置：必须先做语义换算

实录：串口链路的 `invert_*` 类配置里**含一层固件补偿**（固件对某些轴出厂反相、
某些轴按"原始值超过阈值即取负步长"处理）；而 TCP/仿真链路**没有固件层**
⇒ 直接复用会让两种模式**推杆方向正好相反**，且**两边都"看起来正常"**（各自内部一致）。

⇒ **通则**：
- 方向/单位/标定补偿类配置**跨链路复用前**，先确认**每一层**它被解释成什么；
- 换算必须**集中在一处**（单一入口函数），并在注释里写清**为什么取反**；
- 加一条**方向断言**（同一输入在两链路得到的舵机角增量同号），别只测"能连上"。

## 3. ★★ XYZ → 关节角：**禁止自证**

后端（或新入口）**不自带 FK/IK** ⇒ 想把笛卡尔目标变成关节角，只能走
**「冻结基线 + ≥3 条独立实现互证」**：一组基准点由**互相独立的实现**分别算，
两两差异必须落在**登记容差**内。**自己写的实现不能当自己的证据。**

- **容差按对象登记、必须写明理由、未登记一律 `raise`（不给缺省值）**：
  悄悄给一个"够大"的缺省 = 把"没人想过它的精度来源"藏起来，
  而那正是**放宽阈值以通过测试**的开端。
- ★ **"计数对齐" ≠ "结果正确"**（同源自研解析器误判）：一致性必须逐**值**比对，
  不能只比条数。
- ★ **新框架与旧黄金基线在同名用例上必须逐位相同** —— 否则"抽象"过程会把基准期望值**悄悄改掉**。

## 4. 链路不对称必须登记成"设计"

★ **同一串字节在不同链路上可以有不同语义与回执类型**，判据是**"它由谁发出"**：
某条命令在真机链路上只可能由上位机**翻译**产生 ⇒ 属**命令路径**；
在仿真链路上只会由调试/验收脚本发出 ⇒ 按**外部改动**对待。
另例：同一条状态查询在真机链路被翻译层合成一行关节级回执，在仿真链路却被判为"舵机级回执"。

⇒ **加跨链路断言时必须按链路分别写**，不能假定"同输入 ⇒ 同来源、同回执类型"；
**并把这处不对称写进文档登记成"设计"**，否则下一个人会把它当 bug 去"修"。

★ 另注意**命令接受面**的不对称：仿真端可能**只实现关节级命令**
（舵机级直控 / 摇杆命令一律返回未知命令错误）⇒ "想在仿真上模拟设备侧动作"时，
要么补对等实现，要么走一条**显式标注为"调试直通"**的通道
（该通道语义 = 有人把线直接接在设备上敲命令 ⇒ **不做限位校验、不参与 ACK 门控**，要写清楚）。

## 5. 配置真值的边界（多实现同源）

- **三端（前端 / 后端 / 脚本）各自解析同一份"选择器"**，禁止任一端自带副本。
- ★ **选择器只放"指针"**（id / name / 指向真值的路径），**尺寸、限位、标定、物理量、
  坐标偏移一律禁止** ⇒ 用**白名单 schema 断言**守，**不是靠自觉**。
- ★ **注册表 id ≠ 模型 id**：选择器的键与真值文件里的 `id` 常不同名
  ⇒ **不能用真值文件里的 `id` 反查注册表**。
- ★★ **同名关节会骗人**：两台机器人**都有** `gripper` 之类的键，但语义/范围不同
  ⇒ "键集合相等"**不是**模型一致的判据，**只有限位能兜住**。
  切换后的断言应写"某机型独有键 `not.toHaveProperty`" + 专节声明同名不同义。
- **能力必须"声明"（数据），业务代码禁止 `if 型号 === …`**：
  谁有 IK、谁支持某个动作，由能力字段驱动；"没有求解器"这类拒绝码应与
  "目标不可达 / 越限"**并列而不合并** —— 前者是**没算**，后两者是**试过不行**；
  合并会让用户以为要去调目标点。★ 拒绝时**仍要写入 target**，UI 才能说清
  "我想去哪"与"为什么没动"。
- **绝对路径不许写死**：本机路径进配置 = "换机器即失效"。
  解析顺序建议：显式配置 → 环境变量 → 用户目录下的隔离环境 → PATH。
  ★ **用户可见字符串里的路径同样不许写死**（它会进生产包）。

## 6. ★★ 大搬迁 / 大重构的纪律（照抄可避坑）

**流程**：**一次只搬一个子系统 → 构建 → 测试 → 验证 → 记录**，每步都交付一次实测数据。

**判据要按子系统选**（"全都跑一遍测试"不是判据）：

| 搬什么 | 判据 |
|---|---|
| 配置真值 | 更新冻结基线后**语义核心哈希逐位不变**（证明"只挪了位置，一个字节没动"） |
| 黄金数据 | 与冻结值**逐位一致** |
| 包/契约 | 契约校验工具**四方对账**（选择器 / 清单 / 真值 / 目录） |

**静默类坑（全都"不报错"）**：

- ★★ **「编辑成功」≠「改到盘上了」**：工具里的路径常量上一轮改过却**实际没落盘**，
  报错读起来像"**文件丢了**"。
  ⇒ **每处编辑后用独立命令核对磁盘**（读回 / 计数 / `--check`），同文件多处编辑尤其要复核；
  同文件连续/并行编辑**会丢写入** ⇒ 优先写**一次性脚本**（对每条替换断言"命中次数 == 1"，零命中/多命中都报错）。
- ★★ **不要用 shell heredoc 追加长文本**：实测**文件头部被覆盖**（标题与前面的小节丢失）、
  而**字节数恰好不变**，`wc` / `ls` 完全看不出来。
  ⇒ 追加一律用**带锚点的编辑工具**或**整文件重写**；写完**立刻读回核对章节清单**。
- ★ **路径解析用"向上找标记目录"**（向上找到同时含两个特征目录的那一层），
  **替代一切 `parents[N]`** —— 后者的层数是**被搬迁改写的隐式契约**，写错**不报错**，
  只是解析到另一个目录（症状再次伪装成"文件丢了"）。
- ★ **不要把当时的目录布局写进断言**：问"路径在不在某前缀下"是错的问题，
  要问"**是不是三端都能解析的仓库相对路径**"；搬迁时改它**不是放宽判据**，
  但必须**同时加强**（例：补"两处声明 resolve 后指向同一文件"，把"各自漂移"也钉住）。
- ★ **漏改的读者清单必须靠全仓 grep 建立，不能靠记忆**：
  静态 `?raw` 式导入、脚本里的路径常量、测试里的根目录常量、函数化后改名了属性名的调用点
  —— 一处漏改就会造成**几十个测试同时红**，而报错看起来像模块丢失。
- ★ **报错文案决定定位速度**：路径变更时抛 `KeyError: '…'` 读起来像"工具坏了"；
  改成"**键已过期**"+ 直接给出修法后，一眼归因。
- ★★ **守卫必须"能红"**：往被守卫的范围里**插一个越界 import** 验证它报错并**点名**探针文件；
  临时去掉某条配置验证对应守卫变红并**给出修法**。做不到这两点的守卫等于没有。
- ★★ **"测试存在" ≠ "测试被执行"**：测试通道本身要有守卫
  （断言测试目录存在、在自己包内、与别处不重名）。
  ⚠️ **不要给测试框架传目录参数** —— 传了就用参数**覆盖**默认收集路径，
  **包内测试被静默跳过**（且**退出码仍是 0** ⇒ 只看退出码的脚本会读成"通过"）。
- ★ **验收前先确认工作目录**：在错误的目录下跑收集器会输出"没有收集到测试"**且 `exit 0`**。
- ★ **在途运行的测试进程用的是旧模块**：改完代码必须**重跑**，别把"旧进程的结果"当回归结论。
