# 5.5 ★★★ 暗端件"贴上去看不见"：不是光照不足，是 **8bit 量化**；解法是**逐材质 `envMap`**

真实工程塑料 / 亚克力是**近黑**的，而照片通常**按白色桌面曝光** ⇒ 板面落在 8bit 的 **1~3 码值**。
"贴上去就变黑"**不是偏暗，是信息被量化抹掉了**。先把这一点证实，再谈调参 —— 否则会一直加光。

## 第一步（必做）：量暗端码值分布，别凭肉眼说"偏暗"

```python
Y = 0.2126 * r + 0.7152 * g + 0.0722 * b
print((Y <= 3).mean(), (Y <= 8).mean(), np.unique(np.round(Y[Y < 40])).size)
```

实测（全图口径）：`≤3` 占 **72~77%**，`L<40` 的像素**只用到 41 档码值** ⇒ 七成像素坐在量化台阶上。

## 第二步：证明"等比例提亮救不回来"

把 tile 用四种曲线各拉一版并排看（线性 ×N / gamma 1/2.2 / 百分位拉伸 / 由目标亮度反推 EV）：

| 曲线 | 结果 |
|---|---|
| 线性 ×8 | 只把 JPEG 块与量化台阶一起放大 |
| gamma 1/2.2 | 件被压成**近平色** |
| 推到目标 `L` 所需 **+6.2 EV（×74）** | 板面摊成 **3~4 级平台**（如 41/60/74）⇒ **假色斑，比纯黑更假** |

⇒ **渲染端的曝光补偿应当保持 0**，并在配置注释里写清"为什么不拧这个旋钮"。

## 第三步：黑件的形状可读性来自**镜面项**，与暗端数据无关

非金属 `F0 ≈ 0.04`，**镜面项不乘**那个 ≈0 的暗反照率 ⇒ 形状信息走 **IBL**。
所以正解是**给贴图材质一个环境反射**，不是提亮。

## ★★★ 第四步（最容易错）：`scene.environment` 会**覆盖** `material.envMapIntensity`

three（实测 0.186.0 `WebGLRenderer.js:2736`）：

```js
if ( ( material.isMeshStandardMaterial || ... ) && material.envMap === null && scene.environment !== null ) {
    m_uniforms.envMapIntensity.value = scene.environmentIntensity;
}
```

⇒ **只有材质自带 `envMap` 时，它的 `envMapIntensity` 才被尊重。**
"逐材质关掉环境反射 + 全局开环境"这种设计**根本不生效**。

**症状是"改了配置但数值逐位不变"** —— 实测两版统计**逐位相同**（`L=59.17 / p05=57.36 / max=78.2`）。
**看到"数字好看得过分且不随配置变化"就该怀疑这里。**

> 顺带一个教训：这个坑是被一个 **TS 层级错误**顺带暴露的 —— 字段写错层级 ⇒ 读到 `undefined`
> ⇒ 等效 `1.0` ⇒ 恰好解释了那个"好看得过分"的数。**类型检查抓住了一个物理量级的错误。**

⚠️ 另一坑：`scene.environment` 是**全局**的，会把场景里**非贴图件也一起点亮**
（实测某件被顺带点亮 **×3.38**）—— 那是另一个层面的美术改动，不该搭这趟车。

## 正解：逐材质 `envMap`（作用域精确）

```ts
// 程序化 IBL：不引入任何外部 HDR 资产（离线可复现、不加产物体积）
const gen = new THREE.PMREMGenerator(gl);
const env = gen.fromScene(new RoomEnvironment(), 0.04).texture;
gen.dispose();
// 只发给目标材质
material.envMap = env;
material.envMapIntensity = intensity;
material.needsUpdate = true;   // 换 envMap 会切 shader 的 ENVMAP 宏分支
```

要点：
1. **按材质名 / 显式标签筛选**，其余材质**一个字节不动**；
2. `envMap` 由**调用方**在 effect 里取后传入建造函数 ⇒ 建造函数保持**不依赖 DOM / WebGL**（单测跑 node）；
3. 生成 PMREM 是 **GPU 副作用** ⇒ 放 `useEffect`，不要放在渲染阶段。

## ★ 判据：零外溢必须是「逐像素」，不能是"看着差不多"

| 量 | 改前 | 改后 |
|---|---|---|
| 目标件 `L` mean | 0.08 | **12.21**（×152.6） |
| **`hp_std`（3×3 高通残差标准差 = 细节能量）** | 0.086 | **0.293**（×3.41） |
| `p95−p05`（动态范围） | 0.07 | 1.86（×26.6） |

非目标件要用**按基线图算出的像素集合**逐像素比对：`50.637 → 50.637`，**×1.0000 / `max|Δ| = 0.00`**；
对照的全局方案是 **×3.3757**。
⚠️ 用"掩膜 bbox 画矩形"来定非目标件区域会**把确实该变的邻件圈进来**（实测假 `×1.0546`）。

## ★ 别把这两个旋钮当调参旋钮

`environmentIntensity` 与 `roughness` 实测**只缩放整体亮度、不改变细节能量**：
`L` 在 `7.54 ~ 30.40` 之间动 4 倍时，`hp_std` 只在 `0.364~0.405` 之间动 **11%**。
"再亮一点"换不来更多细节。

**选值经验**：让件面**仍暗于背景**（实测 `12.21 < 22.7`）⇒ 剪影保留、形体不糊进背景，
比"提到和背景一样亮"好看得多（后者件面与背景撞色，等于把轮廓丢了）。
