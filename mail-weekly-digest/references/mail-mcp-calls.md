# 邮件 MCP 调用序列与坑

接口前缀按当前已绑定的邮箱 MCP 替换（下文以 `<mail>` 代指）。工具默认不在激活列表：先 `ToolSearch`（用精确工具名）加载 schema，再 `DeferExecuteTool` 调用。

## 1. 取主邮箱账户

调用 `<mail>__GetMe`，在返回的 `aliases[]` 中取 `is_primary: true` 的 `alias_id`，后续所有查询都带上它。每个会话先调一次即可。

## 2. 列消息（inbox 与 sent 各一次）

```
dir:    "inbox" | "sent"
after:  "2026-08-24T00:00:00+08:00"
before: "2026-08-31T00:00:00+08:00"
limit:  50
```

- `after` / `before` 接受带时区偏移的 ISO8601，区间为左闭右开。
- 单请求 `limit` 上限 50；结果里看 `pagination.next_cursor` 与 `has_more` 决定是否翻页。
- 收件区间取「上周」时：起始 = 上周一 00:00 (+08:00)，结束 = 本周一 00:00 (+08:00)。
- 营销类邮件量大，必要时可按发件人域名在本地过滤，减少后续处理量。

## 3. 只按需取正文

**不要对每封都调 `<mail>__GetMessage`**：营销类 HTML 邮件的正文可达 11 万字符以上，会被截断并落盘，白烧一轮上下文。列表接口的 `snippet` 已足够写 2~3 句摘要；只对确实需要正文的 1~2 封（例如待决策的授权/报名类邮件）再取全文。

需要按关键词定位历史邮件时用 `<mail>__SearchMessages`，按同样规则先限定区间。

## 4. 统计与换算

- `created_at` 是 **UTC**，展示一律 +8 换算成本地时间后再写入报告。
  例：`2026-08-27T19:44:29Z` → 本地 `2026-08-28 03:44` —— **会跨日**，统计归属的日期别写错。
- 四个统计口径：收件数、已发送数、未读数（`is_read: false`）、带附件数（`has_attachments: true`）。
- 分类口径按发件人域名归入：厂商资讯、活动邀约、账号安全、推广广告（可按项目需要增删类别）。

## 5. 未开通账户的处理

若第二账户（与主邮箱并列的另一个邮箱服务）未开通，接口返回 `not_bound`：

- 不要重试，不要向用户重复报错一次以上；
- 在报告与聊天结尾只用一句话说明「本次仅覆盖主邮箱账户」。

## 6. 收尾

`present_files` 打开 HTML；聊天里复述「统计概览表 + 明细表 + 要点提炼」，并明确数据源与覆盖范围（含上面那条例外说明）。
