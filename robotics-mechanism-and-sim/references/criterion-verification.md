# 判据本身也要被验：跨批 + 注入

**这是一条最该被记住的规则** —— 一条验收判据"跑起来全绿"，什么都不能说明。

## 1. ★ 固定 seed 的"跑很多次" ≠ 跨批

同一个固定种子 ⇒ **同一批样本**，跑 100 次也只是同一批。**要跨批就得换种子。**

## 2. A. 跨批：换种子跑多批，看残差分布

- 记下残差的最小 / 最大值与容差的**比值（余量）**。
- 余量太小 ⇒ 判据在边界上飘，随时会红；余量太大（数量级级别的富余）才说明留了安全区。
- 结论要落到：**容差相对实测分布留了多少个数量级的余量**，而不是"跑通了"。

## 3. B. 注入：证明判据会红

往参考侧**注入已知误差 ε**，从小到大扫，找**翻转点**：

| ε | 实测残差 | 判定 |
|---|---|---|
| 0 | 浮点噪声量级 | True |
| 小于登记容差 | 同量级跟随 ε | True（仍 < 容差） |
| **= 登记容差** | **约 1.7×容差** | **False ← 恰好翻转** |
| 大于登记容差 | 同量级跟随 ε | False |

- ⇒ **翻转点必须精确落在"登记容差"处**，才证明判据**不是恒绿**。
- ⚠️ 注入 ε 后残差 ≈ **√3 · ε** 这类系数是**三轴分量各 +ε 的欧氏距离**，属可解释的常数，
  写判据时要把它算进去，别误当成"多了一个 bug"。
- ⚠️ 注入点选在"参考侧"，才能证明**比对逻辑**本身会红，而不是只证明某个断言语句存在。

## 4. 落地口径

- 在验收清单里给"确定性"行加一条警示：**"确定性 ≠ 跨批"**。
- 把**"跨批 + 注入"作为判据的有效性证明**写进脚本注释与记录 —— 新加的守卫**必须已验证过能红**。

## 5. 验收覆盖面（每件都要能被红）

| # | 件 | 判据 |
|---|---|---|
| 1 | 类型检查 | 0 error |
| 2 | 单元/集成测试 | 全绿，且**新守卫已验证过能红** |
| 3 | 生产构建 | 产物里**不得**残留调试句柄 / 旧真值路径（命中数 = 0） |
| 4 | 端到端读数 | 真实浏览器 + 隔离端口；断言"可观测后果" |
| 5 | 仿真矩阵 | 全部机器人 FK 在**登记容差**内 |
| 6 | 黄金数据 | **逐位**复现 |
| 7 | 契约对账 | 选择器 / 清单 / 真值 / 目录 四方一致 |

⚠️ 引用绝对数字前**先跑一遍**（"证书型数字：测试计数 / 资源占用 / 残差必须现跑现取，禁止照抄"）。
