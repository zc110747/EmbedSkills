# 物理仿真：对等实现与真值口径

## 0. 定位

仿真不是"看个动效"，而是**一份可以与真机、与解析解三方互证的独立实现**。
所以核心不是"怎么建模"，而是 **"怎么证明这份仿真与判据都值得信"**。

## 1. ★★ 物理量真值 = 官方模型文件，**不复制任何数值**

- **物理量真值取官方模型文件（MJCF）** ⇒ 自有的 `physics.yaml`
  **只放**：真值声明 + 驱动参数 + 审计快照 + **官方未声明项**。
- ★★ **`--check` 必须从引擎读"生效值"（`MjModel`），不是读 XML 文本**：
  实测 XML 里某个 class 写的 `forcerange` 是某个值，而它被若干 `<position>` **逐个覆盖**
  成另一个值 ⇒ **读文本 = 读了个寂寞**。
- ★ **同一份模型的两副描述（URDF / MJCF）经常数值不一致**：
  - **TCP 帧朝向**以 **MJCF** 为准（URDF 与 MJCF 可能差 90°）；
  - **关节限位**以 **MJCF 满精度**为准（URDF 常被截断到 6 位）。
  - ★ 由此产生的 **FK↔MuJoCo 残差，根因是官方两份文件自身的精度差，不是换算错误**
    —— 别去"修"一个不存在的 bug。
- ★ **两种物理配置形态要用"有没有驱动段"来判**（刻意不加配置项）：
  `legacy`（顶层即驱动参数）vs `driver`（物理量真值在官方模型文件）。
  ⇒ 告警**必须按形态分支** —— 对官方模型说"惯量是估算值"是**错的告警**，
  **比没有告警更糟**（会诱导人去改对的模型）。

## 2. ★★ 静默错误清单（不报错但让结论全错）

| 项 | 事实 | 处置 |
|---|---|---|
| **`timestep`** | 物理时间**只由模型文件**决定；上层"物理频率"参数不生效 | 构造时**硬自检**；上层传参不一致时告警"**以模型为准**" |
| **`max_velocity` 优先级** | 同时写了两种单位时，**取 `rad_per_s` 才等于改前行为**（`deg_per_s` 是换算近似） | 写反会**静默改变运动速度** ⇒ 加断言 |
| **渲染器参数顺序** | `Renderer(model, height, width)` —— 顺序是 **(height, width)** | 传反**不报错、不告警**，却让**所有目视结论都错** ⇒ **工具调用的参数语义必须先验证** |
| **同名关节** | 两台机器人都有同名关节但范围不同 | 见跨链路入口类知识 |
| **引擎只看"局部角盒"** | hinge `range` 只能表达轴对齐盒，而耦合关节的合法域是**斜的** | 限位真值只有真值文件一份；仿真侧 padding 只做**数值保护**，不承担语义 |

## 3. ★★ 统一 Sim2Sim：只有一份判据

- 一个函数按 `robot_id` 参数化 + 一个 CLI `--all` + 矩阵默认取选择器**全部**机器人。
- ★★ **绝不为第二台机器人另写一套验收** —— **两套标准各自都会绿**，
  于是"统一"从未被真正测试过。
- ★ **交叉一致性**：新框架采的快照与旧黄金基线采的快照，在**同名用例**上必须**逐位相同**
  —— 否则"抽象/重构"过程会把基准期望值悄悄改掉。

## 4. ★★ 物理稳态偏差 ≠ 移植缺陷

**判据是"它在不在动"，不是"它差多少"。**

物理引擎有重力 + 有限 PD 增益 ⇒ 臂会停在**力矩平衡处**，而**不是**命令角。
看到"某关节差一点点"时，**三条读数**才能把它定性为物理而非实现：

1. **不发任何命令、空载静置**，偏差一样存在；
2. **不同时刻读数一致**（是**稳态误差**，不是"还没收敛"）；
3. 偏差**只出现在受重力的关节**上（转轴竖直的关节 / 轻负载端 ≈ 0）。

⇒ **正确处置 = 按链路登记容差**，
**不是**放宽全局阈值，**更不是**改物理模型去凑判据。

★ **附带复盘：别用"开机静态偏差"做自校准。**
开机快照取在极早期（臂还在从初始位形往平衡态**松弛**）⇒ 两次测量会给出不同值
⇒ **不可复现**。拿它当真值 = **把噪声焊进判据**。

★ **位置伺服同样"停不到"，判据要挂在"动没动"上，不是"差多少"。**

- 一条 `joint_position` 命令把某关节推出一段幅度，若干个控制周期后实测停在中间，
  存在可观残差；若命令幅度更小，残差也按比例缩小。
- **把命令保持住再读**（`step` 不带 action = 保持上一命令）：残差仍在以很小的速率
  缓慢蠕变，多等若干倍周期**不收敛** ⇒ 按上面的第 2 条读数，这是**稳态误差**，不是"还没到"。
- ⇒ **"关节落在指令 ±固定小量内"是一条恒假判据**：它红的时候不代表实现坏了。
  正确形状是三条，且必须**把残差打印出来**、不假装它是 0：
  ① **停住了**（连续两段位移 < 阈值；阈值按**运动量**登记，取实测蠕变量的约一倍余量）；
  ② **方向对**（位移 × 指令符号 > 0）；③ **过半**（停在起点与目标之间）。
- ⇒ 消费端纪律：**"指令 ≠ 实际位姿"**，实际位姿一律从 `/state`（或等价的状态接口）**读回**，
  不许拿自己刚发出去的数当结果。这又是一例：**判据本身要先被验**。
- 顺带：这类接口常给 `periods` 设上限（超了直接 422，因为 realtime 下一个
  控制周期就是固定墙钟时间）。**要长 rollout 就循环，别用一个大数去试探护栏。**

## 5. ★★ 绝对角 / 局部角问题（与真值文件的接口）

耦合关节的**合法域是斜的**，而引擎的轴对齐 `range` 表达不了它。
⇒ 仿真照常执行"局部角在盒内、但绝对角结构上转不到"的位形。
⇒ 架构结论：**限位真值只有真值文件一份**，仿真侧 padding 只做数值保护。
