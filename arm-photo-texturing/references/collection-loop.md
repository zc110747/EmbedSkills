# 2.5 ★★ 实物采集闭环：抓帧 → 三态判定 → 动作建议

**不要靠肉眼判"这张行不行"。** 采集是闭环（摆 → 拍 → 判 → 调），肉眼判每张都要来回比划，
慢且不稳。写一个判定工具，把 §2 的四项要求**变成数字**，并**从数字反推动作**。

## 抓帧（零依赖，不需要 OpenCV）

```bash
ffmpeg -f dshow -list_options true -i video="<设备名>"      # 先看分辨率上限
ffmpeg -f dshow -rtbufsize 128M -i video="<设备名>" \
       -frames:v 8 -f image2pipe -vcodec mjpeg pipe:1       # 抓 8 帧，读 stdout
```

- **必须取最后一帧**：设备启动瞬间会吐黑帧/绿帧，抓 `-frames:v 1` 常拿到全黑。
  一次抓 N 帧、只用最后一帧，比"发现是黑的重试"稳。
- `-f image2pipe` 输出的是**首尾拼接的独立 JPEG**，不是多帧容器
  ⇒ 按 `FFD8`/`FFD9` 切。
- 判定阶段**降采样**（1/6 足够判几何）；出纹理**必须全分辨率原图**。刻意分成两步。

## ★ 三态判定：`ok` / `reject` / `undecidable`

**「判不了」≠「不合格」**，混起来会让人去调一个**不存在**的问题。

机械臂的零件是**螺栓连成一体**的 ⇒ "画面里最大的暗色连通域"永远是**整条臂**，
不是目标零件。若照常算对边长度，会得到"左边 885 / 右边 313 px，差 182%"——
数字全是真的，**却归因错了对象**（看着像严重倾斜，实际框的是整条臂）。

```
先判「这一帧能不能判」：  最大连通域触边？  或  轮廓长宽比与目标零件差 >30%？
     ↓ 是                                   ↓ 否
  undecidable                            reject / ok
  （给出隔离办法，                          （给出倾斜方向 / 靠近多少 /
    且**禁止**输出任何                       长边要不要横过来）
    "看起来像结论"的数字）
```

> **通用规则**：当"这一帧判不了"时，绝不要输出任何"看起来像结论"的数字。
> 第一版在 `undecidable` 时照样打了 `12 px/mm`（拿整条臂算的），看着还挺好 —— 那是最坏的。

## ★ 指标要量在**正确的对象**上，而且要**归一化**

清晰度**不能量零件内部**：板面是均匀的黑色亚克力，内部本就没高频 ——
一块对不上焦但表面干净的板，内部方差同样接近 0。**真正会因失焦垮掉的是轮廓**
（对焦时 240→30 集中在 1px，失焦时摊成 5~10px 的斜坡）⇒ 量**边界一圈**上的梯度。

**也不能用梯度的绝对值当阈值**：它同时被**光照**缩放。实测同一台相机，
真机那一帧背景只比黑板亮 **119** 级、斜率 **53**；换个亮场景同一条边给 100+。
⇒ 用**归一化**的边缘过渡宽度：

```
ramp_px = ΔI / (2 · 斜率)          理想硬边 = 1.0，与光照、与放大率都无关
```

实测校准（720p）：真机 **1.17** · 高斯模糊 r=1 **1.8** · r=2 **3.1** · r=3 **4.6** ⇒ 上限 2.5。
（顺带一个反直觉：真实抓拍肉眼看着"偏糊"，实测边缘已接近理想硬边 —— 别信肉眼。）

## ★ 前提：目标零件要先「隔离」—— 但**白卡做不到**

零件螺栓连成一体、暗色部分天然连通 ⇒ 不隔离就永远判 `undecidable`。

**⚠️ 2026-09-13 实测定论：插白卡是无效的**（旧建议已推翻）。实测数据：

- 暗像素占整帧 **25.7%**，左下象限 **65%**；
- **板、立柱、底座、舵机、控制板全是同一种黑**，且板与板**由螺栓物理相连**；
- 最大暗色连通域占 **97.7%**，bbox `x[0,1040] y[0,690]`（几乎整幅画面）。

⇒ **不存在"只含一块板"的连通域**。白卡挡得住**拍摄路径上的背景**，
挡不住**结构性的物理连通** —— 螺栓还连着呢，白卡插在板后面也一样。

**可行的替代：放弃分割，改用「相机标定 + 运动学投影」直接算四角。**

三块目标板的大面法向实测均为 `(0,1,0)` ⇒ 板面**平行于像平面** ⇒ **正交模型就够**：

```
u = ox + s·X(mm)         画面右 = 世界 +X
v = oy − s·Z(mm)         画面上 = 世界 +Z
```

`(s, ox, oy)` 用**搜索**从画面里拟合（本项目 `tools/project_plates.py`）。目标函数**三项相乘**：

```
score = inside * gap_bright * (edge_hit / 1.5 + 0.05)
        ①框内暗色比例  ②板间空隙亮色比例  ③框边命中「暗↔亮」边界比例
```

**★ ②空隙项是防退化的关键**（本节最值钱的一条）：只优化 ① 时，`s=2.5` 会把三块板
挤成一团塞进左下角的底座暗区，拿到 **97.4% 的"假性满分"** —— 而那时 `oy=770`
**已经在画面外了**。与 §4 的 `Image.QUAD` 同一族错误：**数字漂亮，位置全错**。
⇒ 必须加「板间空隙 <30px 直接判 0」，并**收窄搜索范围**（如 `s ∈ [3.8, 5.6]`）。

> ⚠️ **"数值自洽"是最危险的假信号**：本例曾拟合出 `{s:3.80, ox:530, oy:645}`，
> 与三块板的图像位置**一一对应、数值完全自洽**，于是被当成真值用了下去 ——
> 按它出的三块纹理**全部不合格**。事后证明 **`3.80` 是搜索下界被截断的值**（见下一节）。
> ⇒ 目视复核叠加图是**唯一**的验收手段；数字再漂亮也不能代替看图。
> 另外"人工把 `ox` 从 530 改成 460"的修正**是错的**，A/B 对比证明 530 才对
> （数据也一致：框内暗色 69.8% vs 41.5%）—— **数据会骗人，人也会。**

> ⚠️ **转关节也不能代替隔离**：转 base 只改变哪块板朝前，不改变"连成一体"这件事。

## ★★★ 先测一件事：**搜索区间是否贴边**（这条踩过一次，代价最大）

**带区间的搜索，必须显式检测"最优解是否落在区间端点上"。**
贴边 ⇒ 该值**不是测量结果，是区间的人为截断**。

实测事故：拟合出 `s = 3.80`，与三块板的图像位置**一一对应、数值完全自洽**，
于是被当成真值用了下去，按它出的三块纹理**全部不合格**。
事后才发现 **`3.80` 恰好等于当年的搜索下界 `S_LO = 3.8`** ——
它从来不是自由极值。把区间放宽到 `×0.6~1.8` 后，最优解直接变成 **`2.58`**。

```
搜索 s ∈ [3.80, 5.60]  → 最优 s = 3.80   ← 贴边，是截断值，不是测量值
搜索 s ∈ [2.28, 6.84]  → 最优 s = 2.58   ← 才是真的
```

**这比"分数不高"隐蔽得多**：分数看着还行、数值看着合理、还与图像自洽 ——
**唯一能暴露它的，是"换个区间再跑一次看结论变不变"。**

```python
# 永久防护：最优贴边就大声说出来
if s <= s_lo * 1.02 or s >= s_hi * 0.98:
    print(f"⚠️ s 落在搜索边界上 ⇒ 范围设窄了，用 --s-range {s*0.6:.1f},{s*1.8:.1f} 放宽重跑")
```

> **判据**：**两个读数互相矛盾时，先查区间是不是设窄了，别急着改模型。**
> 同理适用于 `--s/--ox/--oy` 这类"手工覆盖"值 —— 它们不是测量，只是先验。

## ★★★ 什么时候该放弃自动投影（判据）

**自动投影不是万能的。** 判定它"在这套场景下不可用"的三条硬证据：

1. **最优分数低且叠加图肉眼不对**。别只看分数 —— 一定要看叠加图。
   实测最优 score 仅 **18.2**，三个框**都没贴板边**（框落在暗区中段，边缘全是"暗↔暗"、
   没有亮度跃变）；把参数手动拨到"看起来该对"的位置，score 只有 **1.9~4.2**，反而更差。
2. **目标板在投影上互相粘连**。本例三块板在 HOME 位**竖直首尾相接**
   （立柱 Z[38,60] 紧接大臂 Z[59.8,134.2]）⇒ **没有任何一条边能提供唯一定位约束**。
   目标函数只能"整条结构一起平移"，平移 70px 分数照样不低。
3. **相机相对物体的真实位姿从未标定**。`缩放 + 平移`只有 3 个自由度，
   而"三项乘积"只有 1 个标量约束 —— **约束少于自由度，解必然不唯一**。
   单帧拟合出来的 `(s, ox, oy)` 是**欠定的**，不是标定。

⇒ 命中任一条，就**停止调目标函数**（那是"改模型让它对上"，同一类错误），
转用下面的 **§2.7 致动并观察** + **§2.8 窄带 PCA**。

> ⚠️ **别拿 `ramp`（边缘过渡）反过来判断"相机失焦"**：`ramp` 是在**投影框边缘**测
> "暗↔亮"过渡的 ⇒ 框定位一错，它就成了噪声。实测`CONCLUSION` 报 `ramp=10.78px 失焦`，
> 放大目视**真实边缘只有 ~2px，并未失焦**（框落在暗区内部，边缘压根没有真实边界）。
> **一个判据只有在其前提成立时才有意义 —— 不要用下游指标反推上游前提。**

## ★★ 另一个必须先查的坑：**目标是否被画面裁掉**

出纹理前必须确认目标**完整入画**。实测踩到：`y = 0` 处有一条 `x[506,760]` 的**连续暗带**，
从 y=2 起才裂成多段 ⇒ 结构在**顶边被切断**。目标被裁 ⇒ 纹理四角必然缺角。

**这条已经踩过，解法是"换个姿态而不是硬凑"**：HOME 位大臂竖直、顶端顶到画面边；
改用 `shoulder=45` 这类姿态即可**整臂完整入画**，而且板面**仍然正对相机** ——
因为肩/肘绕**世界 Y** 摆动，板的大面法向 ±Y 不变。**不要在 HOME 位出纹理。**

**判据（一行）**：`mask[0].any() or mask[-1].any() or mask[:,0].any() or mask[:,-1].any()`
⇒ 边缘有暗像素就要警惕，再叠加图确认是"贴着边"还是"被切断"。


## ★ 真机零件可能是**镂空桁架**，`size` 只是外接盒

实测：机械臂臂板中间是镂空的三角桁架，放大照片可**透过开口看到背后的墙**；
而前端把 `plate` 渲染成 `RoundedBoxGeometry`（**实心倒角盒**）。后果：

- 轮廓填充率天然只有 **40~50%** ⇒ 这必须是**提示**，**不是阻塞**。
  升级成阻塞会让每张真机照片都判死，工具变"永远说不"的噪音源、人开始忽略它
  **= 等于没有工具**。
- **直接把照片烘到实心盒上会把背景色带进孔洞**，贴上去比不贴更假
  ⇒ 贴图阶段必须做**孔洞掩膜**（把孔洞像素填成零件主色），或把镂空建成几何。

## 取景预算（先量相机上限再定策略）

```
长边需占的画面比例 = 目标 px/mm × 长边mm ÷ 画面长边px
```
实测某笔记本内置相机上限 **1280×720** ⇒ **长边横过来放**：顶到画面边之前还能再靠近
**1.78 倍**（1280 vs 720），px/mm 的**上限**随之 ×1.78。

> ⚠️ 别把它说成"同取景下 px/mm ×1.78" —— 同取景旋转**不改变** px/mm。
> 增益来自"能再靠近"。这类指令写错，人会白折腾且不会报错。

## ★★ 动关节改变不了 `px/mm` —— 只有物理靠近相机

**这是最容易白折腾一整天的一条。** 想让板在画面里更大，直觉是"把臂摆一下"，
但三条独立实测都指向同一结论：

| 动作 | 实测 | 为什么 |
|---|---|---|
| 转 `base` 0 → −20° | 远端放大 ×1.08，但板法向偏 20°、投影 ×cos20°=0.94 ⇒ **净 1.015** | 零和，还多一层透视 |
| `shoulder` 摆动（仿真） | 大臂板长轴倾角 **89.2°→79.2°→59.2°→41°**，但**板长度不变** | 板随肩同步转，投影长度不变 |
| `shoulder` 0 → 30°（真机） | 暗色投影面积 **236345 → 230804（−2.3%）** | 差值来自**遮挡**，不是缩放 |

**原因**：相机在 **−Y**（垂直于摆动平面），而摆动平面是 **X–Z**
—— **摆动平面平行于像平面** ⇒ 摆动既不改变到相机的距离、也不改变投影长度，
只改变板**在画面内的朝向**。

⇒ **提高 `px/mm` 的唯一手段是物理把相机靠近目标。** 本例当前 `s ≈ 3.80 px/mm`
（74mm 板 → 281px），目标 ≥6 需靠近约 **1.6×**。

> ⚠️ **对比实验必须先回 HOME**：若工具是"只发变化的关节、其余保持不变"，
> 状态会**跨实验累积** —— 实测先 `base=-20` 再只发 `shoulder=30`，
> 后者会把 base 保持在 −20 ⇒ 两张图的机位根本不同，**读数全部作废**。
> 给指令工具加一个 `--home`（先回零位再动）是刚需，不是可选项。
