# 容差按对象登记

## 1. ★★ 原则

```text
FK_TOL_MM = {
  <robot-A>: <极紧量级>,   # 实测残差远小于它 ⇒ 留若干数量级余量
  <robot-B>: <较松量级>,   # 实测残差同量级偏小 ⇒ 留约一个数量级
}
# 未登记的 robot_id：直接抛错，不给缺省值
```

- ★ **悄悄给一个"够大"的缺省** = 把"**没人想过它的精度来源**"藏起来 ——
  而那正是**放宽阈值以通过测试**的开端。⇒ 未登记一律 `raise`。
- ★ 每条容差后面必须写**为什么是这个量级**（实测值 + 余量），评审时先看这行。
- ★ 容差随"对象"登记（机器人 / 链路 / 关节），**不是一张全局表** ——
  不同机器人、不同链路（真机 / 仿真 / 后端 ACK）的误差来源不同，混用一张表必然要么过松要么常红。
- ★ **余量太小 = 判据在边界上飘，随时会红**；余量通常是"实测残差的若干数量级"，
  具体倍数按对象登记，不照抄别的项目。

## 2. 阈值的形状

| 场景 | 阈值形状 | 反例 |
|---|---|---|
| FK / 位姿残差 | 按对象登记的绝对容差 | 全局一个数 |
| "是否停住" | 按**运动量**登记（实测蠕变量的约一倍） | 拍一个看起来够大的数 |
| 后端 ACK / 链路到位 | 按链路登记（时延、限位截断引起的误差） | 与物理稳态误差共用一条 |
| 物理稳态偏差 | 按链路登记，**明确写出"这是物理而非缺陷"** | 放宽全局阈值、改物理模型凑判据 |

## 3. 未登记就报错，而不是给缺省

- 缺省会**静默**把新对象纳入"已覆盖"，于是没人再回去想它的精度来源。
- 新增机器人 / 新增链路时，必须**显式登记**：写实测值 + 余量 + 理由。
