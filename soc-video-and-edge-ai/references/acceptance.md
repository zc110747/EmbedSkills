# 验收：无头回归与端到端判据

三条链路各有自己的验收面：推流端（媒体服务器 + 播放器）、服务端（浏览器两端）、AI 分支（无头单测 + 指标）。共用原则：**判据要能被脚本判定，不靠人眼看图**。

## AI 验收清单

| 项 | 判据 |
|---|---|
| 视频不受影响 | 关 AI / 开 AI 两次运行：帧数、dropped、码率一致；管线描述字符串 diff 后，关 AI 时不含任何 AI 元素 |
| AI 指标 | 单行指标含 `fps` / `infer` / `track` / `queue` / `processed` / `dropped` / `skipped` / `objects`，可被脚本正则提取 |
| frame_id 语义 | 30fps 源 + 5fps AI ⇒ 相邻结果间隔 ≈6 |
| timestamp 语义 | 取自 PTS、单调递增 |
| bbox 语义 | 落在**原始分辨率**坐标内（不是 letterbox 后的 640 空间） |
| 跟踪稳定 | 真人长时间（约 20s）保持同一 `id`，conf 波动但 ID 不跳 |
| 模型缺失 | 删掉模型文件后启动：视频照常 STREAMING，日志出现"AI 未启动，视频流不受影响" |
| 单测 | 全部 pass（含 skip） |

## 无头回归测试（不靠人眼看图）

摄像头对着天花板时 `objects=0` 是**正确结果**，不是 bug。别用真机画面做回归，用静态图：

1. 取 Ultralytics 官方示例图（`bus.jpg`，多人 + 车）放入测试夹具目录。
2. 用 `stb_image.h`（单头文件、public domain，**只给测试用**）解码。
3. 断言：检出 person 数 ≥ 1，且每个 bbox 满足 `0 ≤ x1 < x2 ≤ width`、`0 ≤ y1 < y2 ≤ height`。
4. **缺推理运行时或缺夹具时打印 `[skip]` 并计 pass**，不要 fail（保证 CI 可跑）。

另两个必测用例：
- **跟踪稳定性**：构造 3 帧缓慢平移的同一目标，断言只产生 **1 个 track_id**。
- **管线生命周期**：init → start → push 5 帧 → 回调收到 → stop，断言线程干净退出。

MSVC `/W4` 下 `std::getenv` 会报 **C4996**（零警告要求）：封装 `safe_getenv()`，MSVC 走 `_dupenv_s`，其他走 `std::getenv`。

## 推流端端到端验收

1. 起媒体服务器 → 推流端推流 → 播放器看到实时画面。
2. **杀媒体服务器**：推流端不退出，状态转 DISCONNECTED，按 1/2/5/10s 退避。
3. **重启媒体服务器**：推流端自动恢复 STREAMING。

判据取自**媒体服务器日志**（逐行实时刷盘）中的上线提示；不要用推流端 stdout 日志（有缓冲，且受稳定宽限延迟）。

## 服务端端到端验收

1. 全量构建全绿（前端产物 + 服务端 exe + 推流端 exe）。
2. 无交互一键启动 → 健康检查接口返回 ok。
3. 摄像头列表接口中目标流状态 online。
4. 浏览器 WebRTC 出画（桌面 + 手机两端）。
5. HLS 兜底：WebRTC 超时或手动切换后，两端均出画。
6. 联调脚本 pass 计数达标、fail 为 0。

## 常见"假绿 / 假红"

| 现象 | 真相 |
|---|---|
| WHEP 探测返回 502 | 合成 SDP 缺 ice-ufrag 的**脚本假象**；真浏览器已可用则可忽略 |
| 状态已是 STREAMING 但播放端无画面 | "假 STREAMING"：异步建连握手未完成；判据要加稳定宽限 |
| 脚本报 exit 1 但功能正常 | PowerShell 把原生 stderr 当错误；真实退出码要读 `$LASTEXITCODE` |
| 判定重连失败 | 读了被缓冲的 stdout 日志 |
| 诊断文件内容乱码/为空 | PowerShell `>` 落盘是 UTF-16，需按 UTF-16 解码 |
| 改了代码行为没变 | 未重新构建（服务端要 `go build`；前端要 npm build + 再 go build 嵌入） |
| 第二次启动起不来 | 媒体服务器多开了 RTMP/SRT/MOQ 等监听口 |
| 集成验证时服务端无响应 | 拉起的进程被调用会话回收；需在同一次调用内起进程 + 发请求，或改用长驻后台任务 |
