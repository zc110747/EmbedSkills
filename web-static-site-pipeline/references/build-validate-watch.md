# 构建 / 校验 / 监听：实现细节

## 1. 内容源结构（Markdown）

一篇 = 一个文件，文件名 `NNNN.Title_With_Underscores.md`，正文用固定 H2 分区：

```markdown
# 原始标题

## Article      ← 正文（唯一会被送去生成音频的区）
## Words        ← 表格：单词 | 音标 | [词性] | 释义 | [例句]（3 或 5 列，靠表头别名识别）
## Questions    ← `**题干**` 或 `Question N：题干` + `A. …`
## Answers      ← 答案解析
## Continue(s)  ← 上一篇/下一篇，构建忽略，仅作人工维护的交叉引用
```

- 扩展形态可混用：front matter（`id` / `title` / `audio`）+ `## Q1` + `题型：单选|填空` + `答案：` / `可接受答案：` / `解释：`。
- **答案有四种写法**，必须都支持：① 紧凑串 `BAC`；② `Question5: …`；③ 分块；④ 编号列表 `1. **B. …** 解释`。
- ④ 的序号点常被转义成 `1\.`（CommonMark 与 `1.` 等价），正则要写 `\\?`；**别全局删反斜杠**（会破坏真需要转义的地方）。
- 选择题键判据要严格：只在 `A.` / `A)` / `A、` 这类**选项前缀**位置取字母，不能把 `cook`、`bamboo` 的首字母读成选项。
- 题干里的 `______` 是内容，`strip_markdown` **不得**把它当成下划线强调处理。

## 2. 校验器该断言什么

| 断言 | 判据 |
|---|---|
| 五区齐全且顺序正确 | 各 H2 的 `id` 出现位置单调递增，且 `>Article</h2>` 之类字符串在 |
| 标题格式统一 | 由 `display_title()` 生成（`NNNN. 原标题`），浏览器标题再挂站点名 |
| 全站相对路径 | 正则扫 `href="/…"` / `src="/…"` ⇒ 有则 FAIL（项目子路径部署必须相对） |
| 资源指纹 | 用 `asset_url()` 算出期望值再比对，**别写死 `?v=abcd1234`** |
| 首页不含文章页专属内容 | 判「某类内容不在首页」要查**专属类名**，不要查通用属性 |
| 汇总数字 | Chapter 篇数 / 总数 / `aria-valuemax` 必须等于真实数据，不是常量 |
| 能力分支 | 有播放器的页才查三档倍速与无 ±seek；无播放器（缺音频）的页只断言播放器专属类名不出现 |
| 可重复性 | 重构建到临时目录，逐字节比对；不一致连文件名一起打印 |

## 3. 行尾与指纹的联动

- `.gitattributes` 写死：`* text=auto eol=lf`、`*.bat eol=crlf`、二进制按 `binary`。
  校验用 `git ls-files --eol`，**只应剩批处理文件是 CRLF**。
- 指纹算的是**磁盘字节**：一次意外的行尾转换会让全站 `?v=` 全变、所有页面 diff 一遍。
  文档里报字节数时注明是 LF 口径。
- ⚠️ 回滚内容目录**绝不能** `git checkout -- content/`（会把整个目录的未暂存改动一起回滚）。
  正确做法是逐个文件：`git add <file>` → `rm <file>` → `git checkout -- <file>`。

## 4. 监听器（watch）

- 轮询源目录 mtime，1 s 级足够；变化即**全量重建**（新增/删除会改相邻页导航，增量必错）。
- 源写坏：打印错误并继续监听，不退出（否则改一半的 md 会把 watch 打死）。
- 附带开关：`--audio` 只补**缺失**的音频，不检测内容是否过期 —— 因此「改了正文就要手动重生成同名音频」必须写进文档。
- 改名/删除的清理不自动做（不删文件原则）：只提示「旧的产物与音频需要人工删」。

## 5. 构建脚本的边界

- 只解析、只生成；**不生成音频、不转码、不联网**。
- 缺资源只警告：一篇缺音频不该拖累其它页面产出。
- 可复现优先：任何 `datetime.now()`、`set` 迭代序、`os.listdir` 原序都会破坏字节级一致。
