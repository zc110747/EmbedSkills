# `.bat` 写法与一键脚本落地规范

## 一、跑 / 调试 `.bat` 的本机环境事实

| 事实 | 说明 |
|---|---|
| **跑 `.bat` 用 Bash 工具的 `./x.bat < /dev/null`** | 实测：输出完整、`$?` 就是脚本真实退出码、`pause` 正常响应。**`< /dev/null` 不可省** —— `pause` 会等按键，不重定向就是"无输出 + 卡到超时"，极易被误读成"Bash 跑 `.bat` 不可信"。 |
| 别用 `cmd //c "x.bat > f.log"` | 会进 cmd 交互模式（打印版本横幅后停在提示符）。 |
| Bash 工具里显式调 `cmd.exe` 会被拒 | `cmd.exe /c x.bat` → 策略拒绝。注意 **`./x.bat` 允许、`cmd.exe ...` 不允许**，两者结果差很多。 |
| PowerShell 工具已无法跑 `.bat` | `cmd.exe /c ...` 与 `& .\x.bat` 都是**整条命令行在校验期被拒**（连它前面那句写文件都没执行），没有"落文件诊断"这条路。跑 `.bat` 一律走 Bash 工具。 |
| PowerShell 工具的 stdout 本环境不回显 | `Write-Host` 看不到是正常的。cmdlet 结果一律落文件再读，不要反复重跑。 |
| 构建日志可能是 UTF-16 | `Tee-Object` / `Out-File` 产出的日志常是 UTF-16LE，按 UTF-8 读会乱码；用 `python -c "...decode('utf-16','replace')..."` 解码。 |
| 链接前先杀目标进程 | 程序还在跑 → exe 被文件锁 → `Permission denied`，与**沙箱**拦截症状字面相同。判据：有没有 `[sandbox] 命令被沙箱拦截` 块；关了沙箱仍报 = 进程没退。GUI 程序尤其易踩（用户开着界面看效果）。 |
| "端口 / 地址"是两端的 | 见 §三·坑 29。 |

标准诊断流程（Bash 工具，能拿 stdout + 真实退出码）：

```bash
# 先杀残留进程：上一轮的僵尸进程是"脚本时好时坏"的第一嫌疑
#   netstat -ano | awk '$4=="LISTENING"{print $5}'   （别用 sort -u / find / timeout）
#   taskkill -F -PID <pid>
./x.bat --no-pause < /dev/null
echo "exit=$?"
```

- 脚本自身会落日志时**优先读它**，比控制台输出信息量大得多。
- ⚠️ **"镜像目录里复测通过"必须先确认镜像里是改后的副本**：改了哪个文件就重新 `cp` 哪个文件，否则验证的是幽灵。

## 二、`.bat` 写法三十大坑（每条都真踩过）

| # | 坑 | 现象 | 修法 |
|---|-----|------|------|
| 1 | `if (...)` 块内 `echo` 里的 `)` 提前闭合块（如 `echo ... (exit %errorlevel%).`） | `此时不应有 .` / `命令语法不正确` + RC=255 | 块内 `)` 转义为 `^)`（不是禁括号）；cmd **解析期**就整体解析整个 `if (...)` 块，即使运行期不执行该分支也会报语法错 ⇒ 必现 |
| 2 | `%~dp0` 尾反斜杠使 `\"` 转义引号 | cmake 把整行吞成一个 `-S` 参数 | 先 `if "%ROOT:~-1%"=="\" set ROOT=%ROOT:~0,-1%`，拼接时显式补 `\` |
| 3 | 路径拼接丢分隔符 | 生成 `<name>build-msvc` 这类错误目录 | `set BUILD=%ROOT%\build-msvc`（显式补 `\`） |
| 4 | `start "t" cmd /c prog > log` 重定向落在 `start` 上 | 日志 0 字节 | 重定向放进 `cmd /c "..."` 内部 |
| 5 | `timeout /t` 被 GNU timeout 抢占 | `invalid time interval '/t'` | 钉 `C:\Windows\System32\timeout.exe`，或改用 `ping -n` |
| 6 | `for /l` 内 `goto` 丢变量 / 块内 `%VAR%` 取旧值 | 轮询标志不生效 | 改 `EnableDelayedExpansion` + 标志位轮询，块内读刚 set 的值用 `!VAR!` |
| 7 | `for /f ('powershell 含双引号/花括号命令')` 嵌进 `if (...) else (...)` 深块 | 顶层单独测正常，嵌进 else 块即 `此时不应有 X` 类解析错 | 把枚举逻辑抽成 `:子程序`（顶层执行），或先把 PS 输出落临时文件再 `for /f` 读文件；避免深块内出现 `('"..."')` 混合引号 |
| 8 | **cmd 不剥离双引号内的 `^`**：`powershell -NoProfile -Command "... Get-X ^\| Where-Object ..."` | PowerShell 收到字面量 `^`，报 `找不到接受实际参数"^"的位置形式参数` | `^` 只在**双引号之外**才是转义符。PowerShell 命令里**不要写管道**：用 `@(…).Where({…})`、`foreach`、`Invoke-RestMethod` 替代 `\| Sort-Object`；或把脚本写成临时 `.ps1` 再用 `-File` 调。同理 `2^>nul` 必须放在 `-Command "..."` 引号**之外** |
| 9 | `if (...)` 块内 `echo` 文本含**成对**括号，如 `echo  (from GET /api/x) ---` | `此时不应有 ---。`（`(` 开嵌套块、`)` 提前闭合） | 块内 echo 文本去掉括号（改 `-` / `[]`）；确需保留则转义 `^(` `^)` —— 同样只在双引号外有效 |
| 10 | **findstr 的 `$` 锚点 + 管道**：`(echo %PORT%) \| findstr /r "^[0-9][0-9]*$"` 判合法端口为**非法** | 合法数字被拒，`(echo 8081 \| findstr /r "^[0-9]*$")` 同样失败 | `$` 不吃掉 `echo` 输出的 **CR**（CRLF），行尾残留 `\r` 导致不匹配。改用 `set /a` 回环校验：`set "N=" & set /a "N=%PORT%" 2>nul` 后 `if not "%N%"=="%PORT%"` 判非数字，再 `LSS 1 / GTR 65535` 查范围 |
| 11 | 脚本内部固定拼子目录前缀：`set CFG=%ROOT%\config\%CFG_NAME%`，用户却传 `--config config\x.yaml` | 拼成 `config\config\x.yaml`，报 not found | 三级探测：`<root>\<subdir>\<name>` → `<root>\<name>` → `<name>`，命中哪个用哪个；**并单独保存传给子进程的相对路径**（子进程 CWD 未必等于脚本所在目录） |
| 12 | `node_modules` 存在就跳过 `npm install` | `Rollup failed to resolve import "xxx"`（依赖是后加进 package.json 的） | "装过一次" ≠ "装全了"。比较 `package.json` / lock 与 `node_modules` 的 mtime，或**构建失败时自动 `npm install` 并重试一次** |
| 13 | `for` 块内 `echo %%C` 输出**外部数据**（设备描述、路径、hwid 可能含 `)` / `&`） | 块被 `)` 提前闭合，枚举逻辑静默崩掉 —— **源码里看不到括号，坑在运行期数据里** | 枚举行解析抽成 `:子例程` 用 `call :line "%%A" "%%B"` 处理（`%~1` 顶层无块解析）；`echo "%~2" \| findstr` 加引号护住 `&`；列表收集后在**块外**用 `!VAR!` 打印；首列数据用 `findstr /r "^COM[0-9]"` 先过滤非目标行 |
| 14 | **自转录日志**：脚本内 `call "%~f0" %* > log 2>&1` 或 `cmd /c ""%~f0" %*" > log 2>&1` 自重启 | 日志里有「另一个程序正在使用此文件」，且 `exit /b` 变成 1 —— **被占用的是 `.bat` 自身** | cmd 无法在脚本运行期间重新打开正在执行的 `.bat`。日志一律由**调用方**重定向，脚本内绝不自重启 / 自转录 |
| 15 | 用 `.bat` 当工具链替身（mock）做集成测试 | mock 只跑到自己第一行就"返回"，父脚本后续语句**全部不执行**，退出码还是 mock 的 | cmd 里直接调用另一个 `.bat`（**不加 `call`**）= 转移控制权而非返回。要造替身就编译真 `.exe`：用 gcc（`gcc -O1 -o dotnet.exe mock.c`） |
| 16 | **`for /d %%d in ("路径\前缀*")` 的 `%%d` 带着外层引号** | `%%d` = `"C:\...\dir"`（引号在值里）⇒ `if exist "%%~d\bin\x.exe"` 永远失败，变量静默为空 | 必须 `set "DIR=%%~d"` 用 `%%~d` **剥引号**再判存。对照：`%%~$PATH:p` 形式（for 变量是**裸名**）**不带**引号；**带引号写 `for %%p in ("a.exe")` 反而会把引号注入结果**。两种形式行为相反 |
| 17 | **用分隔符拼接字符串，再用 `for /f "delims=X"` 读回来想得到多行** | 只得到**一行** —— `delims` 切的是**行内 token**，不产生新行 | cmd 没有数组，用**编号变量 + 计数器**：`if defined M1 set /a N+=1 & set "MISSING_!N!=!M1!"`，打印 `for /l %%i in (1,1,%N%) do echo !MISSING_%%i!` |
| 18 | **`call :label` 出现在 `if (...)` 块内，或标签定义在调用点之后** | `系统找不到指定的批处理标签 - xxx`；调用**静默不发生**，计数器 / 变量保持默认值（酷似"逻辑没写"） | cmd 按**文件镜像**解析 call 标签，块内 + 标签在后都不可靠。helper 段放**中段**，主流程 `goto :after_helpers` 跳过它，然后在**块外**顶层层 `call`；只是"往列表加一项"就直接用坑 17 的编号变量内联 |
| 19 | **`findstr /c:` 模式里写了非 ASCII 字面量**（如 `findstr /c:"USB 串行"`） | 文件以 GBK 解析，UTF-8 中文**破坏整行**，cmd 把碎片当命令跑 ⇒ 一串 `'local' 不是内部或外部命令`，整个脚本从该行起崩掉 | `.bat` 里**任何位置**都不要非 ASCII（注释、echo、findstr 都一样）。匹配厂商 / 型号只用 ASCII token：`Arduino` / `CH340` / `CH341` / `CP210` / `FTDI` / `USB Serial`。**判据**：报错里出现"一段像自己注释的英文单词被当成命令名" |
| 20 | **`for /f` 反引号内的 cmd 元字符未转义**（`for /f ... in (\`powershell ... \| Where-Object ...\`)`） | `此时不应有 \|` / `The syntax of the command is incorrect.` —— 裸 `\|` **终止了命令替换** | 反引号内的 `\|` `>` `<` `&` 一律加 `^`。⚠️ 但见坑 8：`^` **只在双引号外**有效，所以 PowerShell 命令体内部**根本别写管道**，`2^>nul` 放在 `-Command "..."` **引号之外** |
| 21 | **`if exist "\\.\COMx"` 判串口是否存在** | 对**所有**端口都返回"不存在"，含设备管理器里正常列出、可正常打开的端口 ⇒ 用它做端口预检会**误拦真板子** | 用枚举而非存在性测试：`[System.IO.Ports.SerialPort]::GetPortNames()` 取回后拼成 `,COM<n>,COM<m>,` 形式，再 `echo %LIST%\| findstr /i /c:",COM<n>,"` 判成员。**并顺手把可用端口列表打给用户** |
| 22 | **PATH 回退命中"同名但异族"的工具链** | PATH 上 `avr-objcopy` 解析到 **Microchip XC8**（PIC 家族）的同名程序；`if exist` 通过、预检"全绿"，但混进 avr-gcc 链接产生**极难定位**的 hex / 链接错误 | 工具链回退**必须带厂商拒绝列表**（`\Microchip\` / `\xc8\` / `\xc16\` / `\Keil`），命中则整组丢弃并留 `REJECTED_CC` 供上层报明确错误。原则：**宁可清楚报"请安装"，也不静默用一个错工具链**。另：`objcopy` / `size` 必须与编译器**同 bin 目录** |
| 23 | **把退出码塞进 `:label` 子例程签名**：`call :pause_exit 1`，子例程里 `exit /b %~1` | **`exit /b` 在 CALL 上下文里只结束这个 CALL**，调用处继续往下走 ⇒ 成功路径打印 `[OK]` 后**顺序落入**失败标签，连打多条 `[FAIL]`、退出码被带成 1；参数错路径报完错**接着跑完整构建**并 EXIT 0。症状是"成功和失败同时打印" | **暂停与返回码必须拆开**：`call :pause_exit`（只等按键，内部 `exit /b 0`）＋ 紧接一行 `exit /b <code>` —— **后者才是真正结束脚本的那句**。每个 `:label` 分支末尾都要有自己的 `exit /b`（`goto :eof` 只跳到文件尾、**不携带退出码**） |
| 24 | **`shift` 之后再读 `%~dp0`**（开头写 `if "%~1"=="--no-pause" set NOPAUSE=1 & shift` 然后才 `call "%~dp0<env>.bat"`） | `%~dp0` **派生自 `%0`**，`shift` 把 `%1` 挪进 `%0` ⇒ 取到**别的路径**；无参数时退化成**当前目录**。实测报到项目根，环境脚本加载失败、`PROJ` 全空、**依赖全报缺失**，症状酷似"工具链没装" | **所有 `%~dp0` 派生量必须在任何 `shift` 之前捕获**：`set "BATDIR=%~dp0"` 放在参数解析之前，之后一律用 `%BATDIR%`。`%~nx0` / `%~n0` 同理 |
| 25 | **脚本移到子目录后用 `%~dp0..` 推导工程根** | ① 字面 `%~dp0..` 残留尾反斜杠、分隔符混杂，污染下游每条路径；② 更隐蔽 —— **判据取自错误的层级**：想验"自己在 `scripts` 里"却去读 `%~dp0..` 的末段名（那是**工程名**）⇒ 守卫恒不成立，`PROJ` 静默停在 `scripts\`，构建误报源文件 `not found` | ① 用 `for %%d in ("%~dp0..") do set "UP=%%~fd"` 取**规范化**父目录（`%%~f` 真正折叠 `..`）；② 判自身目录名要读 **`%~dp0` 加尾点**：`for %%s in ("%~dp0.") do if /i "%%~ns"=="scripts" ...`；③ **用工程标记文件兜底**：`if exist "%%~fd\src\main.cpp"`，脚本被放回根目录也能工作 |
| 26 | **父脚本在根、子脚本在子目录，却只用一个目录变量** | 只用一个 `BATDIR` 必然错一半：拿它调子脚本 → `<工程名>\build.bat 不是内部或外部命令`；改成子目录又会导出错误的 `PROJ` | 明确区分**两个**变量，且都在 `shift` 前捕获：`set "BATDIR=%~dp0"`（自己所在目录 = 工程根）＋ `set "SCRDIR=%~dp0scripts\"`（工作脚本目录），调用写 `call "%SCRDIR%build.bat"`。`PROJ` 交给环境脚本统一推导 |
| 27 | **用 Edit / Write 工具改 `.bat` 后被重写成 LF 行尾**（工具默认 LF，cmd.exe 要求 CRLF） | 纯 LF 时 cmd 无法正确断行，把整文件按空格 / 换行**碎片化成命令**执行 → 一串 `'-click' 不是内部或外部命令` 之类 token 碎片，`%%T` 退化成 `%T` | 改完必须转回 CRLF：`tr -d '\r' < x.bat \| awk '{ printf "%s\r\n", $0 }' > x.tmp && mv x.tmp x.bat`。复查：`tr -cd '\r' < x.bat \| wc -c` 应等于行数；配合坑 19 再查非 ASCII（`grep -P '[^\x00-\x7F]' x.bat` 应为空） |
| 28 | **把含 `&&` 的变量插值进 `echo`**：`set "FE_CMD=npm install && npm run dev"` 后写 `echo starting: %FE_CMD%` | cmd 在**变量展开之后重新解析整行**，`&&` 成了命令分隔符 ⇒ 只打印前半句，**后半句就在脚本自己的目录里被执行了**。它**不报语法错**，看起来只像"echo 少打了几个字" | ① `echo` 文案一律写字面量；② 变量只在**带引号的位置**插值才安全（`cmd /k "%FE_CMD%"`、`if exist "%P%"`）；③ 要打印命令本身分行写多条字面量。**同族字符**：`&` `\|` `\|\|` `>` `<` `^` 全都一样 —— 口诀"**变量展开处若不在引号内，就当作要执行的内容看**" |
| 29 | **把"端口"当成一个变量，忘了它是两端的**：脚本公布 `--port` / `PORT` 开关改了端口，但**后端 CORS 白名单**、**服务端绑定地址**、**就绪探测地址**各自写死旧值 | ① 页面**能加载**，随后每个请求 **HTTP 400** 且无 `access-control-allow-origin`，浏览器报成"API 网络错误"；② 服务明明起来了就绪探测**报未启动**（服务绑 `::1` 而探测是 `socket.AF_INET`，**结构上**看不见 `[::1]` 监听，不是偶发）⇒ 打印 `nothing is listening on port <p> after 180 s` 并 exit 1，而 dev server 健康服务中 | ① 服务端**显式命名绑定地址**，不要靠"localhost 的默认解析"（Node 会先解析成 `::1`）；② 白名单**按同一个变量派生**；③ 探测与绑定读**同一个**变量（含 host），并**导出给子进程**（`start` 的子控制台会继承）；④ 验证时把端口**真的移开**跑一遍 —— 两端不一致只在移端口时现形 |
| 30 | **`cmd /k "set X=Y && ..."` 里的尾空格** | `,` 前那个空格会**进入变量的值**（`Y `），依赖它做 hostname / 路径时解析失败 | 用继承（脚本内 `set` 后由 `start` 的子进程继承，推荐），或写成 `set "X=Y"&& ...`。判定口诀同坑 28 |

### 族小结（按症状归类，便于反查）

- **坑 1 / 8 / 9**：cmd 解析期定死语义 —— 括号、`^`、引号在**块内 / 引号内**行为都不同。
- **坑 10 / 11 / 12**：输入假设太乐观 —— 校验工具的边界行为、参数的多种写法、缓存目录的时效性。
- **坑 13 / 16 / 17 / 18**：**"变量收集"族**，症状都是**变量静默为空**，排查时先 `echo` 中间变量（引号污染 / 分隔符切不出多行 / 块内 call 标签失效）。
- **坑 14 / 15**：**自调用族** —— cmd 不允许 `.bat` 在执行中再进自己，也不允许不经 `call` 进别人。
- **坑 19 / 20**：**非 ASCII 与转义族** —— 中文进 `.bat` 任何位置都会炸，反引号里未转义的元字符会截断命令替换。
- **坑 21 / 22**：**"预检把好环境判成坏"族** —— `if exist "\\.\COMx"` 恒假、PATH 上的异族同名工具链。**预检宁可少判也不要误判**。
- **坑 23**：**"控制流收尾"族** —— `call :label` 是**返回**不是**终止**，收尾动作抽成子例程时要把 `exit /b` 留在调用方。手法：跑一次成功路径，看有没有 FAIL 混在里面。
- **坑 24 / 25 / 26**：**"脚本搬家 / 目录推导"族**，症状都伪装成"工具有问题"（依赖全缺失 / 源码找不到 / 子脚本不存在）。**动手前先 `echo` 出 `%~dp0`、`%PROJ%`、`%BATDIR%` 三个值。**
- **坑 27 / 28**：Edit 工具的行尾副作用、**"插值即执行"族**（静默多执行一条命令，**静态检查抓不到，只有真跑一遍并逐行读输出才能发现**）。
- 凡是要在 `.bat` 里调 PowerShell，优先选**无管道、无嵌套块**的写法，比事后调转义省事。

## 三、一键脚本落地规范

### 3.1 依赖预检（"缺什么一次列全"）

1. **抽出唯一环境脚本**，被所有脚本 `call`（**不要 `setlocal`**，否则变量传不出去）。产出统一变量。解析顺序：显式覆盖 → 标准安装位置 → 旧布局兼容 → PATH 回退。
2. **预检用"先赋值、后计数、再逐行打印"三步**（坑 17）：
   ```bat
   if not defined AVR_CC set "M1=  [REQUIRED] avr-gcc.exe  C compiler missing"
   if defined M1 set /a MISSING_N+=1 & set "MISSING_!MISSING_N!=!M1!"
   ...
   for /l %%i in (1,1,%MISSING_N%) do echo !MISSING_%%i!
   ```
   每个缺失项**自带修复命令**。
3. **区分 REQUIRED 与 NOTE**：只影响部分能力的依赖不要一票否决（如编译只需 gcc / objcopy / size，**缺烧录工具不阻塞编译**），只打 `[NOTE]`。一刀切会让"只想编译"的用户被迫装全套。
4. **失败前不产生副作用**：烧录前预检不过时明确打印 "the board was NOT touched" 并 `exit /b 1`。
5. **包目录兼容扁平 / 嵌套两种布局**：`packages\<pkg>\bin\` 与 `packages\<pkg>@<版本>\<版本>\bin\`，**先探直接子目录、再探深一层**（顺序反了会静默命中没有目标 exe 的兄弟目录）。
6. 工具链的**语义兼容性**不能靠"文件存在"判定（坑 22）：判"这一组工具是不是同一族"，而不是"名字对不对"。
7. 拿不到真实退出码时：Bash 工具里 `$?` 可用；MSYS 会把某些退出码映射成 255，但**脚本自身 `exit /b` 的值是对的**，验证以脚本打印的 `[OK]/[FAIL]` 分类为准。

### 3.2 失败处理

- **单一失败出口** `:fail`，靠 `goto :fail` 到达（绝不靠顺序执行落进去），所以它永远在**顶层**运行 —— 那里 `!VAR!` 与文本里的括号 / 引号都安全。
- 失败前设 `FAIL_STEP`（形如 `3/5 <步骤名>`）、`FAIL_REASON`、可选 `FAIL_HINT1/2/3`，`:fail` 里统一打印。`FAIL_STEP` 给默认值以防漏设。
- 每条 hint 给出**下一步可执行命令**，不要只描述现象。
- **同一个非零退出码要按上下文给出不同原因**：如构建失败时，若此前检测到运行实例占用则报"文件被锁 + 怎么停"，否则报"编译错误 + 怎么复现"。
- 退出码统一：成功 `exit /b 0`，失败 `exit /b 1`；提供 `--no-pause` 供 CI 使用（pause 前先判断开关）。

### 3.3 PAUSE 是**交付契约**，不是调试残留

**子例程签名只等按键，不带退出码**（坑 23）：

```bat
call :pause_exit          REM 只暂停；内部 exit /b 0
exit /b <code>            REM 这一句才真正结束脚本并返回码
...
:pause_exit
if defined NOPAUSE exit /b 0
echo.
echo Press any key to close this window . . .
pause >nul
exit /b 0
```

- **每个**退出点都要遵守：正常结束、usage、参数错、预检失败、编译失败、烧录失败，一个不漏。
- 打印**明确文案**再 `pause`，不要裸 `pause` —— 用户截图 / 汇报时能一眼看出这是"正常收尾"而非卡死。
- **串联调用时只保留最外层一次暂停**：

  ```bat
  REM 父脚本（在工程根）
  set "BATDIR=%~dp0"              REM <- 必须在 shift 之前捕获！见坑 24
  set "SCRDIR=%~dp0scripts\"      REM <- 工作脚本目录，见坑 26
  call "%SCRDIR%build.bat" --no-pause
  call "%SCRDIR%flash.bat" %PORT% --no-pause

  REM 子脚本（在 scripts\）开头
  set "BATDIR=%~dp0"              REM <- 同样必须先捕获
  set "NOPAUSE="
  if /i "%~1"=="--no-pause" set "NOPAUSE=1" & shift
  call "%BATDIR%<env>.bat"           REM <- 用 %BATDIR%，不是 %~dp0
  ```

  验证手法：外层调用 `grep -c "Press any key"` **必须等于 1**，子脚本 `--no-pause` 调用**必须等于 0**。嵌套没抑制，用户点一次会连按三次回车。
- **位置约定**：**入口脚本放工程根目录**（双击入口），**其余脚本放 `scripts\` 子目录**；环境脚本放 `scripts\` 内并由它统一推导工程根：

  ```bat
  set "PROJ=%~dp0"
  for %%s in ("%~dp0.") do if /i "%%~ns"=="scripts" (
    for %%d in ("%~dp0..") do if exist "%%~fd\src\main.cpp" set "PROJ=%%~fd"
  )
  pushd "%PROJ%" >nul 2>nul & set "PROJ=%CD%" & popd >nul 2>nul
  ```

  （判自身目录名读 `%~dp0.`，不是 `%~dp0..`；用 `%%~f` 拿规范化父目录；用工程标记文件兜底。）

### 3.4 依赖自举：缺依赖时脚本自建环境，但**必须先问**

- 探测时把**第一个「能跑但缺依赖」**的候选留作 `BASE_PYTHON`（`if not defined BASE_PYTHON set …`，第一条胜出），它只用来建 venv。
- `set /p` 问 Y/N；**只认显式 `Y`**，其余输入（**含 EOF**，即 `./x.bat < /dev/null`）一律走原失败路径 ⇒ 提示**既不会挂死也不会被误答**。必须在真机上验两种路径：EOF 走拒绝、管道送 `Y` 走接受。
- 装完**重新走一遍同一个探测**再继续；失败要说清 `.venv` 已存在但不完整（"信任目录名"正是探测要防的事）。
- 所有失败路径共用一个打印手动修复的子例程；手动命令**指向 requirements 文件**（`-r`），不要在那里再抄一份包名。
- **依赖清单只能有一个出处**。`.bat` 解析不了 requirement 行 ⇒ 它的 import 探测行仍是副本，用一条**静态测试**钉住：声明的每个包都要被探测，或**豁免须有出处**（"A 由 B 担保"要对着 `importlib.metadata.requires("B")` 验）。
- dev 依赖要**装齐**（含 test runner 等），因为 launcher 自己会把 `python -m pytest -q` 当下一步命令交给用户 —— 装不全就是把一句假话交给用户。
- 顺带：`import a, b, c` 只报**第一个**失败 ⇒ 报错文案说"缺依赖"时先逐包核对到底缺几个（实测 5 个里只缺 1 个）。

### 3.5 硬编码设备索引是事故源头

真实案例：脚本默认 `dev index = 1`，但本机只有一个设备 0 → 源元素启动失败 → agent 直接退出 → 下游无发布者、播放端连空路径，**现象是"整条链都不工作"，实际只是第一环断在索引上**。

正确做法：默认值取最通用的 `0`，并在拉起前先枚举可用索引做校验，不在列表里就回退到第一个可用值并打印 `[AUTO]` 提示；枚举失败（无设备 / 工具不在 PATH）则保留原索引并打 `[note]` 交给后续诊断，**不要静默吞掉**。
