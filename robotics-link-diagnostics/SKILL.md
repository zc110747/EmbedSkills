# robotics-link-diagnostics · 上位机 ↔ 机械臂后端链路

## 何时用

- **字节/舵机层**：串口文本协议、固件回执、开环无回读、串口独占、上电复位吞命令。
- **关节级层**：TCP / WebSocket 上的 JSON Lines、状态帧 `origin`、命令门控与 latest-wins。
- **服务端加入口**：新协议/新传输/新网关接进来，或让外部客户端读当前状态。
- **验收**：e2e 全绿但怀疑结论，或出现与代码无关的假 FAIL。

## 核心知识点

**先分层再推理**：舵机/字节级词汇由**固件**实现；关节级词汇由**上位机翻译层**合成，
固件可能根本没有。未识别的动词只原样转发、不合成回执 ⇒ **无外部动作时链路本来就该静默**。

**谁引起、谁跟随**（状态帧 `origin`）：

| `origin` | 含义 | 页面行为 |
|---|---|---|
| `command` | 本页自己发的命令 | 不跟随 |
| `device` | 设备侧自主变化 | 跟随 + **抑制回发** |
| `external` | 另一台上位机经第三方入口下发 | 跟随 + 抑制回发 |
| 未知/缺失 | —— | 降级按 `command`（宁可少跟随） |

来源必须**随命令同行**，不能等状态帧到了再从"在途命令"里取 —— 回执一到就清空了在途记录。
外部入口要在协议里标注身份；借用"本页命令"身份 ⇒ 对端指令侧停在旧值，用户下次动自己的控件
会把**整组旧指令**下发，真机跳回旧位姿。

**门控**：在途 / 待发两槽 + latest-wins（尾沿补发）；"让位 ≠ 丢弃"，被让位的意图只在
真正发送那一刻取值。不排队、不周期轮询 —— 轮询挤占带宽与门控窗口，交互回执永远在追赶历史。

**入口分层**：新入口只当 adapter —— 解析 → 调**同一个**控制器路径 → 声明自己的来源身份。
不得绕过控制器直连设备，不得自造限位/尺寸/标定，不得在入口层做 IK/FK/坐标变换；
"读当前 → 算目标 → 下发"必须原子。

## 判据与反模式

| 判据 | 可信度 |
|---|---|
| 固件自报的**独立丢字节计数** | ★★★ 一票否决 |
| 命令回读确认"目标已被接受" | ★★★ |
| 脚本的"发送 vs 回执"对账 | ★ 易被工具自身缺陷污染 |

- **链路层全绿 ≠ 物理到位**：无位置反馈时状态是固件内部目标值（开环），物理层只能靠相机等外部真值。
- **"能驱动" ≠ "对端界面显示对了"**，两条独立断言。
- **拒绝必须可观测**（原因码 + 当前值）；被拒后本地目标必须回滚，否则每帧从越界值继续累加 ⇒ 完全不动且日志无错。
- **禁止自证**：几何/坐标换算不能拿自己的实现当证据；用冻结基线 + ≥3 条独立实现互证，容差按对象登记、未登记即报错。
- **测试必须能红**：恒假的检查会把"我没查"伪装成"我查过了"。
- **跨链路配置不能直接复用**：方向/单位/标定常含某一层的补偿，直接搬会让两种模式行为相反且都不报错。
- **链路不对称要登记成"设计"**：同一串字节在不同链路可有不同语义与回执类型，判据是"它由谁发出"。
- **进程活着 ≠ 服务在服务**：断言存活要打端口/健康检查，不要数进程。
