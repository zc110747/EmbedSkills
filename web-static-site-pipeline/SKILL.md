# 静态内容站的构建 / 校验 / 监听流水线

内容源（Markdown）→ 生成物（HTML）→ 部署（GitHub Pages 项目子路径）的一整套约定：
哪些文件是源、哪些是产物、怎么证明构建没走样、以及"改了却没生效"的三个真凶。

## 何时用

- 给纯静态站**新增内容**（新文章 / 新页面），或搭建同类的"内容源 + 构建脚本"站点。
- `build` 跑完 **exit 0 但产物不对**，或校验器报出一堆 **假 FAIL**。
- 「**代码明明改了，手机上还是旧样子**」——先按本文的缓存章排查，别改代码。
- 需要**可复现构建**的证据（同一输入两次构建逐字节一致）。

## 目录职责（先分清源与产物）

| 角色 | 典型位置 | 纪律 |
|---|---|---|
| 唯一维护源 | `content/*.md` | 只改这里；产物永不手改 |
| 生成物 | 根 `index.html` + `src/*.html` | **必须提交**（Pages 以仓库根为站点根，没有构建步骤可言） |
| 静态资产 | `assets/`（CSS/JS/图标） | 随仓库提交；改完要重跑构建刷指纹 |
| 外部产物 | `sources/*.wav` 之类 | 由外部工具写；构建只**引用**，缺失只警告不失败 |
| 工具 | `scripts/{build,validate,watch}.py` | 只用标准库；不引框架、不联网 |

## 核心知识点

| 知识点 | 结论 |
|---|---|
| 永久 ID | 编号就是身份：四位补零、超四位不截断；**编号 / 文件名 / front matter 三者必须一致**，不一致直接报错而不是猜 |
| 文件名纪律 | 只用 ASCII、无空格无标点（它同时是 URL 片段与音频名）。撇号会同时引出 percent-encoding、git 引号、HTML 转义三层麻烦 ⇒ 正文里保留原字形，文件名去掉 |
| 可复现 | 「输入不变 ⇒ 字节级一致」。判据不是跑通，而是**重构建到临时目录逐字节比对**；任何时间戳/随机序都会破坏它 |
| 内容指纹 | CSS/JS 的 URL 挂 `?v=<sha256 前 8 位>`；**只按文件内容算**（别掺 mtime，否则破坏可复现） |
| Pages 缓存 | 静态资源回 `Cache-Control: max-age=600`，HTML 也一样 ⇒ 只改内容不改 URL 时，手机最长 10 分钟吃旧文件（已因此误判过「修复没生效」） |
| 改资产的连带 | 改了 `assets/` 必须重跑构建，否则页面里的 `?v=` 落后于磁盘上的实际文件 |
| 校验分支 | 断言要按**页面能力**分叉：有 X 才查 X 的细节，没有 X 就只断言 X 的类名/字段不出现，否则拿到空集合 → 假 FAIL |
| 别用宽字符串判"没有" | 判「页面上没有某控件」不能用 `'data-action=' not in html`——其它区域（含题目区）也带这个属性，会假失败。要查**该控件专属的类名/属性名** |
| watch 语义 | 新增/删除会改相邻页的导航 ⇒ 监听到变化**全量重建**，不做单页增量；源写坏只报错不退出（保持监听） |
| 分组 | 按固定号段（如每 100 号一组）分组，**只输出有内容的组**，首组默认展开 |
| 空值兜底 | 百分比/汇总一律防除零；总数取自真实数据而不是硬编码 |

## 「改了没生效」三步定位

1. **先验部署物**：远端分支与 HEAD 是否齐平、线上文件字节数是否等于本地。
2. **再验缓存**：看响应头 `Last-Modified` 与 `Cache-Control`，核对用户看到的时间点。
3. **最后才怀疑代码**：用 headless 浏览器对**线上真实 URL** 量一遍。

顺序反了会把时间全花在改没问题的那段代码上。

## 判据与反模式

- 构建成功 ≠ 产物正确；**生成物里能被断言的字段**才是判据。
- 不要为了"让校验过"去改断言，先确认是断言错了还是产物错了。
- 构建脚本职责单一：不生成音频、不调外部 TTS、不转码、不联网。
- 手改生成物、或把产物当源再改，会在下一次构建被覆盖 —— 只会浪费一轮排查。
