# 坐标映射与"多轴"独立性

面向：把检测结果映射成若干"逻辑轴"（左/右、上/下、前/后…），再拿这些轴做交互或做方向标定的场景。

---

## 1. 三个"轴"可能出自同一个原语 —— 那它们天生不独立

一个很常见的映射写法是：从一个检测框直接算出三个逻辑轴。

```
x = (x1 + x2) / 2 / 宽           帧中心，横向
z = (高 − (y1 + y2) / 2) / 高     帧中心，纵向
y = sqrt(框宽 × 框高) / 高        框的尺寸（几何平均）
```

一个矩形**只有 4 个自由度**（中心 2 + 边长 2），却被压成 3 个输出。
⇒ **三者从定义上就不可能独立**：目标每动一次，中心和尺寸必然同时变。

是否"够用"是**经验问题**，必须实测，不能靠直觉。

## 2. 判据：先测相关矩阵，再设计多轴交互

在写任何"三个轴分别控制三件事"的代码之前，先做两件事：

1. **同一帧集**上算完整相关矩阵（不要分几次跑、不要用不同子集 —— 子集错配本身就能造出假差异）。
2. 对运动向量做 PCA，看**方差占比**：

| 观测量 | 判读 |
|---|---|
| 两轴 `\|corr\| ≥ 0.6` | 两轴在讲同一件事，不能当成两个维 |
| PC1+PC2 ≥ 90% | **有效自由度只有 2**，第三个方向基本不存在 |

实测一例（两次互相独立的录制，结论一致）：`corr = +0.837 / +0.717`，`PC1+PC2 = 94.7% / 92.2%`。
**两次独立录制复现才算结论**，单次录制可能是操作者恰好只做了一个方向的运动。

## 3. 耦合是"透视"还是"取框方式"？—— 排除法

第一反应通常是"框把不该框的东西（手臂/背景）框宽了"。**可以证伪**：
用一个**只含目标自身**的量（关键点导出的尺寸 / 刚性部件间距）重算同一对相关系数。

- 若换掉后相关系数**几乎不变** ⇒ 耦合来自**几何（透视）**，改公式、改配置都无解。
- 若显著下降 ⇒ 是取框方式的问题，改映射即可。

实测：换成只用关键点的尺度代理，R² 只从 0.70 降到 0.54~0.61（约 **15%**）⇒ 主体是透视。
根因是**相机光轴不垂直于目标的运动平面**：目标"抬高"的同时也"靠近"，于是两个物理动作在图像上不可分。

## 4. 铁律：相关系数只能"同对比"，否则结论是垃圾

**必须比较同一对量。** 一个真实的错误：

> 拿 `corr(轴A, 轴B) = +0.837` 去比 `corr(候选量, 其它量) = −0.492`，
> 得出"换候选量可把耦合砍半"。**这两个不是同一对量**（配对、分母都不同），比较无意义。
> 正确的同对比是：`corr(轴A, 轴B)` 与 `corr(候选量, 轴B)`。

⇒ 凡是要用相关系数支持"换方案更好"，写成对照表，**两行必须是同一个第二变量**。

## 5. 维度塌缩是配置修不了的，修法可能在机械层面

轴映射通常带符号/来源两种配置（`invert_x/y/z`、深度来源二选一）。
当问题是**维度塌缩**（两轴讲同一件事）而不是**方向反了**时，这些配置**一个都救不了**。

正确响应：

1. 明说"该轴在本挂载下不是独立观测量"，把**耦合矩阵**本身作为实验产出记录下来。
2. 给出**机械层的判据**：调整相机朝向使光轴垂直于目标运动平面，然后重跑同一脚本；
   验收阈值就是那个相关系数应显著低于 0.6。
3. 方向标定脚本加一个**反向 gate**：相关系数掉到阈值以下时返回非零 ——
   这个 gate 保护的是一个**负面结论**，所以"变好"意味着**文档过期**，不是代码回归。

## 6. 负面结论是合法产出

方向实验的目标是"确定每个轴的符号"。做下去发现某个轴不可测，**这就是实验结果**，
不要为了凑出一个结论去伪造可测性（例如在已知有问题的挂载上强行定符号）。
把"为什么不测/测不了/要改什么才能测"写进文档，比一个编出来的符号有价值得多。

## 7. 两个容易漏的接口事实

- **检测标志位为假时，坐标常被清零**（如 `detected=false → position=[0,0,0]`）。
  ⇒ 分析与前端**必须按标志位门控**，否则目标一离开画面就被读成"一次巨大位移"。
  分析脚本里应显式丢弃这类帧，而不是指望下游过滤。
- **归档导出的字段集可能小于实时帧**（例如实时帧有通用对象数组和画面宽高，导出只剩专用块）。
  ⇒ 需要"反算"某个派生量时，先确认归档里有它的**输入**；
  没有就必须改用归档里确实存在的量（关键点等）重新推导。
