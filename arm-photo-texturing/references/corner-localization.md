# 2.8 ★★★ 定位四角：三种方法，按可靠性排序

**共同难点**：目标板与相邻件**物理连通**（螺栓相连）⇒ 整图分割必然把整条臂圈进来
（见 §2.5「白卡做不到」）。

## 方法 1（首选）：**模型投影给初值 + 图像梯度吸附**

单靠投影不够（整臂剪影 IoU 只到 43% ⇒ 误差几十像素），单靠目视也不够（±15px）。
**但两者合起来可行**：投影给"大致位置与走向"，梯度吸附给"像素级贴合"。

```python
gy, gx = np.gradient(gray); gm = np.hypot(gx, gy)      # 梯度幅值
def quad_score(q):                                      # 沿四边采样取均值，**最大化**
    return np.mean([sample_line(gm, q[i], q[(i+1) % 4], n=70).mean() for i in range(4)])
# 参数化：平移 (dx,dy) + 缩放 k + 旋转 dθ（绕四边形中心），粗→细两轮
# 加很弱的正则 −0.004·(|dx|+|dy|)/10 抑制大平移，防沿"无边段"滑走
```

实测（`snap_quads.py`）：边分 8.78→**19.30** / 4.65→**18.74**，且**长宽比精确吻合真值**
（96.2×323.7px = **3.37** vs 3.36；75.8×286.4px = **3.78** vs 3.78）。

> **长宽比同时精确吻合，是这次吸附可信的主要依据** —— 单看"边分变大"还不够，
> 因为沿一条长边平移也能提分。**必须用长宽比当独立判据。**

## 方法 2：**窄带 PCA**（无模型 / 模型不可信时的兜底）

**核心洞察**：**板本身是一条直带。**
⇒ 沿板的长轴开一条**窄带**（旋转矩形，半宽 ≈ 板半宽），**只取带内暗像素做 PCA**，
用主轴方向的极值给出四角。带外的一切（相邻板、螺栓、立柱、平行杆、线缆）
被**结构性排除** —— 这是绕开"整条臂是同一连通域"的正解。

```python
def band(shape, p0, p1, hw):
    ys, xs = np.mgrid[0:shape[0], 0:shape[1]]
    d = np.array(p1, float) - np.array(p0, float)
    L = float(np.hypot(*d)); u = d / L; n = np.array([-u[1], u[0]])
    rel = np.stack([xs - p0[0], ys - p0[1]], -1).astype(float)
    t = rel @ u; w = rel @ n
    return (t >= -6) & (t <= L + 6) & (np.abs(w) <= hw)
# mask = 前景 & band(...)  →  PCA  →  主轴极值四角
```

**四个要点**：
1. **端点仍来自目视**（±15px）—— 窄带只用来**限定范围**，四角仍由带内像素客观给出。
2. **用长宽比自检**：算出的 `长/宽` 应接近 `geometry.size` 的长宽比。
   实测大臂 3.69 vs 真值 3.36 ✓；小臂 2.76 vs 3.78 ✗（说明带里混进了腕座 ⇒ 收窄带/挪中心线）。
3. **最后一步永远是"四角向心收缩 3~10%"**：自动/半自动四角总会让边缘夹进 1~3px 背景。
4. **目视复核的是"纹理"，不是"框"**：框贴合 ≠ 纹理干净 —— 污染可能横穿框**中部**。

## ⚠️ 方法 3（**不要**单独用）：纯目标函数搜索

**欠定**。只优化"框内暗色"时会把几块板挤进底座暗区拿到 **97.4% 假性满分**
（而 `oy` 已在画面外）。必须加"板间空隙亮色"项 + "空隙 <30px 判 0"才勉强可用。
详见 §2.5「搜索区间贴边」与「什么时候该放弃自动投影」。

## ★★★ 板是镂空的 ⇒ 必须做**孔洞掩膜**（三层判据，缺一不可）

实板是**镂空桁架**，而模型的 `*_vis` 通常是**实心 box**
⇒ 照片里的"孔洞 + 透过孔洞看到的背景 / 被四角框进来的相邻件 / 线缆"烘到实心盒上
会把背景色带进去，**比不贴更假**。**这不是调四角能解决的。**

**做法：把纹理里的"非板面区域"填成板面材质。** 三层判据，每层都对应一个真实踩过的坑：

| 层 | 判据 | 不加会怎样 |
|---|---|---|
| ① **连通性** | 亮区**接触纹理边界** ⇒ 填（板外）；**被板面完全包围** ⇒ 再按面积定（小 = 表面细节保留，大 = 镂空填） | 纯亮度阈值会把板面上的**螺栓一起填掉** |
| ② **形状** | 要保留的亮斑还须 bbox 填充率 ≥ 0.60 且长宽比 ≤ 2.0 | 只判面积 ⇒ 被暗区包围的**线缆小段**也被当螺栓留下 |
| ③ **色差** | `R − B > 15` ⇒ 填 | 暗线缆的**亮度低于阈值**（实测中位 32 vs 阈值 60）⇒ 只判亮度**永远去不掉** |

```python
face   = gray < thresh                      # 板面（实测阈值 60 落在双峰谷底平台）
border = flood_from_image_border(~face)     # ① 接触边界 ⇒ 板外
# ② 被板面包围的：面积小 + 接近圆/方 ⇒ 螺栓，保留；其余填
# ③ 暖色（R−B>15）无论明暗一律填 —— 暗线缆只有这一条能抓到
out[border | big_enclosed | warm] = face_median_color
```

**填充色必须取"板面像素的中位色"，不要写 `(0,0,0)`**：实测板面是 `RGB(1,1,20)`
—— 近黑**带蓝**，填纯黑会在板面上留下肉眼可见的色差补丁。

> **动手前先量一次"板面 vs 非板面"的亮度直方图。** 实测它是**双峰**（板面峰 0~20、
> 非板面峰 110~125、中间 30~90 是谷）⇒ 阈值取谷底平台上很稳健。
> 若直方图**不是**双峰，说明四角没框住板，此时调阈值是白费力气。

> ⚠️ **更正一条旧结论**：曾总结"线缆悬在板前 ⇒ 软件无解 ⇒ 必须物理拨线"。
> 4× 放大后看清：**线缆在板的背面，是从镂空里透出来的，并未遮挡板面**。
> ⇒ **下"软件无解"这种结论前，务必先放大到能分辨层的程度。**
> 另外，"用饱和度分离线缆"也不成立：板是**近黑**（V≈0.1），微小 RGB 差被放大成大 S
> （`(8,7,23)` 算出 `S=0.70`）—— **近黑区饱和度是噪声，不是特征**；判别要用**色调 + 亮度**。

## ★★ 判「四角贴合吗」：只有一条**定义上无歧义**的判据 —— 四条边的亮比例

框精确贴合板 ⇒ 纹理四条边**全落在板上** ⇒ 每条边的"亮像素比例"应接近 0。
实测某双臂板：上 45% 下 18% 左 31% 右 46% ⇒ **框比板大**（而且两块板偏心方向还相反）。

```python
edge = [bright[0:3, :].mean(), bright[-3:, :].mean(),
        bright[:, 0:3].mean(), bright[:, -3:].mean()]   # 上 下 左 右
```

**为什么不用"框外面积占比"**：我曾加过一个"接触边界的亮区（= 框外） vs 被包围的亮区（= 镂空）"
二分统计，看到"框外 29% / 镂空 0%"就断言"框比板大 30%"。**但镂空若开口到板端，
同样会接触纹理边界而被算进"框外"** —— 两种解释都能套上同一个数。
⇒ **当两种解释都能套上同一个数时，该换判据，而不是换参数。**

> ⚠️ 这条偏差**未必阻塞**：若板面几乎是均匀的深色（实测亮像素仅 **<1.3%**），
> 四角偏差主要影响"表面细节（螺栓）的位置比例"，不是"整块板贴错"。
> 这时**先把它贴上去看效果**，比继续抠四角更有信息量。
