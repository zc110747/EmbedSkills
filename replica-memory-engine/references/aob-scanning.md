# AOB 签名扫描

> 三个真缺陷都在这里：**通配没展开**、**越界读静默跳过**、**假命中**。
> 三条都会让"一条都扫不到"或"扫到错的地方"，且都不报错。

## 1. 签名解析：通配必须按字节数展开

**规则**：一个占位 token 含几个字符就代表几个**字节位置**。

| 写法 | 含义 |
|---|---|
| `??` | 1 个任意字节 |
| `????????` | **4 个**任意字节（常见于 rip 相对位移！） |
| `*` / `**` | 按数据源语义规定（有的=任意长，有的=1 字节）——**必须核清** |
| `sN` / `sN.M` | 版本常量占位，扫描时视作通配 |

```text
❌ 错误实现：遇到问号串就 push 一个 Wildcard token
   → "48 8B 3D ???????? 49 8B D8 ..." 变成 长度 3+1+4+... 
   → 整体左移 3 字节，把固定字节当成了别的固定字节

✅ 正确实现：逐字符展开
   for each token:
       if token 全是 '?': emit (token.Length / 2) 个通配（若是 ?? 成对）
       else: emit 1 个固定字节
```

**为什么这个错最阴**：如果**生成侧与扫描侧共用同一套错规则**（例如同一个脚本生成桩 + 同一个解析器扫描），
两侧互相印证、自检全绿 —— 只有对着真实目标才会暴露。

## 2. 匹配：锚点预筛 + 全量校验

```text
① 锚点预筛：取「最长连续固定片段」的首字节作快筛
   （代价最低，能快速排除绝大多数位置）
② 全量校验：锚点之外的**每一个**固定字节都必须相等
   ← 缺这一步，短签名（固定字节只剩 5 个）会在内存里命中一大片
```

**判据**：全量校验通过才算命中。仅锚点通过 = 假命中。

## 3. 分块扫描：越界钳制 + 逐页容错

```text
问题：为处理「签名跨块边界」需要多读 (签名长度-1) 字节
     → 末块会越界到模块尾之后
     → 那块内存可能是 MEM_FREE / PAGE_NOACCESS
     → ReadProcessMemory 返回 ERROR_PARTIAL_COPY(299)
     → 整块读取失败
     → 调用方 continue 跳过 → 一条都扫不到（且无日志）

修法：
  ① 读取窗口钳制在 [模块起点, 模块起点+大小) 内
  ② 逐页读，单页失败就跳过该页（而非整块失败）
  ③ 命中区间必须「整段可读」才算有效命中
  ④ 记录失败页数并在结果里体现（不要静默）
```

**指纹**（怎么认出是这个问题）：
- 目标进程自己报告"桩在内存里"（或另一条独立通道证实），但扫描 **0 命中**。
- 用独立探针（如 ctypes 直接调 `ReadProcessMemory`）精确读 `[0, size)` **成功**，
  读 `size+小偏移` **失败 err=299**。

## 4. 零命中排查顺序

1. **签名本身对不对**：把签名按通配展开后的长度/prin表格打出来，人工核对。
2. **窗口钳制**：模块内能读到多少？模块尾之后是什么状态？
3. **是否加了全量校验**（假命中不算命中，但也要确认不是过严）。
4. **模块选对没**：目标进程可能有多个同名/相似模块（32/64 位、不同路径）。
5. **是否被反作弊/保护拦**：读权限被拒绝。
6. **版本对不对**：签名是版本相关的，换个版本自然不命中——这时应报"位点不存在"而非"接线坏了"
   （见 `replica-mock-harness` 的判据分类纪律）。

## 5. 版本占位

- `sN` 类占位：扫描时通配，**真实值**由"版本表"或**运行期从命中处反解**提供。
- 反解做法：命中后读该位置的字节/立即数 → 得到真实常量 → 供后续断言与写回校验使用。

## 6. 自检（强烈建议）

在**已知答案**的环境（自建桩，见 `replica-mock-harness`）里断言：
- `hit == 我们自己布桩的地址`（而不是"命中了某处"）。
- 通配展开后的长度 == 数据源声明长度。
- 扫描耗时可接受（锚点预筛生效）。

**这是唯一能在没有真目标时抓住"通配没展开"的手段。**
