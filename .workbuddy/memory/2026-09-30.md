## 增设 C 代码规范规则 + 同步系统侧 4 项新增（commit cbc5c14）

### 用户新增的两条规则（本次主要目的）

**规则 1 · 文件级静态变量合并成结构体**
- 同一文件内、属于**同一件事**的多个 `static` 变量，合并为一个结构体实例。
  收益是"后期统一管理"：初始化 / 复位 / 快照 / 调试观察只点名一处。
- 结构体按**所在文件 / 功能**命名（`link_info_t`），**不是** `GLOBAL_INFO` / `xxx_misc_t` 这种筐。
- **判据**：字段是否会被同一段代码"一起初始化 / 一起复位 / 一起打印"？
  答不上来的字段就不属于这个结构体——**禁止把所有变量塞进一个**。

**规则 2 · 对外访问粒度**
- 暴露 1~2 个 → 对**单个变量**暴露读/写接口。
- 暴露 ≥3 个或需整体快照 → 对**结构体**暴露指针接口。

**规则 3 · 第三方边界**
- 规则**只约束自研代码**；`Drivers/`、`third_party/`、HAL/RTOS/中间件一律不动。
- 定位到第三方库的问题 → **只上报不自行改**：现象 + 根因判断 + 影响面，由用户决定改法。

### 用户示例里我指出并修正的两点

1. **`static GLOBAL_INFO *get_global_info(void)` 的 `static` 是错的** ——
   `static` = 仅本文件可见，而它被标注为"对外访问接口"。两者互斥，
   本文件内调用正常会让人误判已暴露，换文件即 `undefined reference`。已在 skill 中写成硬要求。
2. **成员名保留 `s_` 前缀已冗余**（`g_global_info.s_link`）—— 建议去掉，

3. 我另加了一条：**只读就返回 `const` 指针**，否则等于把写权限一起放出去。
