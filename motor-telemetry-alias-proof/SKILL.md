# 读数一直跳：是旋转被欠采样、是噪声、还是饱和？

## 何时用

用户说这类话：

- 「没有负载 / 空载的情况下，PWM 值显示还在一直跳」
- 「这个波形怎么像噪声」「示波器上根本读不出来」
- 「数值在抖，是不是控制器不稳」

**先别改增益、别加滤波。** 跳动的量大概率不是一个标量，而是**旋转波形的某一相投影**，
再被遥测帧率欠采样。也可能它是**饱和钳位**（在 0/1 两个轨之间拍）。三种情况的修法完全不同。

## 第 0 步：先判断这个量是"标量"还是"旋转量的投影"

| 典型 | 本质 | 稳态行为 |
|---|---|---|
| FOC 单相占空比 `dutyA/B/C` | 旋转端电压矢量在 120° 三相上的**投影** | 正弦，`f_e = n_pp·ω/2π` |
| 单相电流 `Ia/Ib/Ic` | 同上 | 正弦 + 纹波 |
| `dq` 量 (`id/iq/vd/vq`)、调制比、转矩、转速 | 旋转坐标系 / 标量 | **直流**（才适合直接读数字） |
| 任何相位/角度量 | 斜坡 | 一直涨，正常 |

**只要它是"投影"，它就必须摆** —— 哪怕负载为零。此时唯一的问题是"遥测能不能跟上"。

## 第 1 步（决定性判据）：按相位分箱，看离散度塌缩

这是区分「旋转」与「噪声」的**唯一干净判据**，而且**不需要改采样率、不需要反混叠**。

原理：混叠打乱的是采样的**时间顺序**；但每个 `(θ, value)` 采样对仍然是该函数的合法采样点。
所以把样本按 `θ` 分箱后，箱内的散布只剩"真噪声 + 非理想因素"；箱间的差异就是信号本身。

```python
import math, statistics
NB = 36                      # 10° 一箱，够细也够样本
def bins_of(rows, ch, th_key="theta", nb=NB):
    b = [[] for _ in range(nb)]
    for r in rows:
        b[int(r[th_key] / (2*math.pi) * nb) % nb].append(r[ch])
    return b

def within_spread_ratio(rows, ch, th_key="theta"):
    bins = bins_of(rows, ch, th_key)
    within = [statistics.pstdev(b) for b in bins if len(b) >= 3]
    overall = statistics.pstdev([r[ch] for r in rows])
    return sum(within) / len(within) / overall
```

判读：

| 箱内/总体 | 结论 |
|---|---|
| **< 0.15** | 是该相位的**确定函数** → 抖动 = 混叠，**不是噪声、不是控制问题** |
| ~1.0 | 与相位无关 → 真噪声 / 真振荡，去查控制器或数值 |

同时用**箱均值**还原出波形形状（顺带验证正弦性、相位差 120°、偏置 0.5）：

```python
def half_swing(rows, ch, th_key="theta", nb=NB):
    ms = [sum(b)/len(b) for b in bins_of(rows, ch, th_key, nb) if len(b) >= 3]
    return (max(ms) - min(ms)) / 2
```

> 还要验 **θ 与机械角自洽**（本次：`θ_e == n_pp·θ_m`，偏差 0.0000°）。
> 若不自洽，说明快照内部不一致，先修那个，别往下走。

## 第 2 步：摆幅必须能用物理律解释——"空载"≠"零"

**最容易犯的错**：以为空载就没电压/没电流，所以读数应该是常量。

反例（PMSM/BLDC）：电机在转 → 有反电动势 → **逆变器必须输出反电动势电压**才能维持 `iq = 0`。
本次实测：空载 100 rad/s、4 极对，`|V_qd| = 4.90 V`（24 V 母线的 40.8%），
且对转速**严格线性**：

```
斜率实测 0.04913 V/(rad/s)  vs  理论 n_pp·bEmf0/kClarke = 0.04899   (+0.29%)
```

**做法**：扫两个自变量（转速、负载），看响应是否符合解析式。
对得上 → 物理正确，问题在**显示**。

## 第 3 步：用权威公式反算，闭合"输出 ← 输入"链路

证明"输出确实编码了指令"，而不是被中间某处改动过。做法是**从快照里的输出量反算输入量，
与快照里的输入量比**（复用上游/固件里那份公式，逐字移植，别自己重推）：

```
由 dutyA/B/C 反算实际施加的 αβ 电压 = 4.9022 V
指令 |V_qd|                       = 4.8969 V      →   +0.11%
```

比值在整个工作区间内都 ≈ 1（本次 5 个工况：0.9977 / 1.0006 / 0.9999 / 1.0001 / 0.9997）
→ 链路闭合，可以放心用这条公式解释现象。

## 第 4 步：算混叠比，给出"能不能读"的充要条件

```
f_signal   = n_pp · |ω| / 2π                  # 电频率
帧间隔 dt  = ???                               # ← 必须实测，见下面的坑
混叠比     = f_signal · dt                     # > 0.5 即欠采样；>> 1 则完全不可读
```

本次：`f_e = 63.66 Hz`（100 rad/s、4 极对），实测 `dt = 42–45 ms` → **2.7–2.8 电周期/帧**。
对比 25 rad/s 时 `0.69`，所以**低速看着不跳、高速乱跳** —— 这本身也是一条旁证。

### ⚠️ 坑：帧间隔必须**实测**，不能拿名义参数推

第一版实现拿 `speedScale / PUSH_HZ` 去算，结果 `speedScale` 这个字段**根本不在协议里**
（后端结构体有、序列化时漏了），读到 `undefined` → 回退 1 → **混叠少算一半**（显示 1.27 而非 2.55）。

**正确做法**：直接量相邻两帧的 `timestamp` 差。

```ts
if (Number.isFinite(this.lastTs)) {
  const dt = s.timestamp - this.lastTs;
  if (dt > 0) this.frameDtSim = dt;      // 实测：还自动包含服务端循环开销
}
this.lastTs = s.timestamp;
```

好处：不依赖任何名义参数，且**包含了真实开销**（本次名义 40 ms、实测 42–45 ms）。
在暂停/停止时 `dt <= 0`，保留上次的有效值，不要回退到常数。

## 第 5 步：别忘了查"饱和/钳位" —— 那是另一种"拍"

如果读数是在**两个极值之间来回拍**（比如 0.00 ↔ 1.00），那更可能是**饱和**：

```
m = |V| / (V_bus / 2)         # 调制比
m ≤ √2  → 线性区
m ≥ √2  → 过调制，占空比被钳到 0/1
```

本次最容易撞的组合：**12 V 母线 + 0.05 N·m 负载**（12 V 下执行器在 100 rad/s 只有
0.0549 N·m 能力，0.05 已占 91%）→ `m = 2.59`，duty = `0.000 / 0.461 / 1.000`，转速守不住。

**修法提示不是调 PID，是提示用户切 24 V 或减负载。**

## 修显示：加"抗混叠的标量"，别去骗原始波形

不要为了"好看"去改采样率或平滑——那会伪造数据。正确做法是**同时给出两类量**：

| 量 | 定义 | 特点 |
|---|---|---|
| **调制比 m** | `\|V_qd\| / (V_bus/2)` | 稳态**直流**，可读；随转速(反电动势)、负载单调 |
| **摆幅** | `m / (2√2)` —— min-max SVPWM 的几何关系（不是拟合！） | 直接给出"0.50 ± X"的直觉 |
| **f_e / 帧间隔 / 帧-电周期** | 说明**为什么**原始读数读不了 | 让用户自己判断 |
| 原始相占空比 | 保留为**波形通道** | 标注清楚，不当作数值读 |

> `duty p-p = √2 · m` 这条是**解析的**：用上游 SVM 公式数值扫描确认（`m ≤ √2` 内 p-p/m 恒为 0.7071），
> 实测偏差 0.4%。**不要把它当拟合系数用**，要在回归里断言。

## 交付前的回归清单（照抄改数字即可）

| 用例 | 断言 |
|---|---|
| 空载即真空载 | 转速 std ≈ 0、`\|torque\|` ≈ 0 |
| 分箱塌缩 | 箱内/总体 < 0.15（A/B/C 各一条） |
| 相位 | A→B ≈ ±120°、A→C ≈ ∓120°；`θ_e == n_pp·θ_m` 偏差 ≈ 0 |
| 物理律 | 摆幅/幅值对自变量**线性**，斜率对理论值 ±3% |
| 链路闭合 | 由输出反算 = 输入，±2% |
| 负载 | 幅值单调抬高；重载时钳位到轨 + `m > √2` |
| 混叠比 | 低速 < 1、高速 > 1（两个方向都要断言，否则测不出"为什么有时不跳"） |

**如实记录未归因项**：本次手推的 `vq = backEMF + R·iq/kClarke` 在空载吻合 -0.11%，
带 0.05 N·m 负载差 -3.8%。因为第 3 步已证明"施加 = 指令（0.11%）"，残差在**手推模型侧**，
所以在回归里**只打印、不断言**，并在注释里写清楚。**不要为了让表格好看去放宽阈值。**

## 顺带的通用教训：harness 必须自己建立前置条件

本次 UI E2E 硬编码 某端口，开发者自己的实例占着该端口时，测试会**静默连到他的会话**，
用他的母线电压和增益去断言 → 产出两个"看起来像回归"的假失败（12 V 母线导致限幅 0.0549
和加载后"未回归"）。修法：

1. **随机空闲端口**（`createServer().listen(0)` 取 port 再关掉）；
2. 前端支持 `?wsport=NNNNN` 覆盖端点（headless harness 才有办法指向私有实例）；
3. 子进程**秒退**即报"端口被占用"，而不是继续连到别人的进程上；
4. 绝不为了跑测试去 kill 用户正在用的进程。

> 遇到"测试失败但代码看着没问题"时，**先看测试连的是谁**。
