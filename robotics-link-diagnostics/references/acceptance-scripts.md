# 验收脚本与探针纪律

适用于**读数类 / 时序类**的 e2e 与探针脚本。这类脚本最常见的失败不是"代码坏了"，
而是**脚本自己造出的假 FAIL**（或更糟：恒真的假 PASS）。

## 1. ★★ 写验收脚本的 6 条通则（换项目仍成立）

1. **一条断言只证一件事**，否则失败无法归因。把并发类场景拆成
   "干净基线" / "正向并发" / "反向抢占" 三段 —— 混成一段会把"A 被 B 接管"误读成"A 失败"。
2. **脚本必须自己造出"可观测的位移"**，否则会把"本来就在目标位"读成"命令没被受理"
   （命令是**有限角速度逼近**：目标 == 当前位置 ⇒ **零位移 ⇒ 零状态帧** ⇒ 等收敛拿到 `NaN`）。
   下发前必须（a）选一个离当前位置 ≥ 阈值**且夹进限位内**的目标；
   （b）**已经在目标位就跳过**而不是判 FAIL。
3. **造前提的参数要从真值里挑，不能写死常量**。实测：写死"向下拨"，而该方向只有几度
   行程 ⇒ 第一次之后就被限位钳住，脚本报"没收到多帧上报"，
   **把限位造成的现象误报成上报机制的缺陷**。
4. **别把"正确的语义"写成断言**：命令之后设备又拨了 ⇒ 位置本来就该是"命令目标 + 拨动"。
   先写清"这一段证明什么"，再写断言。
5. **同一个量只能有一套口径**：脚本里的"一次拨动走多远"必须**实测**，
   不能拿标定系数反算 —— 那就是"第二处重算真值"。
6. **"进程已经跑起来了"比"二进制比源码旧"隐蔽得多** —— 启动器的陈旧闸门**管不到在跑的进程**。
   症状表现为"设备动了、页面不动"，而根因在**构建产物**。
   ⇒ 判"是不是产物陈旧"：**既不看源码时间、也不看进程启动时间**，
   直接**探二进制符号**（新引入的标识串在旧产物里 0 命中即确诊）。

## 2. ★★ 假 FAIL 的主要来源

- **测试必须能红**：新加的守卫要么先构造一个会失败的场景验证它能红，要么等于没加。
  ★ **恒假的检查比没有检查更危险** —— 它会**把"我没查"伪装成"我查过了"**。
  实测两处同源缺陷叠在一行（漏 `-E` ⇒ 正则元字符变字面量 ⇒ **恒不命中**；
  补上后又踩 `\b` 紧跟 `)` 失效）⇒ 端口预检**永远返回"干净"**。
  可靠写法：字段级比较（如 `awk '$4=="LISTENING"{…}'`），
  或**先拿"已知答案的探针文件"验一次工具语义**。
- ★★ **别拿"同义重写"当判据**：某个"是否在动"的指标若定义为 `滞后量 > eps`
  （即滞后量的另一种写法），那么"卡死"状态**永远不可能**出现。
  ⇒ 判据必须自己从**时间序列**得出：只有「命令已静止 ≥ 保持窗口」**且**「趋势不再下降」才判异常；
  **样本不足 / 仍在收敛**一律按"正常跟踪" —— **宁可提示"还在追"，也不误报异常**。
- ★ **趋势判定用四分位中位数**，不用首末值/均值：回推序列混有掉帧与量化台阶，
  **个别异常帧就能把结论翻面**，而"误报卡死"会把人送去查并不存在的问题。
- ★★ **探针的两类静默失真**：
  ① **读错表** —— 同页多张结构相同的表格，全局选择器会命中**排在前面**的那张
     ⇒ **必须限定作用域**；
  ② **滞后读数拆成多次往返** —— 慢环境里读到的是**已收敛值**，让"滞后瞬间"断言假 FAIL
     ⇒ **一次往返取齐所有量**。
- ★ **驱动量要按当前位姿反向选**（不要写死绝对值）：上一轮残留的位姿可能**正好就是**目标值
  ⇒"驱动后位姿不变"⇒ 判据假 FAIL。先读基线再决定方向。

## 3. ★★ 环境与状态卫生

- ★★ **e2e 必须隔离端口**，且**起服务与跑 e2e 必须在同一次调用里**
  （后台进程只活到本次调用结束）。
- ★ **跨批次状态残留**：上一批点过的模式会带进下一批 ⇒ **每批开头显式复位**。
- ★ **复用"上一个任务遗留的后端"会把"前提不成立"读成"代码回归"**：
  端口上若有上一轮遗留的**非干净**实例，某些行为变化是**正确的**
  ⇒ 每次 e2e 前必须确认后端处于**干净基线**。
- ★ **等待条件按"值"等，不要按"新消息条数增加"等** —— 源停住后永远不满足。
- ★ **分段用例必须显式建立前置条件，而不是写在注释里**：前一段若有**时间驱动**的动作
  （按真实 dt 积分的摇杆，"推 0.5s"到底走了多远逐次不同），后一段若依赖它的结束位姿
  就会**偶发 FAIL** —— 一次绿一次红，最容易被误判成"产品回归"。
  修法是后一段开头重新建立已知位姿，**并把它变成一条断言**。

## 4. 闸门类机制的证法：单测 + 脚本各证一半

- ★ **闸门用单测证、可观测后果用脚本证**：竞态/优先级类机制的时间窗口常常窄到脚本摸不着
  ⇒ 单测**直接构造在途态**（手工把"在途"和"待发槽"摆成想要的组合）；
  脚本只证"命令优先 + 被让位的动作没丢"。
- ★ **来源是否随命令同行**，只有"本页命令在途时外部命令进待发槽"这类用例能测出来 ——
  它专门覆盖"上下文在回执时被清空、尾沿补发拿错来源"。

## 5. 报错文案也算验收面

- ★ 被拒/被门控挡下时**必须可观测**（原因码 + 当前值 + 修法），否则客户端只会重试，
  把问题放大成"服务不稳定"。
- ★ 不同来源要走**不同日志文案**：把外部入口报成"设备自主变化（摇杆/手拧）"是**误报**，
  而日志面板正是排障时最先看的东西。
