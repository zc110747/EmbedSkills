# WebView 外壳：把网页装进桌面与手机

不复制站点内容，只做一个**可靠的容器**：网络在就打开网页，网络不在就说清楚为什么，
并且把网页里的本地状态镜像到设备上。桌面端与 Android 端的骨架可以几乎一一对应。

## 何时用

- 要把一个已存在的网页（线上或本地）包成桌面 / Android 应用。
- 现象：「**启动一片空白**」「弱网卡在加载中永不结束」「抓图抓到的是桌面不是我的窗口」。
- 需要让网页里的进度/设置落到**本地文件**，并能与网页端导出互相导入。

## 三态启动（核心模型）

```text
启动 → 启动页（品牌字 + 状态文字，先给用户一个"在动"的信号）
     → 初始化 WebView（失败 → 错误菜单，给出可执行建议）
     → 探网络（网卡状态 + 对目标站 6 s GET）
          ├ 离线 ────────────────────────→ 错误菜单「请连接网络，当前无资源」
          └ 在线 → 导航（25 s 看门狗）
                 ├ 成功 → 网页（此前网页容器一直隐藏，所以看不到半成品页面）
                 └ 失败/超时 → 错误菜单（含人话原因 + 重试）
```

**三态互斥**是这条流程的全部价值：任何时刻只有一个视图可见，网页在"确认真的能显示"之前绝不露脸。

## 核心知识点

| 知识点 | 结论 |
|---|---|
| 探网 | 不要只信"网卡已连接"；补一次对**目标 URL** 的短超时 GET（6 s），两者都过才导航 |
| 看门狗 | 导航必须设上限（25 s）。用**本次尝试的序号**判超时，否则旧的计时器会把新导航判死 |
| 失败原因 | 把平台错误枚举映射成人话（无法连接 / 域名解析失败 / 连接超时 / 证书无效），原样甩枚举等于没说 |
| 隐藏方式 | 桌面 `Visible=false`；**Android 必须 `GONE`** —— `INVISIBLE` 仍参与合成，WebView 的渲染表面会盖住启动页，表现就是"启动一片空白" |
| 注入时机 | 桌面用 `AddScriptToExecuteOnDocumentCreatedAsync`（**必须在导航前**）；系统 WebView 没有等价钩子 ⇒ 在 `onPageFinished` 探测存储，为空才写种子并 **reload 一次**（一次性守卫，防止死循环） |
| 注入内容 | 种子 + 钩 `Storage.prototype.setItem` + 定时轮询兜底（1.5–2 s）：网页可能有绕过 `setItem` 的写入路径 |
| 落盘 | 写 `.tmp` 再替换；损坏存档备份成 `…__corrupt-<时间戳>` 后重建 |
| 站内/站外 | `shouldOverrideUrlLoading`：同域留壳，外链交系统浏览器（否则用户在壳里越走越远，返回键语义也丢了） |
| 缓存目录 | WebView2 显式指定 user data folder（`%LOCALAPPDATA%\<app>\WebView2`）；别落在 exe 目录，装到 Program Files 后无写权限 |
| 运行时缺失 | WebView2 初始化失败要给出"装运行时 / 在浏览器中打开"这类可执行建议，而不是抛异常了事 |
| 登录态 | 壳里的 cookie / 存储与用户浏览器**不共享**，同一份数据的"两台设备"其实是两个容器 |
| 抓图 | 窗口被其它窗口遮挡时屏幕抓图拿不到内容 ⇒ 用 `CapturePreviewAsync` 直接导出渲染结果留证 |
| 进程回收 | 自动化里子树进程可能在工具调用结束后被回收 ⇒ 一次调用内完成「启动 → 截图 → 关闭」 |

## 验收（可自动化的部分）

| 手段 | 用途 |
|---|---|
| `--self-test` | 纯逻辑（ID 规整、载荷键序、落盘、坏数据备份）不开窗口跑完，进 CI |
| `--capture <png>` | 导航成功后导出一张图再退出，证明"壳里真的渲染出来了" |
| `--render-preview <dir>` | 启动页/错误菜单这类自绘界面离屏渲染成 PNG，不用等人盯屏幕 |
| 强制离线开关 | 环境变量或 intent extra，专门验证错误菜单；否则只能拔网线 |
| 真机 | `adb exec-out screencap -p > x.png`；`adb install -r` 覆盖升级需要签名一致 |

## 判据与反模式

- 判据：**离线能进错误菜单、在线能进网页、进度文件内容与网页导出逐字节同构**，三条都实测过。
- 反模式：网页容器一直可见（必定看到白屏）／没有超时（弱网永久转圈）／
  错误菜单里只有一句"出错了"／把注入脚本当成"可选优化"（注入晚了进度就丢了）。
- 桌面与手机共享同一套网页时，**注入脚本要各自写完**（宿主 API 不同），但**载荷格式必须共用一份定义**。
