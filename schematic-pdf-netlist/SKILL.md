# 原理图 PDF → 网表与硬件文档

## 何时用

- 解析原理图 PDF、重建 PDF 中的电路连接
- 提取引脚映射 / 网表 / 电源树 / 器件清单注记
- 为固件补写硬件说明文档，或核对某信号的极性、上下拉、串联端接与 NC 引脚

## 核心知识点

### 1. 导出的 PDF 里没有网表对象

只有矢量线段 + 带坐标的文字，连接必须**几何重建**：

- **导线** = 轴对齐线段（`get_drawings()` 中 type 为 `'l'` 的项）。斜线是元件图形（电阻锯齿、二极管三角、MOS 符号），必须丢弃。
- **节点** = 线段端点按栅格吸附，用并查集合并重合或容差内的端点。
- **T 型节点** = 落在某线段**内部**的节点并入该线网；漏掉会静默拆开视觉上连通的 net。
- **标签** = 文字 token 挂到地理上最近的 net 节点。

### 2. 两个会静默污染结果的坑

- **元件体矩形必须排除**：器件外框在 `get_drawings()` 里是 `'re'` 项，朴素转成四条线段会把整颗 MCU 的引脚熔成一个巨型 net。需排除整页图框，按宽高阈值识别元件体，再丢弃完全落在体内的线段。
- **焊盘标注让正则切分歧义**：`PI<refdes><pin>` 与 `CO<refdes>` 混排，贪心切分会把 `U1032` 切成 `U103`+`2`。先从不含歧义的 `CO*` 收集**已知 refdes 集合**，再对每个 `PI*` 按"已知 refdes 前缀 + 纯数字余项"切分；这类 token 只当**交叉校验**。

### 3. 主证据是"高 dpi 裁剪 + 看图"

几何重建只给出 net 数量与标签云，**给不出**"哪个脚号属于哪个 net"，也认不出 NC 叉。流程：整页 200 dpi 看布局找功能块（电源树、MCU、驱动、ADC、连接器、调试口）→ 按 refdes 从 `words.json` 定位块坐标 → 600~900 dpi 裁剪该区 → 用 Read 看 PNG，逐块记录 refdes、脚号、脚名、net 名、器件值、NC 叉 → 用几何网表**交叉校验**，两侧 net 集合互相对账。密集双页图约需 6~12 张裁剪图，此步决定输出正确性。

## 判据与反模式

- 整页只出 1~5 个 net，或最大 net 挂几十上百个标签 → 元件外框漏排除。
- 某电源网络在用到它的页面上没出现 → 标签未挂上（放宽标签到节点的距离容差）。
- 文档必须逐个列出 NC 引脚，避免后续被误当可用脚。
- 极性 / 端接类结论必须写清：差分对 IN+/IN− 是否交叉走线、低有效使能（`nSLEEP`/`nFAULT`）、串联端接电阻（非上拉/下拉）、带 `VCC/GND/OE` 的四脚 `Y` 符号是有源晶振。
- 未被要求时不提交生成物。
